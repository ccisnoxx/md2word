# 产品范围与冻结决策

## 1. 范围声明

md2word 的唯一产品边界是：

> 将电子元器件 Datasheet PDF 转换为公司内部可编辑、可翻译、可审核、可按公司模板交付的 DOCX。

本文件中的决策在 PRD v1.0 周期内视为冻结。Codex 不得在实现任务中自行扩大范围。

## 2. 冻结决策

| ID | 决策 |
|---|---|
| PD-001 | 一个任务只生成一份目标 DOCX。 |
| PD-002 | 中文 PDF 转中文 Word 使用 `direct_pdf_to_word`，不存在中文转中文 Prompt。 |
| PD-003 | 直接转换不调用 AI 大模型。 |
| PD-004 | 只维护英译中、俄译中、中译英、中译俄四种跨语言 Prompt。 |
| PD-005 | MinerU 是唯一 PDF 解析入口；系统不做 OCR/解析器路由。 |
| PD-006 | `content_list_v2.json` 数组顺序是主阅读顺序，`bbox` 用于布局和定位。 |
| PD-007 | MinerU `image` 和 `chart` 默认渲染为 Word 图片对象。 |
| PD-008 | HTML 可解析时，表格必须渲染为 Word 原生表格。 |
| PD-009 | 表格参考截图是 QA 证据，不是默认输出。 |
| PD-010 | 表格结构失真不触发截图替代；仍生成原生表格并标记质量问题。 |
| PD-011 | 严重表格问题允许内部下载，必须显示“质量阻塞，不可交付”。 |
| PD-012 | 空 HTML 表格可使用参考图/PDF 裁图作内部占位，但永远阻止发布。 |
| PD-013 | 未人工复核的翻译 Word 允许内部下载，必须显示“未复核”。 |
| PD-014 | 未复核或质量阻塞文档不得成为最终交付件。 |
| PD-015 | 人工修改后的 Word 不要求上传回系统。 |
| PD-016 | 系统不提供在线 Word 编辑、在线译文修改或在线修表。 |
| PD-017 | 图片内部文字不翻译。 |
| PD-018 | 不生成双语 DOCX。 |
| PD-019 | 发布状态只针对系统保存的生成 DOCX。 |
| PD-020 | 执行状态、质量状态、复核状态、交付状态必须分离。 |

## 3. 术语规范

| 术语 | 定义 |
|---|---|
| 直接转换 | 不改变语言和语义，将 PDF 内容转换为可编辑 DOCX。 |
| 翻译转换 | 在保持结构和技术信息的前提下，将文档文本翻译到指定语言并生成 DOCX。 |
| MinerU 产物 | `content_list_v2.json`、图片资源和相关解析文件。 |
| DocumentIR | 系统内部稳定文档合同，不包含 Word 专有渲染决策。 |
| 表格参考图 | MinerU 表格截图或源 PDF 裁图，仅用于 QA 和异常占位。 |
| 内部草稿 | 可下载、可人工修改，但没有最终交付资格的系统生成 DOCX。 |
| 最终交付件 | 质量非阻塞、QA 已批准并由 Admin 发布的系统生成 DOCX。 |
| 符号与排版规则 | 对变量、上下标、单位、字体和渲染语义的非翻译规则。 |
| 翻译术语集 | 某语言方向下的源术语、目标术语、推荐/禁用译法集合。 |

## 4. 变更控制

新增以下任何能力必须发布新 PRD 版本，而不是直接加入现有任务：

- 双语输出；
- 批量任务；
- 在线编辑；
- 图片文字翻译；
- 人工 Word 回传；
- 参数数据库、BOM、选型或知识库；
- 外部客户门户；
- 新语言方向；
- 替换 MinerU 或增加多解析器路由。

## 5. Codex 约束

Codex 在实现时必须：

1. 先确认任务是否已经由现有模块实现；
2. 优先补齐差距，不平行建设第二套转换链路；
3. 不把表格问题简化成“全部转图片”；
4. 不引入中译中 Prompt；
5. 不把 QA 页面扩展为编辑器；
6. 不把未复核或 blocked 状态自动提升为发布状态；
7. 对 API、状态、数据库或配置改动使用 Trellis 复杂任务流程。
