# 电子元器件 PDF 到模板化 Word 后端 PRD 草案

> 本文是基于当前讨论形成的草案。所有未确认内容均以【待确认假设】或 Open questions 标注，不作为已定结论。

## 1. 项目背景

### 1.1 已知事实

- 【事实】这是一个给公司开发的后端项目。
- 【事实】当前计划先开发后端，后续再开发前端，整体采用前后端分离。
- 【事实】默认技术栈为 Python + FastAPI。
- 【事实】用户会上传电子元器件相关 PDF。
- 【事实】系统需要通过 MinerU 对 PDF 进行解析。
- 【事实】中文 PDF 希望直接按照用户上传或预配置的模板要求生成 Word 文档，并尽量保证排版。
- 【事实】不同公司可能有不同的 Word 模板要求，例如页眉、Logo、排版、格式等。
- 【事实】英文 PDF 可以选择英译中，通过 AI 做语义翻译，然后在保证排版的前提下生成 Word 文档。
- 【事实】后续可能扩展中译英、中译俄等语言方向。
- 【事实】Word 文档格式、模板和术语规则，当前更偏版本化配置资产。
- 【事实】后续希望这些配置资产变成在线可编辑资源，因此未来会引入权限、版本、回滚、审计和兼容问题。

### 1.2 项目动机

- 【推断｜高】内部文档交付人员或技术运营人员需要将电子元器件 PDF 快速转换为符合公司格式要求的 Word 文档。
- 【推断｜高】当前人工处理可能涉及复制内容、调整标题层级、重建表格、插入图片、翻译英文资料、套用公司模板等重复工作。
- 【推断｜中】项目希望先通过后端能力验证核心链路，再开发前端体验和在线配置管理能力。

### 1.3 当前问题

- PDF 结构复杂，电子元器件数据手册可能包含双栏、参数表、图片、引脚图、封装图、公式和脚注。
- PDF 解析结果不能直接等同于可交付 Word，需要中间结构和模板渲染。
- 英文翻译需要术语一致性、结构稳定性和 AI 调用审计。
- 公司模板差异不能依赖人工临时排版，后续需要版本化资产管理。

### 1.4 业务价值

- 减少内部人员在 PDF 内容整理、翻译、排版上的时间。
- 提高公司交付 Word 文档的格式一致性。
- 提高英文资料翻译中的术语一致性。
- 沉淀模板、术语、语言方向等配置资产。
- 为后续前端、权限、版本、回滚、审计和多公司模板管理打基础。

## 2. 目标用户

| 用户类型 | 优先级 | 用户场景 | 用户痛点 |
|---|---:|---|---|
| 内部文档交付人员 | P0 | 上传中文数据手册或规格书，生成符合公司模板的 Word | 手工排版耗时、表格和图片处理繁琐 |
| 内部技术运营人员 | P0 | 批量验证 PDF 样本、排查失败任务、维护模板配置包 | 缺少可追踪任务状态和失败原因 |
| 内部翻译/校对人员 | P1 | 对英文 PDF 的英译中结果进行线下校对 | 术语不一致、翻译结果不可追溯 |
| 外部客户自助用户 | P2 | 自助上传、选择模板、下载结果 | MVP 不覆盖 |

【事实】MVP 第一批用户为公司内部文档交付人员或技术运营人员，不面向外部客户自助使用。

## 3. 核心问题

### 3.1 PDF 解析问题

- 【事实】MVP 第一批 PDF 限定为电子元器件数据手册 / 规格书类文本型 PDF。
- 【事实】可包含常见表格、图片、双栏内容。
- 【事实】暂不承诺扫描件、BOM、检测报告、复杂图片型 PDF 的高质量转换。
- 【建议】使用 Golden Sample 样本集控制验收范围。

### 3.2 翻译问题

- 【事实】P0 不把英文英译中作为正式主闭环。
- 【事实】P1 将英文 PDF 英译中作为实验闭环，并行开发、单独验收。
- 【事实】MVP 允许调用外部 AI 模型，但必须支持配置化开关，并记录哪些内容被发送，同时预留私有化模型适配接口。
- 【建议】AI 只处理结构化文本节点，不直接生成 Word。

### 3.3 Word 排版问题

- 【事实】MVP 排版目标为混合模式：章节结构、标题层级、正文顺序、表格、关键图片尽量保留；页眉、Logo、字体、标题样式、页边距、目录等服从公司 Word 模板。
- 【事实】不承诺与原 PDF 像素级一致。
- 【推断｜高】Word 生成应由模板规则确定性完成，避免让 AI 直接生成最终 Word。

### 3.4 多公司模板差异问题

- 【事实】P0 支持 1-2 套人工预配置的公司 Word 模板。
- 【事实】不做在线模板编辑器，不承诺任意 docx 自动适配。
- 【事实】模板以 docx 样例 + 配置文件 / 代码规则的版本化配置包形式管理。

### 3.5 术语一致性问题

- 【事实】P0 不强依赖术语表。
- 【事实】P1 英译中实验链路支持最小术语表能力：按语言方向加载固定版本术语表，翻译任务记录术语版本。
- 【事实】暂不做在线术语编辑、冲突合并、复杂优先级和自动回滚。

### 3.6 配置资产管理问题

- 模板、术语、语言方向、AI 模型配置都应作为后续可版本化、可审计、可回滚的配置资产。
- MVP 先做最小版本引用和任务追溯，不做完整在线编辑器。

## 4. 用户主流程

1. 内部用户登录系统。
2. 上传电子元器件数据手册 / 规格书 PDF。
3. 系统校验 PDF 类型、大小和页数。
4. 用户选择处理模式：中文直接生成 Word，或 P1 英文英译中实验模式。
5. 用户选择公司模板和模板版本。
6. 系统创建异步文档任务。
7. Worker 调用 MinerU 解析 PDF。
8. 系统将 MinerU 结果转换为内部 DocumentIR。
9. P1 模式下，系统按语言方向和术语版本翻译 DocumentIR 文本节点。
10. 系统根据模板配置包生成可编辑 Word。
11. 系统上传原始 PDF、中间结果、图片和生成 Word 到 OSS。
12. 用户查询任务状态，完成后获取 10 分钟有效的临时下载链接。
13. 用户下载 Word 后进行线下校对。

| ID | 功能名称 | 用户故事 | 触发条件 | 主流程 | 异常场景 | 优先级 | 验收标准 |

| FR-008 | 下载结果 | 作为 operator，我需要下载生成 Word | 任务成功后 | 获取临时下载链接 | 文件过期、OSS 授权失败 | P0 | 链接有效期 10 分钟 |
| FR-009 | P1 英译中 | 作为内部人员，我希望英文资料可转中文 Word | 选择英译中模式 | 翻译 DocumentIR 文本节点后生成 Word | AI 失败、术语不匹配、结构校验失败 | P1 | 记录模型配置、术语版本和调用审计 |
| FR-010 | 任务重试 | 作为 operator/admin，我需要重试失败任务 | 任务失败后 | 按 job_id 幂等重试 | 输入文件过期、配置版本停用 | P1 | 重试不生成不可追踪的重复结果 |

## 7. 模板与术语规则需求

### 7.1 模板

- 【事实】P0 支持 1-2 套人工预配置公司 Word 模板。
- 模板需要记录适用公司、模板名称、状态、版本号。
- 模板版本需要记录 docx 样例文件、配置文件、代码规则版本、创建人、发布时间。
- 模板规则至少覆盖页眉、Logo、字体、标题样式、页边距、目录、表格样式。
- 任务生成 Word 时必须记录使用的模板版本。
- 【非目标】P0 不支持在线模板编辑器，不支持任意 docx 自动适配。

### 7.2 术语规则

- 【事实】P0 不强依赖术语表。
- 【事实】P1 支持按语言方向加载固定版本术语表。
- 术语版本需要记录语言方向、文件引用、版本号、启用状态。
- 翻译任务必须记录使用的术语版本。
- 【非目标】P1 暂不做在线术语编辑、冲突合并、复杂优先级和自动回滚。

### 7.3 回滚与审计

- MVP 保留模板版本、术语版本和任务引用关系。
- admin 可管理模板配置和术语配置。
- 版本回滚在 MVP 可作为后端预留或运维操作，不一定提供完整 UI。
- 审计日志至少记录操作者、动作、对象类型、对象 ID、时间和关键元数据。

## 8. 非功能需求

| 类别 | 需求 |
|---|---|
| 性能 | 单个 PDF 不超过 50MB、200 页；P0 任务超时 20 分钟，P1 任务超时 60 分钟 |
| 可用性 | API 和 Worker 分离，失败任务可查询阶段和原因 |
| 安全 | JWT 鉴权，文件下载使用临时签名 URL，默认 10 分钟有效 |
| 权限 | MVP 两类角色：admin 和 operator |
| 多租户隔离 | MVP 单租户简化，但保留 tenant_id、company_id、created_by 字段 |
| 可扩展性 | 翻译 provider、OSS client、模板渲染、MinerU 集成都需要可替换边界 |
| 可维护性 | 使用 DocumentIR 隔离解析、翻译和 Word 渲染 |
| 数据一致性 | MySQL 中 document_jobs 是任务状态权威来源 |
| 文件生命周期 | 原始 PDF、中间结果、图片、Word 默认保留 90 天 |
| 合规要求 | 【待确认假设】公司后续会定义更细的文件清理、AI 调用和日志保留策略 |

## 9. 非目标

- MVP 不面向外部客户自助使用。
- MVP 不做完整多租户客户门户。
- MVP 不做在线人工审核 / 校对工作台。
- MVP 不做在线模板编辑器。
- MVP 不承诺任意 docx 模板自动适配。
- MVP 不做在线术语库编辑、冲突合并、复杂优先级。
- MVP 不承诺扫描件 OCR 高质量转换。
- MVP 不承诺 BOM、检测报告、复杂图片型 PDF 高质量转换。
- MVP 不承诺 PDF 像素级版式还原。
- MVP 不提供上传后阻塞等待 Word 返回的同步转换接口。

## 10. 验收标准

### 10.1 PDF 解析验收标准

- P0 建立 10-20 份电子元器件数据手册 / 规格书 Golden Sample。
- 样本覆盖单栏、双栏、章节标题、参数表、关键图片等典型情况。
- 核心链路成功率不低于 90%。
- 标题层级、正文顺序、主要参数表、关键图片达到可交付后轻量校对标准。

### 10.2 AI 翻译验收标准

- P1 单独验收，不阻塞 P0。
- 翻译任务记录语言方向、模型提供方、模型名、术语版本、token/字符数、请求时间和响应时间。
- 默认不在业务日志中保存完整发送文本。
- 调试开关开启时，完整 prompt/response 最多保留 1 天。

### 10.3 术语一致性验收标准

- P1 支持按语言方向加载固定版本术语表。
- 翻译任务记录所用术语版本。
- 【待确认假设】术语一致性先以人工抽检和样本集验证为主。

### 10.4 Word 排版验收标准

- 生成 Word 必须可打开、可编辑、可下载。
- 页眉、Logo、字体、标题样式、页边距、目录等服从模板规则。
- 章节结构、标题层级、正文顺序、主要表格、关键图片在 Golden Sample 中可人工验收。
- 不要求与原 PDF 像素级一致。

### 10.5 模板兼容性验收标准

- P0 支持 1-2 套预配置模板包。
- 每次任务记录模板版本。
- 模板版本变更后，Golden Sample 可回归验证。

### 10.6 异常场景验收标准

- 文件超 50MB 或超过 200 页时，直接拒绝创建任务并返回明确错误。
- PDF 损坏、页数读取失败、MinerU 失败、Word 生成失败、OSS 上传失败均需要记录 failed_stage 和可读错误原因。
- 样本外 PDF 不承诺同等质量，但不能静默失败。

### 10.7 后端 API 验收标准

- 支持登录、创建任务、查询任务状态、查询事件、获取下载链接。
- 所有重处理通过异步任务执行。
- API 查询以 MySQL 业务任务表为权威来源。

## 11. 反直觉但值得考虑的方案

【建议】MVP 阶段不要支持用户上传任意 docx 模板后自动套版，而是使用固定模板配置包。

- 为什么反直觉：用户直觉上会认为上传一个 Word 模板，系统就应该自动照着生成。
- 适用前提：前期服务内部用户，模板数量有限，目标是验证核心链路质量。
- 潜在收益：生成结果稳定、测试可回归、失败原因可定位、后续版本化更清楚。
- 主要代价：模板前期需要人工配置，灵活性不如在线模板编辑器。
- 最小验证方式：选 1 个公司模板和 10-20 份 Golden Sample，跑通解析、生成和人工验收。
