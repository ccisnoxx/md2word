# Word 转换失败原因与源页定位可见性

## 目标

用户反馈转换 Word 失败时不知道具体错误，也不知道哪一页出错。失败任务应直接显示可理解的失败原因、失败阶段和有证据支持的源 PDF 页码，方便检查源文件或提供排查信息。

## 当前证据

- `app/domains/document_jobs/_failure_policy.py:64`：普通异常仅保留异常类型；MinerU/OSError 使用固定安全消息。不能直接公开任意异常正文。
- `app/domains/document_jobs/failure_diagnostic.py:13`：已有当前 retry_count 的失败事件投影；仅 MinerU 验证报告和渲染上下文提供定位。
- `frontend/src/utils/failureDiagnostic.ts:4`：诊断为空时返回空列表，原因主要展示机器码；无页码统一显示文档级问题。
- `frontend/src/features/job-detail/JobDiagnosticsPanel.vue:283`：诊断页已有失败信息；`JobOverviewPanel.vue:1` 的概览缺少同等失败摘要。
- `.trellis/spec/backend/error-handling.md:122`：列表不逐行查询事件，定位只用于详情和异常中心；页码为源 PDF 的 1 起始页码。
- 当前仅检查本地 main 源码；没有实际失败任务 ID、事件和线上版本证据，不能声称已找到该任务根因。

## 范围与要求

R1. 失败任务概览直接显示中文原因、阶段和位置；诊断页和异常中心保持相同解释，技术码、块信息仍可供排查。

R2. 已知受控错误码提供中文含义；细分原因只能来自已有安全证据。泛型异常只说明类别和已知操作，明确具体原因尚未识别，不能伪造根因或暴露原始异常正文。

R3. 有源页证据时显示“源 PDF 第 N 页”；保留多页、首个失败及截断语义。文档范围证据只能说明无法定位单页，不能断言全部页面都错；无诊断或历史证据缺失时明确“未记录失败页码”。

R4. 复用现有投影、渲染上下文和错误安全边界；不同重试代数不能串用。列表保留轻量摘要和详情入口，不新增逐行事件请求。

R5. 保留任务 ID、技术错误码及已加载的 trace_id；失败状态、重试权限、降级和发布资格不变。

## 验收标准

- AC1：有定位的图片、表格、正文渲染失败，在概览可看到阶段、中文原因、正确源页码；索引 0 显示第 1 页。
- AC2：已知验证错误在详情与异常中心使用一致中文解释，保留机器码、多页及截断提示。
- AC3：缺定位证据的失败和历史任务明确显示页码未记录，不伪造页码，不把缺证据解释为文档级根因。
- AC4：只有异常类型时说明信息不足；任意异常正文、文档内容、密钥、签名 URL 不因本次改动进入公开诊断。
- AC5：诊断仅取当前重试代数；成功、进行中任务没有失败提示；列表不增加逐行请求。
- AC6：执行与实际改动对应的定向回归和前端类型检查，不以本地结果宣称线上任务已修复。

## 不在范围

自动修复文档、改变降级策略、生成失败后的部分 Word、PDF 预览跳转、Word 输出页映射、历史错误补造、数据库迁移、全仓回归、生产部署及线上重试。
