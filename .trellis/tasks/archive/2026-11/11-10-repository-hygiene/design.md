# 仓库卫生修复设计（已批准实施）

## 边界与所有权

本任务直接交付当前树清理、卫生检查和提交入口，它们需要同一套清理规则才能验收，因此使用一个任务。历史重写、真实凭证轮换和线上配置不属于本任务实施授权，扫描只提供后续决策证据。

| Owner / 路径 | 负责行为 |
|---|---|
| 根 `.gitignore` | 忽略 `.tmp` 和经核实的个人 IDE 绑定，不承担已跟踪内容检测。 |
| `scripts/ops/check_repository_hygiene.py`（新增） | Python 标准库实现路径/地址规则；读取 Git index 或显式跟踪文件，不依赖业务 runtime。 |
| `.githooks/pre-commit`（新增） | 调用暂存卫生检查和固定版本 Gitleaks；非零退出阻止提交，不安装依赖、不改写文件。 |
| `.gitleaks.toml`（新增） | 继承内置 secrets 规则，只为已确认文件校验和设置窄范围例外。 |
| `docs/dev/repository-hygiene.md`（新增） | 规则、开发工具安装与校验、当前 checkout 激活、局限、例外依据和回退说明。 |
| 两个现有沙盒脚本 | 去除个人目录默认值，保留显式 CLI / 环境配置入口。 |
| 现有任务/文档 | 规范化路径和失效工作树元数据；不改变任务状态、历史测试结果或业务合同。 |

不新增通用框架、服务、后台进程、CI 或应用运行依赖。Gitleaks 是单独的本地开发工具；使用已经核对的 8.30.1 版本及官方发布 SHA-256，不将本轮临时二进制或全量扫描原始报告提交。

## 暂存检查与规则

### 输入合同

- `--staged`：通过 Git 的 NUL 分隔接口枚举新增、修改、复制、重命名后的 index 路径，读取实际暂存 blob；删除无需读取内容。初始提交也适用，不要求已有 `HEAD`。
- `--tracked`：显式扫描当前跟踪工作树文件；列明缺失、非文本/二进制及不支持内容的边界，不自动扫描被忽略私有文件。
- 临时名检查针对准备进入提交的路径；内容检查针对对应文本。不能只检查工作树，也不能只检查 diff 新增行而遗漏新增文件完整内容。
- 任何 Git 读取失败或扫描器缺失都要明确失败；读取成功的空集合是合法无待检输入。不能用宽泛 catch 将未知异常转为空命中。
- 输出限制为仓库相对 `file:line`、稳定规则 ID 和中文修复提示，不回显源码行、地址、SSID、DNS 或 token。

### 规则与精确例外

| 规则 | 默认拒绝 | 合法范围 |
|---|---|---|
| `temporary-file` | 被提交文件名后缀 `.tmp`（大小写统一判断）。 | 文档提及该后缀不构成文件名违规。 |
| `user-home-path` | macOS/Linux/Windows 的真实用户目录绝对路径，包括文本中的常见 JSON 转义形式。 | 明确变量、占位符和检测规则本身；不允许整目录豁免。 |
| `private-ip` | RFC1918 IPv4 字面量：使用标准库验证候选地址，避免把版本号认作 IP。 | 已确认部署必须项按路径 + 规则 + 内容指纹 + 理由精确登记；标准回环/绑定地址按现有开发用途保留。 |
| Gitleaks 内置规则 | 固定版本扫描发现的新 secrets。 | 只对当前 3 个已确认 hash JSON，按规则 + 文件路径 + 校验和条目形状同时匹配（AND），不放开整个 `.trellis` 或所有 64 位值。 |

本次观察到的地址风险是 RFC1918 IPv4；不声称此规则覆盖任意内部域名、公网主机或全部 IPv6 拓扑信息。更广的企业内部资产识别不在本轮。

卫生例外放在同一检查器的最小常量清单中，避免额外配置层；其理由和定位同步写在开发文档。Gitleaks 的细粒度 allowlist 使用官方配置接口。测试生成的违规样本存放在临时仓库；同一 allowlist 文件中新加入的真实 credential 字段也必须被拒绝。

## Git 钩子接线与兼容

- 选择原生 Git `pre-commit`，不新增 pre-commit 框架。当前没有既有钩子需要迁移；实施时复核，出现并发钩子时保留并说明，不覆盖未知内容。
- 钩子依次调用 `python3 scripts/ops/check_repository_hygiene.py --staged` 和 `gitleaks git --pre-commit --staged`，显式使用仓库 Gitleaks 配置，启用脱敏和不采信行内 allow；依据实际 CLI 验证参数组合。
- 当前 checkout 的激活已获用户批准：仅设置本仓库 `core.hooksPath=.githooks`，不修改全局 Git 配置。先在临时仓库验证，再核对本仓库实际配置及入口可执行位；不执行根仓库提交。
- 检查器直接读 index，不 stash、不暂存用户文件、不调整工作树。Gitleaks 钩子只扫描此次暂存补丁，历史扫描独立运行，避免每次提交重复扫描历史噪声。
- 新克隆仍需按文档安装工具并激活；本地钩子可被 `--no-verify` 绕过，本任务不提供服务端强制保证。

## 扫描与历史决策

基线扫描已经完成，范围和结论见[验收记录](verification.md)。详细报告保存在本地，后续复用无变化的历史结果。当前跟踪文件的 secrets 命中已核对为校验和；历史存在同一段硬编码 Bearer token 的两条记录，其中一条位于当前 main 祖先。

建议由凭证所有者优先确认并吊销或轮换，记录权限和是否已失效。本任务不调用发现的 token、不访问管理平台、不自行轮换。即使已吊销，也需根据仓库公开范围、内部网络保密要求及协作成本评估是否进行独立的历史清理；仅删除当前脚本不能清除旧提交。

如另获授权，历史清理方案应使用独立镜像/备份、明确 refs 和替换集合、先做可审查演练，再决定强推、协作者迁移及托管平台缓存处理。本任务不会先执行改写再要求补批。

## 回退

- 当前树变更通过精确 diff 或后续反向提交恢复；不执行硬重置或历史改写。
- 本地 hooks 配置恢复实施前实测值（当前未设置时只取消本任务设置）；保留其他新出现的配置。
- IDE 文件保持在本机；只恢复本任务相关的跟踪策略，不批量添加其他 IDE 状态。
- 无数据库、线上服务和数据迁移回退需求。
