# 上线窗口执行与验收顺序

任务在计划获准后开始。生产部署、单公司开关和可能的回退分别按用户授权的窗口执行。 执行和复核前定向读取 [Word 生成规则](../../../../spec/backend/word-generation-rules.md) 中 TABLE-001 的「线上原排版的同源取证与人工核定」小节。

1. **确认现场与制品。** 确认获准样本和测试公司、账号和回调入口、首轮验收与停止条件。按实际生产分层 Compose 清单记录项目、依赖、挂载、当前 API/Worker 镜像和上一制品。当次候选用仓库既有锁和发布路径，固定制品摘要。先核对回退目标对当前产物和账本的兼容范围。参照 [hostdzire 部署手册](../../../../../docs/deploy/hostdzire-dmit-md2word.md#分层-override-上线当前生产方式) 和第五阶段归档。
2. **候选上生产并保持关闭。** 仅获准后替换指定的 API 和 Worker。按实际清单逐实例核对启动时间、镜像 ID、应用版本、队列、配置和 Poppler 五工具。可先用 `docker compose ps`、限定字段的 `docker inspect`、容器内工具 `-v` 与现有 `/api/v1/health/ready` 收集证据。当前在跑的制品、配置和文件结构独立核对。
3. **关闸实跑。** 用获准测试样本提交正式转换。对照真实回调入站、按任务 seed 验签、专用消息登记、Celery 消费、原包归档、IR 与 Word。完成含跨列候选的负例和普通转换对照，检查质量、审批和发布门禁，以及管理员新同包拒绝。回调证据缺失时暂停，先从现有回调、任务和 Worker 记录定位。
4. **单公司灰度。** 取得明确开关授权后，在所有执行者同时收敛单一测试公司。测试名单内真实回调、同源自动修正与 Word 单列认证，再核对名单外或受限现场的对照。用当前生成件验证未决项不能批准或发布。发布正例要求获准的测试发布、正式预览就绪、正确审批和其他发布门禁满足；缺少任一条件记录未验收状态，预览配置变化不属于本任务默认动作。
5. **收敛与回滚。** 每个阶段对账上传、回调、当前代、报告/IR/Word、最终交付状态及未决 ID。比较关闸基线的队列积压、来源核验失败、Worker 耗时和错误率。触发停止条件时按设计核对关闭、名单清空、在途和已接纳 UUID、旧件读取和必要的兼容镜像回退。保持实际操作证据可复核，单公司验收结果由本阶段记录，后续扩大范围另作决定。

每个运行记录只保存白名单字段、脱敏摘要、HTTP 与终态，以及技术限制和未验收项。已经通过且输入制品、依赖和配置一致的隔离结果可以引用。最后分别标注关闸生产、真实回调、灰度与停用的通过或阻断原因。
