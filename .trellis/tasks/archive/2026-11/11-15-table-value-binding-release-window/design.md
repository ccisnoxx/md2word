# 上线窗口技术设计

## 候选与关闸基线

使用获准的不可变候选镜像，记录提交、镜像 ID 与可用的制品摘要、平台、发布时间及回退目标。按生产实际 Compose 项目、文件顺序和覆盖配置核对 API、Worker、恢复入口、共享存储和队列。部署范围限获准的应用服务，沿用现有数据库、Redis、卷和路由。核对源 PDF、原 ZIP、IR、报告和 Word 的保留期、删除声明与不可变写入边界。

候选上生产后的第一份有效配置为 `DOCUMENT_TABLE_VALUE_PDF_BINDING_ENABLED=false` 与 `DOCUMENT_TABLE_VALUE_PDF_BINDING_COMPANY_ALLOWLIST=[]`。以实际实例、运行用户和 PATH 查 `pdfinfo`、`pdftotext`、`pdftocairo`、`pdftohtml`、`pdftoppm`，逐一记录路径和版本。对照 API 启动身份和 Worker 任务加载配置。配置切换后确认所有执行者收敛，避免同一队列由旧、新策略混合消费。

## 真实回调证据

1. 以获准测试公司和文档从正式入口提交原排版任务。目标 MinerU 账号和获准 HTTPS 回调须对应实际候选的 `POST /api/v1/mineru-callbacks/result`。使用每个任务的正式 seed，按 UTF-8 原始 `content` 及供应方 `checksum` 核对 `SHA256(uid + seed + content)`。证据只保存脱敏身份、摘要和核验结果，不保存 seed、凭证、带签名 URL 或原始回调正文。 [MinerU API 合同](https://mineru.net/apiManage/docs)
2. 关联真实入站请求与 `mineru_callback_received` 事件、回调专用消息和 Worker 消费。核对签名覆盖的结果中含本次已登记 `batch_id`、唯一相符的 `data_id`、完成状态和结果地址。核对 `source_file_id`、实际 PUT 的长度与 SHA-256、回包消息和原解析代一致。允许域检查通过后，从归档重读原 ZIP 并对账其身份标志、上传摘要、长度、v2、layout 和包内 PDF。HTTP 200 后还须观察消息真正消费及最终产物。
3. 同代重复消息应只有一条接纳和有效归档，旧代或身份冲突不得覆盖当前代。拒收与重复的既有隔离对照可复用，线上只观察获准测试任务的真实回调和自然重试。轮询结果可以协助定位回调异常，同一个任务的轮询成功不会签核回调验收。

关闸时来源登记和普通转换继续运行。用可识别跨列的测试件核对原跨列发现保留，Word 无自动修正，审批和发布保持质量门禁。已经分列的回包用于普通转换对照，跨列门禁用实际有跨列的样本验证。管理员新同包请求预期因 `table_value_column_review_disabled` 拒绝。回调接收 200、Word 产出和审批发布结果分别记录。

## 单公司灰度

获准后仅配置一对 `(tenant_id, company_id)`。资格按任务持久化的归属判断，API 和全部 Worker 同步启用。先取该公司原排版真实回调正例，核对同源及表框证据和实际 DOCX 的值、列、单位、占列数与已认证 finding ID。指纹一致走原路径，异指纹只在真实回包身份和严格逐页证据均齐全时使用上传 PDF 核定，表框校正仍依现有 1 pt 规则。未证条目继续阻断。

在具有合法测试身份的名单外公司走同入口对照，核对零新增认证、零新同包接纳。若现场只允许单租户单公司，沿用隔离名单外证据，并明确现场只能验证关闸对照和唯一配置；扩大范围前补相应证据。P7 实际存在候选时检查 `±5 µV` 单列 TYP 与 `±100 µV` 单列 MAX。LOW/HIGH 可以验证原生单列，逐页证据缺失时维持现有判据。实际 Word 是否正确、质量阻断、预览是否就绪与发布是否成功均单独记录。

## 停用与版本回退

| 触发 | 动作与对账 |
| --- | --- |
| 停止灰度、真实回调错配、错列、错误解除、越公司或实例策略不一致 | 按已授权回滚动作，在兼容候选上关闭总开关并清空名单。核对所有执行者已收敛，新任务无新增核定，新同包接纳拒绝。 |
| 停用时仍有已接纳同包意图 | 保留源 PDF、原 ZIP、当前 IR/报告、固定代次和请求 UUID。相同 UUID 可对账，完整来源的已接纳代继续使用冻结证据。对涉及完整性异常的测试件保留交付阻断并记录影响范围。 |
| 应用运行需回退镜像 | 恢复通过兼容验证的上一制品及实际文件顺序。对已产生新 `table_edge`、逐页凭证或同包账本的环境，须先验证目标能读写这些记录并保留代次防护。观察到的旧生产镜像 `1748f5ee` 缺这些模块，不能作为灰度产生新证据后的默认回退目标。无已证兼容镜像时保持兼容版本关闸并等待处理。 |

停止条件包括任何未决放行、证据错绑、错误落位、非名单接纳，或持续回调/Worker 异常影响普通转换。停用保留已完成的审计和制品，既有已发布件按现有处置入口处理。
