# 整合冷启动与参数值列核定分支

## 目标

将两个本地分支的独有成果分别通过 GitHub PR 合入 main。确认远端主分支包含两个原始分支的提交后，再清理对应分支。

## 已确认的基线

- main 起点为 c6f30670。冷启动分支 c663210d 有 6 个独有提交和 19 个冲突文件。其中 MinerU 实现 4db17ac3 与主分支 6d006e38 补丁等价，主分支随后以 93da6905 确定 direct 新任务按原文绑定语言。
- 参数表分支 525904a0 有 21 个独有提交和 13 个冲突文件。独有成果涵盖源 PDF 取证、同源人工核定、同包新代、Word 实物认证、审批重验、试点名单及历史证据。主分支 f1fd5398 已有参数值列归属判断、摘要绑定的确认及正式发布阻断。

## 需求

- 冷启动保留主分支 API 工厂、健康依赖及 Worker Runtime 合同，补入适配当前入口的空库一次启动、失败等待、重启验收脚本和原验收记录。
- 参数表合入独有功能。总开关默认关闭，名单默认为空。保留主分支的表头识别、疑似项检测、旧报告兼容、明确确认和正式发布阻断。对应 finding 获得实物认证或按既有合同作有效确认后，才可以解除对应阻断。
- 用独立工作区解决冲突。每次在 GitHub 确认合并且源提交已进入远端主分支后，删除相应分支。Claude 工作区分离 HEAD 时保持原提交和文件内容。

## 验收

- 冷启动差异保留最新入口和主分支语言绑定。核对验收脚本的语法、Compose 入口和归档历史。
- 参数表定向测试覆盖主分支检测和发布、分支选通和租户权限、证据认证、同包核定、当前代/主件重核。OpenAPI 快照与实际代码一致。
- 两个 GitHub PR 均已合并，两条原始分支 HEAD 均是最终 origin/main 的祖先。确认本地和远端分支清理及主工作区同步。

## 范围

整合已有实现及必要冲突修复，运行直接验证受影响合同的定向检查。生产部署、启用灰度、真实 MinerU 提交、生产数据修改及完整发布验证分别管理。
