# 参数值列行取证设计

## 所有权与数据流

`pdf_value_column_review_flow.py` 继续负责来源、layout、表区以及显式人工核定优先权。`pdf_value_column_binding.py` 在已验证表头和实测表区内建立行候选，保留已有的独立列、值完整性和释放格检查。成功仍生成当前 `PdfValueColumnBinding` / `TableValueColumnCorrection`，失败仍产出绑定原 finding 的 `PdfValueColumnUnresolved`。实际 DOCX 认证继续决定是否移除活动 flag。

## 局部候选

1. 结构化行匹配结果，携带证据支持的候选 band 和锚点，或者明确的失败原因。同一源行复用上下文查询，继承两个源行争用同一位置、同一行映射多个 band 的检查。先确定同行，再核定目标列。
2. 按对应表头区域验证参数、条件和可用的独立数值邻格。空条件不提供证据，可比较而冲突的上下文不得跳过。对样本实际出现的换行、下标和公式表示差异，只支持能在闭合上下文格内完整逐词、逐段或逐字形验证的形式；未知形式不参与正向取证，不能把不匹配当作肯定结果。数值 token 继续使用原精确规则，文本排版处理不进入数值匹配。
3. 在表头下已验证的整个 numeric span 查找完整精确词框。重字、无法确证可见性的同值框或源侧潜在争用不能当成表内唯一。唯一值须完整落入唯一已闭合 band，且单位、表头及非目标值的行上下文相符。若值重复，用参数/符号、条件、值和单位的精确证据求交；唯一组合可消歧。已确定的 band 内仍须只有一个目标值词框。
4. `rowspan` 根据实测闭合格的边界及连续 band 核对数量和端点。`row - cell.row` 仅用于在已证实跨行范围内定位。参数格与单位格用相同约束；值或顺序不能覆盖物理跨度冲突。保留 `row_anchor_bboxes` 的实测非目标值锚点。

## 整表顺序

- 在同一表片段收集数据源行和实测 band。完整打印文字及物理边界独立证明的分节标题可作为结构边界；不可把无证的空行或未闭合边界当成可跳过的分节。源行与 band 计数无法核对时，不用顺序新增修正，仍允许独立局部证据成立。
- 按严格递增的一对一映射对齐已有候选。固定独立锚点和已证明的跨行约束，在可行映射中最大化已取证的匹配数。每个被顺序消歧的候选须已有相容的实物证据，且有独立前后锚点；顺序不生成新候选，也不覆盖冲突。只有整个序列恰有一份最优映射才接受。用动态规划或等价有界方法计数，达到 2 即饱和；同一映射的不同跳步顺序不重复计数。无可行解、多解或倒序锚点继续未决。
- 固定完整样本有一条末行横线落在表框下缘外。本次沿用现有横向单侧恢复，不扩框底边；未闭合末行保留警告，前面独立核实的 band 可由局部证据确认。

## 原因与兼容

| 原因 | 可核对的触发条件 |
| --- | --- |
| `row_anchor_missing` | 缺少可信上下文，或可比较的同行文字无法对上 |
| `row_anchor_nonunique` | 可信上下文支持多个 band，且无更具体的失败原因 |
| `rowspan_context_unresolved` | 不能证明跨行格在连续 band 上的物理归属 |
| `value_word_nonunique` | 有竞争目标词框，未被独立行证据消歧 |
| `unit_row_mismatch` | 单位不能被证实属于所选 band |
| `source_row_band_count_mismatch` | 顺序路径要求的源行和完整 band 数不合，且局部证据不足 |
| `row_sequence_ambiguous` | 顺序路径无可行解或有多个等价最佳解 |

每个 finding 返回一个确定的主原因。明确找到 band 后优先报告具体值、列或单位失败；行未定位时分别记录跨度冲突、候选竞争和顺序失败。对新增原因各留可触发的回归，不把历史泛化原因用作新增匹配的正常返回。

API 枚举做加法，既有 `row_ambiguous` 与 `unit_mismatch` 不改写。保留原 finding ID、绑定序列化、摘要和权限合同。使用新原因的 Worker 前需有兼容的 API 读者；停用时保留兼容读者，并沿用现有开关和名单。不进行本次部署。
