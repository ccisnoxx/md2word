## 抽取范围和持久化

新旧兼容点是不可变的**翻译源 IR**。为新登记的翻译源件在受校验的 IR 字节中写入可选版本 `translation_item_scope=annotations-v1`。缺省值序列化时省略，保留历史源件、历史目标件及 direct 的原始格式。适用范围由源件版本决定。新任务首次登记源件获得新范围，沿用原源件的同代恢复及用户重试保留原范围。未知版本或源/目标声明不匹配按既有完整性失败处理。

| 源件及状态 | 行为 |
| --- | --- |
| 无版本，有或没有已安装的旧根树 | 用原抽取规则重建或安装权威根计划。原批次、attempt、结果和审核证据按已有身份检查。 |
| 有 `annotations-v1` | 同一范围贯穿建批、领取、准备、拆分、重试、fan-in 和审核。新版本结果需要全部预期 ID，含所有合格注释。 |
| 旧任务保留完成译后 IR 或 DOCX | 继续按原报告和指针读。获得新翻译能力的正常入口是以新任务生成源件。 |
| 缺失、错绑、未知或冲突证据 | 保留当前源件、树一致性和批次完整性错误语义。禁止按批次现有 ID 反推范围，避免把新批次漏项判成旧版本。 |

抽取规则由 `DocumentIRTranslationService` 拥有。复用有序 target/item 列表，将 `field` 收敛为五个受控字面量，按 block 顺序和字段内原下标生成 ID。已存在的三类目标保持算法，包含 HTML 中 `eq` 后代占用的原始索引。新范围在原目标之后加入本块 `captions`、`footnotes` 中非空项。合成降级页继续按现有过滤。同步和本地正式转换在各自翻译入口建立同样的新范围，供请求导出、回放和结果取证使用。direct 路径经过原有分支。

正式调用沿 `TranslationPlanner` 及现有组件消费源件。用于初次安装的内存 IR 与落盘字节使用同一已选范围。所有重新读取、汇总和审核调用使用同一规则。原批次记录及结果已经持久化有序 item ID，并以源文件 ID 和字节摘要绑定；注释随这些字段原样登记。数据库结构、批次 JSON schema、lease/CAS 及 Validator 证明格式沿用现有合同。将译文精确写入目标数组位置，整批与 fan-in 完整性成功后才登记目标件。公式、数字、单位和技术型号走同一个 Codec 及 Validator。

## 源身份、表格及审核

- **派生字段。** 在转换选择第一条题注作为 `block.text` 的实际分支确认别名。利用该分支提供的身份，仅为新翻译范围保存必要的原下标，随源 IR 绑定并传递到目标。新范围的派生 `.text` 不重复送译，回填时从相应翻译值更新。旧范围的 `.text` 正常保留既有 ID。独立段落（包括 `annotation_role=table_context`）按自身 `.text` 翻译。遇到无法证明的同文关系保留独立单元。审核把派生内容定位到题注证据，只计算一次翻译覆盖。
- **表对象语义。** 新范围按源 block、字段、下标关联表格级注释；逻辑表关联沿用已验证的 group 和片段关系。现有 B06 的 HTML 单元格上下文、表头路径、同行参数和启用设置继续使用。开启该设置时，注释沿现有每项上下文位置携带表格块 ID、适用的已验证逻辑表 ID 和注释字段/下标，使用有明确注释分支的内部结构。其 JSON 无行列或 span，无额外源文拷贝。无可解析网格的注释仍以其表格块为主，避免把独立注释绑定到相邻表格或虚构单元格。关闭上下文时注释仍照常翻译及回填。现有 Prompt 和技术文本预算继续适用。
- **Word 展示身份。** 按注释字段和原下标组织新范围的输出及证据。现有表格计划继续负责续表兼容性。只有源位置已确证为同一注释，并且合并后的输出符合现有兼容条件时，才沿用原注释代表。独立位置即使译文相同也分别输出。译文不兼容时用原有分段及 `table_render_layout_incompatible` 证据保全内容。布局和写入共享一个位置投影，持久化认证消费同一规则。需要跨重读保留的源事实限于别名下标及源角色、代表位置，保存在新范围的 IR 字节中，与原文、表格位置和已验证的续表关系核对。原始片段、注释文本和现有来源账本保持各自存放。
- **表转图验证。** 当前 `validate_table_figure_bindings()` 会对比图题和从原始 runs 重建的原文，直接比较将拒绝合法译文。将验证分为源来源和当前显示两部分，严格验证原始 runs、来源指纹、题注位置、资产和角色。源件入口、direct 和历史件保留逐字核验。新范围目标仅在经过已校验源件、目标位置精确回填及整批准入后使用译后路径。以现有 Artifact 来源角色、绑定的 source IR 和恢复摘要为边界验证目标，IR 中的范围标记只选择抽取规则。重读仍复核已登记的目标字节和 Word 证据。
- **审核和调试。** `review_content.py` 的预期覆盖用源范围重算，`_log_evidence()` 由明确的 field/index 取未 strip 的实际回填值核对 restored digest，注释不落入 HTML 分支。`_parts()` 为新注释提供相同的 `unit_id`，使批次、术语、定位和原译对照都指向同一位置。旧注释可显示来源，旧批次覆盖分母沿用当时的抽取范围。已有 `translation_qa.py` 调试视图补齐同一范围的注释段，保持历史正文与 HTML 视图行为。沿用已有授权、全文调试开关、日志脱敏和证据保留策略。

## 原生上标与报告

由共享 `app/conversion/docx_rules/formula.py` 负责。在现有分隔符闭合检查之后、进入 OMML 解析之前，判断整个已识别表达式是否为无基底的上标组，组内容限一个或多个括号内的 ASCII 整数。接受 `^{(1)}`、`^{(1)(2)}`，保留组间已有空白。该组由现有 `_word_run(..., superscript=True)` 生成，结果使用现有 `semantic_runs`。保留 `MathSpan` 源偏移、原文摘要、分隔边界和整段翻译保护。常规数学、非数字内容、带基底的式子或不完整分隔符继续由原解析及降级路径裁决。

正式 Word 写入、公式报告和持久化重读复用现有锚点和投影。校验实际 `w:r` 的文本及 `w:vertAlign`。历史 `text_fallback` 由现有重放路径按已认证报告还原，不用新渲染结果重判旧件。报告版本和错误码用现有定义。源 IR 或 Word 中无关的脚注编号、表格、图片及版式继续按各自合同处理。

## 兼容发布边界

旧源件可以由包含这项修复的读写者消费。旧二进制会忽略新范围，无法作为新源件的兼容写者。若之后进入发布，按已有批次生命周期部署流程同步切换相关执行者。回退时保留能理解新源件范围的执行者或先由其处理已挂接的新源件，再切回旧写者。现有在途根计划和历史产物遵循保留策略。生产切换是独立操作。
