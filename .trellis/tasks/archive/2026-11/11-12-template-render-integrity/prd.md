# 模板与渲染资源完整性

## 目标与基线

让正式 Word 渲染、重试和发布证明消费同一组已认证的任务资源，并在生成和发布边界发现损坏的模板装饰、配置或资源。

- 2026-11-12 本地 `main`：`30081252df51acdc3205809fe51f8b7df315a2e6`。实施分支：`codex/template-render-integrity`。需求源为原工作树中的《md2word 模板与渲染完整性优化实施清单》，执行顺序采用用户消息中的七项顺序。
- 默认发布 seed 为 `default@2`。manifest 绑定的 DOCX 承载页眉、页脚与公司 Logo，v2 YAML 承载页面、字体、颜色、段落和表格样式。默认关闭页眉和页脚覆盖。
- 默认 DOCX 基线 SHA-256 为 `7b3efd9ce7f19f19ed3a667d10d34995cc6a5b574b24abd85c52a23901577a88`，v2 YAML 为 `132d0bb76e71c807912031199e894dfc0e3d50bd7534180f8ceaba7a5fa20b4d`。现有两组指定测试在上述提交通过 78 项。

## 验收条件

| 编号 | 可观察结果 |
| --- | --- |
| TPL-BASE-001 | 运行时代码变更前，用 manifest 解析的真实模板渲染纵向单栏、双栏、横向、恢复纵向单栏。断言可打开、页眉页脚、Logo 媒体 SHA-256、引用关系、Section 继承、首页和奇偶页设置以及关闭 override 时的保留行为。Logo 从关系动态发现。 |
| TPL-RSC-001 | 带快照的 direct 和翻译任务按版本、payload 与实际文件 SHA-256 核验 DOCX、YAML 和术语规则。任务首次渲染后可用已核验副本重试，共享资源变化不影响副本；首次资源篡改、任务副本篡改、坏快照、资源不可用均给出稳定错误码且不暴露路径。物化使用同目录临时文件、flush、fsync、原子 replace。普通重试复用原绑定，显式选择其他术语资源维持现有授权和语义。发布证明绑定实际渲染资源。无快照历史任务维持原入口。 |
| TPL-QA-001 | 生成 `template-conformance/v1`，独立识别页眉、页脚、媒体和 Section 引用。损坏 ZIP、缺部件、丢引用、错误关系目标、媒体缺失或替换可检测。单独打开任一 override 仍检查另一侧的保留和两侧关系。无模板模式可用。 |
| TPL-VAL-001 | draft 创建、DOCX 替换、版式 draft、publish 和 bootstrap 复用同一联合预检。校验 DOCX 可打开、内部部件、Section、关系及媒体，校验 YAML schema、有效页面、颜色、字号、间距、override 和实际 Word 样式类型。预检失败无新增版本目录、半成品资源记录或默认指针变化。保留成功验证任务和既有发布权限。 |
| TPL-CFG-001 | 编辑 schema 每个叶子均登记实际消费者、适用条件或只读用途。以真实基线和单字段变异证明页面、标题、正文、表格、装饰字段在对应 OOXML 分支有效。已支持的只读或隐藏 renderer 字段（含页面宽高、`word_style_name`、`table_style.header_bold`）有定向验证；不借此扩大编辑能力。 |
| TPL-QA-002 | 新报告进入现有 renderer evidence、质量门和 Datasheet 质量报告。阻断码影响质量状态；事件仅输出固定码、布尔状态与计数。旧证据缺少该字段时仍可读，有该字段时按版本及产物绑定校验。 |
| TPL-GOV-001 | bundled 当前默认从 manifest 解析，保留持久化版本默认指针及历史路径。release check 包含模板联合预检、默认绑定、字段消费和装饰基线。历史 YAML 的用途通过 manifest 旁注和维护文档标明，保留历史字节与 SHA-256。 |

## 交付边界

保留现有 API、资源版本历史、默认模板二进制及正常默认文档可见输出。范围限于既有模板、渲染资源、质量和发布检查，不增加在线 Word 编辑、用户回传、云平台、多解析器、品牌工作流、Logo YAML 配置或大规模样式重构。
