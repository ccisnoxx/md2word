# 来源账本设计

## 合同归属

MinerU 转换拥有源分支选择、规范化及源位置。DocumentIR 完整性模块拥有账本解码、逐项比对和受控错误。翻译服务拥有 item ID 到目标字段和下标的回填。正式 Worker 拿到已验证的批次结果后调用同一回填逻辑。渲染和持久化重读读账本、复算证据，沿现有产物字节摘要及 render evidence 认证。

新正式转换写入可选的文档级 `source_item_ledger_scope`，包含版本和按文档顺序排列的注释归属块 ID。每个主列表块保存 `metadata.list_item_ledger`。仅有应保留注释的块保存 `metadata.annotation_ledger`。文档级范围可识别整份注释账本连同数组被移除的情况，无需为普通正文块写空账本。由现有整页降级入口按已认证的移除块更新范围，保留页继续核验。未知版本、范围与账本冲突、缺失必需账本一律拒绝。

## 列表项

`select_mineru_list_source` 仍负责选择权威分支。按真实源结构枚举项，使用现有文本、富文本及公式规范化规则生成冻结输出投影。先冻结源序号、规范化输出及摘要，再组装 IR。后续对账从账本和实际字段分别取值，不能从事后消费结果重写预期值。冻结文本只在转换期间留在内存。

| 字段 | 约定 |
| --- | --- |
| `version`、`selected_field`、`mode` | `list-item-ledger/v2` 与实际读取分支。 |
| `source_item_count`、`empty_item_count`、`item_count` | 分别是枚举源项数、空源项数和实际输出总数。文本拆分模式以既有拆分规则识别出的逻辑项作为源项。 |
| `source_index`、`source_sha256`、`empty` | 零基源序号，稳定序列化选中源值后的 SHA-256，以及实际无输出标记。结构化 v2 和 legacy 项按原序枚举，保留空槽。 |
| `output_index`、`normalized_sha256` | 一对一时记录零基输出位置及冻结规范化文本的 SHA-256。空项的输出位置与规范化摘要为空。 |
| `output_start`、`output_end`、`normalized_sha256s` | 一对多时使用左闭右开区间和按区间排列的逐项摘要。每个输出位置必须被精确覆盖一次。 |
| `sequence_sha256` | 对带版本的有序源记录计算摘要，覆盖源序号、源摘要、空项、输出位置和有序规范化摘要。译后保持此值和全部源记录。 |
| `target_sha256` / `target_sha256s` | 仅在译后为有输出的记录登记，按同一位置对齐。每个目标摘要来自已认证的回填值。 |

文本摘要对实际 IR 字符串的 UTF-8 字节计算，统一使用 `sha256:<hex>`。结构摘要沿用项目确定性 JSON 摘要惯例，列表顺序参与计算。对账验证数据类型、源索引连续性、空项与映射互斥、区间连续完整、计数与序列摘要。direct 将实际 `list_items` 的逐项摘要与源规范化摘要核对。已经翻译的 IR 比较目标摘要，并保留源序列约束。文本相同的输出仍须占各自位置。一对多用逐项摘要防止同区间内换位。既有显式列表缺少可见正文的拒绝规则继续适用。

## 题注和脚注

源注释身份取自按结构识别出的逻辑注释。题注复用 `caption_reconciler` 已知的组、片段与 donor 位置，沿其既有守恒核验接受跨块题注与源串拆分。脚注从实际注释字段及原位置收集，在可确认的富文本 run 或连续片段边界内归一化，保留已有合法拼接。独立位置的相等字符串分别入账。只有源定位或既有绑定证据能证明同一逻辑注释时，才按同一个注释处理。

归并和角色转换须保留来源到目标的映射，之后才能写入注释数组。表前条件、表转图派生标题及证据型正文仍由已有规则核验。它们不占 `captions` 或 `footnotes` 的下标。修复后的题注账本挂在目标块上，`block_id` 保留来源块身份。

`annotation-ledger/v1` 的 `items` 记录 `block_id`、`field`、`source_index`、`source_sha256`、`target_index`、`target_sha256`。源下标按来源块与字段的逻辑注释顺序分配，先于目标块分配；必要的原始片段证据沿用已有来源定位。目标下标是账本所属块对应数组的实际位置。源摘要使用已冻结、可送入 IR 的规范化注释文本。direct 的目标摘要等于源摘要，译后保留来源值并换成已验证译文的摘要。每个独立源身份恰好对应一个目标位置，全部数组位置连续且完整；校验同时覆盖目标内容和顺序。

已知派生的 `block.text` 继续使用题注别名。新 direct 产物沿用现有按位置的渲染、规划和实物对证路径，以账本范围选择该规则。复用正式注释位置和已核验续表代表机制，保留独立位置，不把同一来源的别名重复写入 Word。规划、写入及重读应使用同一选择条件。direct 产物不建立翻译范围。旧 direct 仍按当时的渲染证据重读。

完全同文的两个值若只交换字符串，输出序列本身没有发生可观察变化。通过两个独立源位置、完整的目标位置覆盖和翻译 ID 顺序约束，检测此类数据的漏项、重用位置及错绑。

## 翻译与持久化

回填以可信源 IR 和已核验的批次结果为输入。翻译前核对 source/direct 账本。新 Worker 源件带既有 `annotations-v1` 范围，同步入口沿现有准备规则固定范围。用账本枚举应译的输出位置，与抽取出的 `(item_id, block_id, field, index)` 按顺序核对。继续复用批次对有序 ID、缺失、重复和多余项的准入校验。fan-in 还须对照完整源计划，避免局部正确的结果覆盖同一位置。位置有且仅有一个通过校验的非空结果后，才在副本中回填并更新目标摘要。目标摘要从已验证的 replacement 生成，再用真实回填值重算复核。账本中的源字段保持不变。

同步翻译和 Worker fan-in 都在成功返回或登记前调用这条边界。Worker 在写译后 IR、发布证据或切换任务指针前收口异常。源 Artifact 必须走已验证来源角色和字节绑定，目标 Artifact 必须走已完成翻译及源指针绑定，保持当前 `translation_items_applied` 合同。有源件和目标件的消费入口可核对双方冻结身份。DOCX 持久化重读使用已有文件归属、字节摘要和绑定证据，复算相同账本校验与摘要，支持注册源件已过保留期的现有恢复路径，无需追加源件读取。只读路径发现损坏时拒绝该产物。

## 恢复、错误及兼容

- 转换边界能够从同一权威源分支恢复时，用内存冻结投影恢复字段及对应派生值。翻译边界能够从已验证的原 item ID 和结果恢复时，用同位置回填。仅账本与冻结值一致、所属位置唯一且恢复后全量复核通过，才登记 `source_ir_integrity:ledger_recovered` warning。恢复不从相邻位置猜测，也不以已有目标正文重算预期摘要来漂白损坏。
- 保留 `source_ir_integrity:list_item_count_mismatch`，新增固定的 `source_ir_integrity:list_item_ledger_mismatch` 和 `source_ir_integrity:annotation_ledger_mismatch`。账本认证先于依赖注释内容的别名和表转图校验，以免缺项被报成不相关的无效输入。事件和复核摘要仅投影受控 code、块 ID 与计数。缺少可信内容、源证据或翻译身份时无法恢复。批次 Provider 错误继续沿已有专码处理，账本层发现的实际不一致沿 `source_ir_integrity` 收口。
- 表格单元格、参数列规则和既有表格 evidence 由当前 owner 处理。`row_ambiguous` 不参与此阻断。
- 通过版本显式分派。历史 v1 继续产出原形的计数摘要，无账本历史件保持原来的字段省略、序列化和 render hash 形状。范围字段缺省时须完全省略。新件只写当前版本。已有历史翻译批次继续以冻结源件重建原目标集合。
- 新件写入、翻译、渲染和重读支持须一起落地，避免滚动期间新写旧读。回退写入之前须保留能读取新件的运行版本。不可通过剥除账本回退或跳过坏件检查。
