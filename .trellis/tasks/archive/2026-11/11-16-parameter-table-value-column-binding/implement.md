# 参数表数值列归属检查实施计划

实现和检查时从 [Word 生成规则](../../../../spec/backend/word-generation-rules.md) 定向读取 TABLE-001 至 TABLE-004、QUALITY-001、QUALITY-002 和 QUALITY-004。该文件超过 Trellis 自动注入的单文件上限，需直接读取这些章节。

## 实施顺序

1. [x] 固定 [三份输入](research/samples.md) 在现有授权测试存放范围内的引用。将两个 SN74AC244 v4 原包作为独立回归项登记，固定同一源 PDF 和独立标注。进入回放前强制核对指纹，未找到输入时保留具体缺测原因。OPA228 使用已有 Golden PDF 切片与匹配 gs-008 包。
2. [x] 在 `app/services/tables/validator.py` 增加只读源 Grid 检查，覆盖只含 `td` 的样本表头、独立列、多器件组和合法合并。由 `quality.py`、`evidence.py` 的既有契约认证并聚合。确认检测值使用来源而非译文，且报告可确定性复算。实际 OOXML 的原生表结构仍由现有渲染计划与证据负责。
3. [x] 在现有授权表格质量详情中投影定位和值，同时提供当前报告摘要。验证报告可读性、版本兼容和敏感信息投影边界。候选产物登记和最终质量汇总继续走现有证据管道。
4. [x] 在现有复核请求中接受明确确认的报告摘要，并随已验主件绑定写入原审核记录。复用 `review.py`、`use_cases/review_writer.py` 的锁内复核以及发布预检和提交重核。所有正式发布入口使用同一确认有效性。旧复核调用对涉及疑似项的主件无法绕过确认，未受影响请求、已发布快照与历史追加记录保持可读。
5. [x] 完成定向回放和合同验证。独立复核了同一任务在读取质量报告、提交确认、发布提交之间的证据校验，以及重复表头和续表识别。已更新 Word 生成规则。 [验收记录](validation.md)

证据消费涉及 [表格附件校验及读取](../../../../../app/domains/document_jobs/table_evidence.py)、[复核质量投影](../../../../../app/domains/document_jobs/quality_review_projection.py)、[基础质量汇总](../../../../../app/domains/document_jobs/base_quality.py)及 [发布预检](../../../../../app/domains/document_jobs/use_cases/publication.py)。先核对现有授权与摘要持久化位置，再选取同一权威字段。每次审核请求在拿锁前验证报告，锁内比较当前选定主件和报告身份；正式发布提交复查已认证身份。现有表格证据缺损时走现有失败边界，避免把无法验证的报告投影成空清单。

| 范围 | 最小验收证据 |

| 草稿、复核、正式发布 | 在现有 `tests.test_document_job_delivery_state_api.DocumentJobDeliveryStateApiTests` 和现行发布合同测试入口加入指定用例，并按新增用例名执行。覆盖内部下载、未确认批准/正式发布拒绝、当前报告确认、其他发布条件仍然有效、遗留审核入口、缺失或失效证据、读写之间换件、发布提交竞争，以及拒绝时零发布记录。正例保留旧批准路径。 |

执行前记录实际调用和用例名。验证合并与可编辑性时直接读 Word 表结构，以独立标注核对正确归属。这三份样本不提供新一轮商业 Word 客户端签字。线上或真实 MinerU 重传无需用于本次离线回归。

## 评审与回退

- 优先校核正例误报和无单元格 bbox 的结果。现有报告格式若必须引入新版本，保留旧读取与已审核/发布身份，确认回退版本可以读取新记录后才允许回退。
- 以 [设计](design.md) 的主件与报告绑定为正式发布条件。对丢失或过期的确认，继续交付可编辑内部草稿，正式发布保留拒绝原因。
- 本计划评审通过后进入实施阶段。部署、改生产配置、提交和推送各按项目授权执行。
