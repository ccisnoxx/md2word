# B1 候选与恢复验证设计

## 来源与隔离

用固定 main 提交导出正常基线，在临时目录叠加可审查的候选差异，沿用仓库现有锁定依赖。记录基线 SHA、候选差异 SHA-256、依赖及构建输入身份、源码清单与进程实际加载路径。验证只访问独立临时仓储和测试产物。历史 PR #9 的候选脚本与记录可从 Git 对象只读参考，证据不跨构建继承。

## 停写边界

- `app/services/renderer/block_anchors.py:126` 可让生成端不建通用锚点，`block_evidence.py:488` 会省去同次锚点证明。当前 `render_evidence.py:368` 会拒绝缺该证明的 v2 新件。候选差异须让明确的停写构建通过正式新件流程，保留正常构建的缺证拒绝、同次 plan／trace 对账和必需内容认证。
- `app/domains/document_jobs/preview.py:225` 在同一成功分支生成页映射和页级质量报告。停写仅限新页映射，须核对 `preview_evidence.py:139` 的计划认证和 `:96` 的报告绑定，避免把可选锚点依赖带入停写新件的计划认证，或让冻结的页级质量状态出现未记录变化。对有效旧报告保留原绑定。关闭页面观察或预览不能单独证明 B1 停写兼容。
- 停写检查核对 DOCX XML、独立锚点证明和 manifest 字段。模板书签和公式、图片等独立内容证据仍按现有合同处理。

可复用 `tests/test_preview_page_mapping.py` 的 manifest 夹具、`tests/test_document_job_result_persistence.py:208` 的三入口模式，以及历史 PR #9 的独立进程指纹做法。以 `app/domains/document_jobs/render_result.py:70` 和 `:178` 为三条入口的当前落点。历史样本优先使用可获得且可验证来源的原始离线产物，标注生产者版本。合成负例和当前构建样本单列，历史原件不可取得时将该证据保留为缺口。
