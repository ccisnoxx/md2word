# RND-504 Word 预览兼容回归与运行说明

## 目标

为现有 Word 预览链路补齐三类兼容回归，让维护者能按当前配置判断启用条件、识别存储故障并选择恢复动作。

## 基线

当前 `main@ab03ba49` 已有沙箱 Provider、产物登记、仓储领取和下载授权。[历史 PR #8](https://github.com/ccisnoxx/md2word/pull/8) 的 `27e9b1a` 用于定位缺少直接覆盖的用例。历史请求幂等重放已有 `tests/test_word_preview_historical_replay.py:139` 的回归。

## 需求与验收标准

- [x] **AC1 跨进程领取。** 在真实 file 和 SQLite 适配器上，让两个独立进程竞争同一待运行预览。每个适配器应有一个 `claimed` 和一个 `busy`，重新读取仓储后当前 run 只消耗一次 attempt。
- [x] **AC2 部分登记失败。** 让初次预览先成功登记 PDF，再在登记页图时失败。保留原选定 DOCX、凭据和字节，任务沿既有失败路径收尾。未确认的 PDF 不在任务文件列表公开，下载授权拒绝。
- [x] **AC3 签名有效期。** 经任务下载授权签发 S3 预览 PDF URL，在 manifest 和必需页图分别最早到期的场景中，签名参数和返回期限均受完整证据集合的最短剩余有效期约束。
- [x] **AC4 运行说明。** 在现有后端 runbook 补充 Word 预览的默认配置、沙箱启用所需证据、冻结快照、产物登记和存储失败处置，以及现有的重试和下载边界。明确离线回归的证据范围，并引用仍待验证的 B1 回退条件。

验收依据见[交付与验证记录](./verification.md)。

## 范围边界

交付限运行说明与以上三类定向回归。产品代码、配置、API、数据库、生产沙箱启用、B1 实现及演练均在范围外。若发现现行行为不满足验收，记录差异供复核。

规划阶段仅创建任务和整理规划。收尾阶段保留 `en2zh-runtime-evidence.md` 原样，复用实施阶段的定向回归结果。
