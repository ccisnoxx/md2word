# 完整 gs-008 的只读坐标探查

## 输入与方法

使用完整缓存中与 v2 内容列表同源的 `*_origin.pdf`，两份实际指纹匹配[完整缓存清单](../../../../../../tests/fixtures/datasheet_quality/local_baseline_manifest.json)中的 `gs-008`。PDF 是 612 × 792 pt、旋转 0 的单页，实际表题为 6.7 Electrical Characteristics: OPAx227。源 Grid 表片段为零基页 0 的 `/0/2`，32 行 × 8 列。

按 `pdf_point_bbox` 将 MinerU 表区域 [89, 130, 908, 657] 换算到 PDF 左上点坐标 [54.468, 102.960, 555.696, 520.344]。与同文档 `layout.json` 中的表体点框 [55, 103, 556, 521] 各轴相差不到 1 pt，布局记录的页尺寸与实际 PDF 页框一致。同名 PDF 的配对反例见[页框与来源核验](pdf-observation-and-coordinates.md)。

本次使用本机 Poppler 26.06.0。下面命令用于读取实物观测，SVG 只落到临时目录。

```bash
pdfinfo -box "$SOURCE_PDF"
pdftotext -f 1 -l 1 -bbox-layout "$SOURCE_PDF" -
pdftocairo -f 1 -l 1 -svg "$SOURCE_PDF" "$TEMP_SVG"
```

用词框匹配实际表头色块，从 SVG 读取带描边的水平分段、垂直组边和可见字形位置；并以源 Grid 里两个请求位置的独立邻接内容定位 PDF 行。探查没有输入第二阶段人工核定里的目标列，也未生成修正后的 Word。
