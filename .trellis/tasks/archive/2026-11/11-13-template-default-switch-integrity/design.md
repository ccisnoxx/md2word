# 默认模板版本切换设计

## 现有状态与边界

- `resource_default_versions` 以 `(resource_type, resource_id)` 为主键，是每个模板版本默认指针的唯一来源。`template_state.json` 保存全局默认模板 ID，已有独立的 `PATCH /api/v1/templates/{template_id}/default` 入口。
- 目前 `set_default_template_version()` 在数据库写入后才调用 `_activate_template_version()`。该方法既检查文件存在性也修改全局模板 ID。随后还会通过独立数据库连接追加审计，并重新读取资源以构造响应。任一步失败都可能发生在指针已提交之后。
- 本方案将显式版本切换限制在指定 `template_id` 内，符合 `docs/api/templates.md` 描述的两个入口分工。依赖旧副作用的调用方需要另调全局默认模板接口。这是可观察的行为调整，需要在计划评审中确认。

## 切换顺序

1. 模板服务读取目标记录，拒绝不存在或非 `published` 的目标。读取数据库指针行，捕获版本和 `updated_at`，或者记录当前没有指针。读取指针发生在文件预检前，使以同一观察值开始的请求可以被区分为成功和冲突。直接读取指针行，避免把无法关联到记录的已有指针视为空行。
2. 在事务外调用 `_validate_registered_template_package(record)`，复用登记 payload 的自洽检查、实际 DOCX/YAML 联合预检和两个哈希比较。响应所需的文件元数据也在此阶段准备，发现读失败或元数据哈希不符时中止。对缺少 YAML 绑定字段的历史记录，若旧读取路径会回退到 manifest 的 YAML，拒绝将未登记哈希的配置激活为默认。显式 `null` 继续表示无 YAML。
3. 在一个短 MySQL 事务中锁定目标资源行，按 `published` 和已验证的 `snapshot_hash` 复查。已有指针按主键锁定，再比较版本和 `updated_at`，匹配后更新。无指针时用唯一主键插入，明确识别该插入的重复键为竞争失败。已是目标版本的请求仍须校验并确认当前指针，作为幂等成功处理。
4. 用同一连接读回默认指针并确认版本、目标状态和快照哈希。对已鉴权的 API 请求，使用现有审计事件格式在同一事务写入 `template.set_default`，沿用切换理由和追踪信息。事务异常由 `MysqlPersistenceBackend.connect()` 回滚。现有 `AuditService.record()` 可复用事件构造部分，其他调用仍各自持久化。成功响应使用事务确认结果和预先准备的元数据，避免提交后再做可能失败的文件读取、审计或默认指针查询。
5. 模板禁用沿用原状态和审计语义，通过 MySQL 在同一事务先锁目标版本，再用该事务的首次普通读取观察指针并决定是否写入状态。显式切换指向同一目标版本需要持有该目标锁。禁用先提交时，切换复查状态并拒绝。切换先提交时，禁用发现目标是默认版本并拒绝。首次普通读取发生在获得目标锁之后，也避免为不存在的指针加间隙锁。此约束用于模板禁用入口，通用资源服务的其他调用按原合同运行。

## 可观察结果

| 条件 | 接口结果 | 状态 |
| --- | --- | --- |
| 目标记录不存在 | 404 | 原指针保留 |
| 目标非 published、文件不可用、包不合法、记录或文件哈希不符 | 400，模板包问题沿用现有稳定原因码 | 原指针保留 |
| 预检后目标状态、快照或指针发生变化 | 409，`template_default_conflict` | 保留数据库当时的指针 |
| 指针读回不符或成功审计写失败 | 数据库事务失败 | 回滚本次写入 |
| 成功 | 200，`is_default` 和 `is_current` 为 true | 指针及审计一同提交 |

## 保证范围

- 保证覆盖预检、数据库冲突和提交前失败。若发送 COMMIT 后连接中断，可能无法判断数据库是否已经提交。沿用仓库区分提交结果未知的做法，返回明确的可重读状态，避免盲重试或回写旧指针。
- 数据库锁只保护版本记录和指针。登记文件遵循已发布资源不可变约定，外部在预检后修改共享文件仍由任务物化阶段校验并拒绝。此修复涉及显式版本切换入口，发布时附带设默认和启动登记仍是各自的写入路径。
- 使用现有表及列，部署无需迁移。应用回退后，已提交的指针和审计仍可读取。已创建任务的模板快照继续保留。

MySQL 8.4 的 `FOR UPDATE` 读取最新可用行并持有排他锁，主键唯一性裁决首次插入。见 [MySQL 锁定读](https://dev.mysql.com/doc/refman/8.4/en/innodb-locking-reads.html) 与 [InnoDB 语句加锁规则](https://dev.mysql.com/doc/refman/8.4/en/innodb-locks-set.html)。
