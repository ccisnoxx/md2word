# [P1] 默认模板版本切换完整性与并发保护

## 目标

管理员显式切换模板的默认版本时，只有登记资源可用且内容匹配的已发布版本才能成为新默认。失败请求不得覆盖原指针或其他请求已经提交的结果。

## 背景

`app/domains/templates/read_service.py:507` 先调用通用资源服务覆盖默认指针，再检查文件存在性并写本地默认模板 ID。`app/infrastructure/persistence/mysql/resources.py:191` 的写入不比较原指针。现有模板包预检可以从实际 DOCX、YAML 字节计算哈希，并与登记记录比较。

## 需求

- R1：显式切换前读取目标记录并验证 `published` 状态、快照身份、DOCX 和已绑定 YAML 的可读性、结构及实际 SHA-256。支持明确没有绑定 YAML 的模板版本。
- R2：以请求观察到的默认指针和通过预检的目标快照为条件进行 MySQL 切换。同一事务内读回确认后才提交。允许为已发布但尚无默认指针的模板首次设默认。
- R3：保持管理员鉴权、切换理由和成功响应结构。成功审计与版本指针一起提交。`set-default` 管理该模板内的默认版本，全局默认模板 ID 由已有 `PATCH /api/v1/templates/{template_id}/default` 管理。
- R4：两个请求基于同一旧指针切换到新版本时，只有一个成功。冲突请求返回 HTTP 409，可重新读取后发起新请求。直接影响目标状态的模板禁用操作需要与该切换互斥，避免把默认版本禁用。

## 验收

- [x] AC1（R1）：DOCX 或已绑定 YAML 分别缺失或不可读取时拒绝切换。资源仍能解析但实际哈希变化时也拒绝切换。数据库原默认版本与成功审计均不变化。
- [x] AC2（R2、R3）：完整的 published 版本可切换，提交后通过独立连接读回目标版本，成功响应标记为默认并记录一次审计。新任务按该模板 ID 绑定切换后的版本。覆盖无默认指针的首次设置及无 YAML 的合法版本。
- [x] AC3（R2、R4）：两个独立连接读取相同旧指针后分别切换至两个合法版本，只出现一个成功和一个 409。最终读回与胜出请求一致，且只新增胜出审计。覆盖默认行不存在时的首次竞争。
- [x] AC4（R2、R3、R4）：预检后目标状态或快照发生变化、同事务读回不符、审计写入失败时，本请求没有默认指针写入或成功审计。显式切换成功的默认模板版本不能被并发禁用。
- [x] AC5（R3）：对当前全局默认模板之外的模板执行版本切换时，只更新被指定模板的版本指针。使用既有全局默认模板接口切换模板 ID。

执行结果见 [本地验收记录](./verification.md)。

## 范围

覆盖显式版本切换 API、模板服务、MySQL 条件写入及必要的模板禁用并发检查。动态模板目录、Worker 资源副本、其他资源类型、`publish(make_default=True)` 和启动登记的流程由各自任务或既有合同管理。
