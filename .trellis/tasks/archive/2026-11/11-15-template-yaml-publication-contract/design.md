# 模板准入与正式来源设计

## 准入规则

模板包校验层负责判断三类事实。登记版本是否存在有效 YAML 绑定，基础配置或语言覆盖是否声明外部 Logo 路径，以及任一有效语言配置是否会启用并消费该路径。复用现有 `TemplateConfigPackage` 与 `with_language_override`，从与哈希核对相同的 YAML 字节判断。历史布局文件声明缺失与实物损坏分别报告。路径和哈希都缺失表示未绑定，半绑定、文件丢失或哈希不符沿用现有完整性错误。

| 意图 | YAML | `header.logo_path` |
| --- | --- | --- |
| 新建模板、上传或替换版本、生成样式草稿 | 必须通过联合预检，持久化绑定 | 管理员可预检有外部 Logo 的草稿 |
| 管理员发起草稿验证 | 必须有有效绑定 | 沿用草稿兼容模式 |
| 将草稿正式发布 | 必须有有效绑定 | 基础配置和语言覆盖均不得声明非空路径 |
| 已发布版本设默认、新任务绑定 | 必须有有效绑定 | 历史声明只有在所有有效配置均不会消费时才允许 |
| 已存在的任务恢复和内部下载 | 继续沿用原绑定与既有读取权限 | 兼容历史读取 |
| 准备新的正式文档发布 | 必须实际消费原绑定 YAML | 任一有效配置会消费外部路径时仅供内部使用 |

## 模板写入与默认指针

1. 在 `TemplateReadService` 各创建入口的联合预检加入 YAML 要求，先校验再分配版本、落盘及写目录。首次创建的 multipart 参数要求存在。版本上传和替换沿用有效绑定时仍登记新版本的实际哈希。编排预检与底层 loader 的历史兼容分开。
2. 样式编辑器以旧内置 YAML 派生草稿时，如果候选配置中的 Logo 路径在所有有效配置中都不生效，可以在**候选 YAML** 清理继承的路径，再按候选字节计算哈希及预检。若任一语言配置会使用外部 Logo，管理员提供清理后的 YAML 再发起发布。保留旧 YAML 的路径、字节、版本及 payload 哈希。
3. 将正式发布校验放在验证任务匹配及成功写入前。保留既有草稿 CAS、默认指针事务、读回和审计。版本默认与全局默认都按对应绑定准入，拒绝时保留原指针。
4. 启动登记和目录导入区分保留历史与新登记的正式版本，不能凭旧通用预检新增不合规的正式绑定。空库继续使用当前内置 seed。已有不合规默认指针保留为现状，提交时给出明确错误，由管理员显式切换到合规版本。兼容无效力的历史字段适用于带有效 YAML 的旧版本和现有内置 seed。

## 任务绑定与恢复

准入放在创建和克隆提交之前，认证最终被固化到快照的模板记录。隐式选择尤其要保留明确拒绝，避免 `build_resource_snapshot` 的旧降级分支吞掉模板准入错误。保留源快照的 clone 核对其原绑定哈希，不借用同名当前默认的资格。缺乏可认证绑定的旧任务可以选择合规版本重新克隆。

现有任务继续按历史恢复入口解析，包含保持旧模板绑定的术语重绑。新代入口（对已成功任务发起重新生成）执行已有资源完整性要求，并对仅供内部使用的原绑定给出明确原因。所有检查应用于现有支持的后端。基于登记版本的正式提交不得退回无快照路径。保留 renderer 和本地开发入口的旧配置解析。

file/SQLite 的非登记版本在新任务请求快照中记录 `template_layout_config_sha256`。renderer 在解析前校验本次读到的 YAML 字节，同一次读取用于计算哈希和渲染。历史恢复按字段是否存在保留既有行为。

## 渲染实物与文档发布

正式运行从已核验的任务副本消费 DOCX/YAML。正式资源可发布性同时依赖绑定状态、YAML 及 Logo 规则。关闭页眉覆盖时跳过外部路径解析与读取，保留 DOCX 页眉。历史、草稿验证和本地开发沿用原 YAML 目录解析。

共享发布证据校验必须识别按旧规则生成的结果。对已有报告复用经过认证的配置证据判定外部 Logo 规则，覆盖旧报告自称 `complete` 但含生效路径的情况，文件当前是否存在及 Logo 哈希有无均不作为准入依据。只针对新发布请求和发布前置检查。已发布记录、重放及最终件签发继续使用其既有冻结证据。

## API 与界面

- 在模板版本响应与模板摘要增加布尔字段 `legacy_internal_only`。已确认无绑定或历史版本会消费外部 Logo 时为 true。损坏文件仍通过现有资源状态与错误呈现。模板列表沿用既有授权范围，避免在任务列表为每行额外读取私有证据。
- 模板创建缺 YAML 返回字段错误。新任务、克隆及默认切换命中历史内部版本时返回 `legacy_internal_only` 原因。正式模板发布含非空 Logo 时返回定位到 `header.logo_path` 或对应语言覆盖的字段错误。沿用各入口既有 HTTP 分类与错误包络。
- 任务详情发布资格和提交拒绝共享 `legacy_internal_only` 原因。明确已知的历史绑定优先于笼统的来源不可用结论。普通 DOCX 继续使用 `internal_only` 下载分类。
- 模板管理页消费后端字段，显示仅供内部使用，阻止对应版本的发布、验证或设默认操作。首次创建表单同步 YAML 必填，上传版本保留有效 YAML 的继承交互。

## 兼容与回退

沿用已有字段和版本资源记录，无数据库 schema 变更。生产验证前先只读确认当前默认模板绑定与旧版本清单。若当前默认不符合准入条件，先选定可用版本和切换窗口，再单独执行运维变更。
