# 模板 YAML 绑定与正式页眉资产约束

## 目标

新生成的业务 DOCX 必须使用所选模板版本绑定的 YAML。正式页眉的 Logo 来自版本绑定的 DOCX，任务的正式发布资格在模板选择和任务详情中可见。

## 需求

### R1 模板版本必须有效绑定 YAML

- 新建模板、上传新版本、替换 DOCX 和版式编辑生成草稿都要保存有效的版本级 YAML 绑定。首次创建必须提供路径。已有模板上传或替换时可沿用既有 YAML，前提是新版本登记该文件和内容哈希。
- 无 YAML 的草稿不能发起验证任务或发布。正式默认版本切换只接受具备有效 YAML 绑定的版本，适用于模板下的版本默认与全局模板默认。
- 当前共享预检允许缺省配置，显式默认切换也曾将无 YAML 作为合法用例。[模板包预检](../../../app/domains/templates/package_validator.py#L98) · [原默认切换验收](../archive/2026-11/11-13-template-default-switch-integrity/prd.md#L21)

### R2 新任务使用通过准入的模板版本

- 覆盖默认选择、显式选择、所有创建新任务的克隆策略，以及管理员草稿验证。拒绝发生在创建任务、写入任务事件和投递 Worker 之前。
- 无 YAML 的历史模板版本继续可读。已存在的任务可在原权限和状态允许时恢复、重试和下载内部 DOCX。克隆到新任务须使用符合当前合同的版本。
- 模板 API 在历史版本和当前模板摘要上投影 `legacy_internal_only`。新建、克隆或默认切换命中仅供内部使用的版本时返回明确原因，相关历史任务详情也给出同一发布禁用原因。
- 当前无 YAML 资源可解析和渲染，但产生 `status=complete` 的来源证明需要本次渲染实际消费 YAML。保留源快照的克隆有独立准入路径。[版本解析](../../../app/domains/templates/read_service.py#L1004) · [克隆准入](../../../app/domains/document_jobs/use_cases/request_snapshot.py#L204) · [来源冻结](../../../app/domains/document_jobs/publication_provenance.py#L68)

### R3 正式模板发布排除外部 Logo

- 新发布的模板版本不得声明非空 `header.logo_path`，包括语言覆盖中的值。旧配置解析和管理员草稿验证继续兼容该字段。
- 历史版本只要有任一可用语言配置会读取外部 Logo，即仅供历史恢复和内部下载。准备正式发布的旧任务即使已有完整形式的来源报告，也要满足外部 Logo 约束。
- 历史 YAML 中不会被消费的字段可以保留，适用于现有 `default@1`、`default@2`。两份内置 YAML 的页眉覆盖均为关闭，正式渲染直接复用 DOCX 自带页眉。不可变历史资源按原版本和原哈希读取。
- 目前任务物化 YAML 后仍保留源目录，页眉覆盖启用时 renderer 从该目录读取图像。[任务物化](../../../app/domains/jobs/resource_snapshots.py#L517) · [渲染读取](../../../app/services/renderer/word_renderer.py#L125)

## 验收标准

| 编号 | 对应需求 | 可观察结果 |
| --- | --- | --- |
| AC1 | R1 | 缺省、空白、找不到或解析无效的 YAML 在创建、替换或发版前失败。已有有效 YAML 的版本上传可继承，写入的版本 payload 含路径及实物哈希。失败不留下候选版本、目录或成功审计。 |
| AC2 | R1、R2 | 无 YAML 草稿不能验证或发布。已发布但无 YAML 的历史版本仍可读，返回 `legacy_internal_only=true`，且不能被设为默认或通过显式、隐式、保留源快照等方式进入新任务。拒绝保留原指针，无任务和队列副作用。 |
| AC3 | R2 | 旧任务按原绑定恢复和内部下载。未正式发布的历史结果在任务详情和发布拒绝中可见 `legacy_internal_only`。既有正式发布记录及其下载继续可读。 |
| AC4 | R3 | 基础配置或任一语言覆盖含非空 Logo 路径的草稿不能正式发布。历史上会读取外部 Logo 的已发布版本被限制为内部使用，外部文件存在、缺失或变更时结论一致。已生成但未发布的对应 DOCX 同样受限。 |
| AC5 | R1、R2、R3 | 合规版本可通过草稿验证、发布、默认切换、绑定及渲染。内置历史两版用原 YAML 字节生成，DOCX 内嵌 Logo 可见，渲染不读取 YAML 所在目录的外部图片。合规任务继续生成完整渲染来源证明。 |

## 范围外

Logo 上传、额外资产快照、品牌配置系统、历史资源回填和生产默认版本切换。
