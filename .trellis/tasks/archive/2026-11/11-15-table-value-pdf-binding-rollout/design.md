# 参数值列绑定的上线前验收与灰度设计

第四阶段已用本地 Poppler 26.06.0 通过正式转换和实物重读。完整 `gs-008` 原 23 项中 9 项认证解除，余 14 项阻断。实际 Word 中 `±5 µV` 只在 TYP，`±100 µV` 只在 MAX。独立 LOW/HIGH 表覆盖贴边阻断与人工同包核定后放行。生产 Dockerfile 由 apt 安装 `poppler-utils`，仓库未锁定该包的版本。候选镜像、实际 Worker 进程、上游回包和实际 MySQL 尚待核实。[第四阶段本地验收](../11-15-table-value-pdf-binding-online/validation.md) · [运行配置调查](research/worker-and-rollout.md)

## 候选身份与实际 Worker

1. 在与目标配置匹配的隔离环境部署经授权的候选。固定 Git 提交、镜像 digest、平台和 Worker 执行入口。用独立的 MySQL schema、队列和对象存储前缀，限定测试身份和允许提交的 PDF。授权后的线上首次部署以关闭状态核对实际实例与候选证据的身份。
2. 以每个实际转换实例的应用用户及 PATH 核对 `pdfinfo`、`pdftotext`、`pdftocairo`、`pdftohtml`。记录四个路径、四个版本、执行用户、镜像身份和所在服务。版本由四工具的 `-v` 输出实取，须能解析且相同。分别核对活跃 API 和正式消费实际使用的开关和范围配置。API 在启动时构造配置，Celery 执行时从所在容器环境构造，须按各自时机确认生效。健康检查覆盖的裁图工具不能证明四工具可用。
3. 由真实进程消费任务，覆盖单页文字、字形和图线取证，验证进程实际能写临时文件并产生可读的工具输出。两类版式使用第四阶段真实夹具做对照。检查取证总预算最多 60 秒且不超过所余执行时限的一半，耗尽后原 blocker 及未决原因保持有效。记录耗时和现有失败、重试信息，不在此阶段改变阈值。[运行配置调查](research/worker-and-rollout.md)

## 真实 MinerU 同源与 Word 验证

使用获准提交的测试 PDF，走正式上传、真实 MinerU 原包归档和 Worker。记录上传 PDF 的实际长度、SHA-256 和文件 ID。沿同一任务的源 ID、`batch_id`、`data_id`、原解析代和明确的 raw 文件指针，重读已归档原 ZIP 并核对长度与摘要。核对正式规则选中的 v2、同文档唯一 layout 和对应的包内原 PDF，分别保存路径身份和摘要。包内原 PDF 与实际上传 PDF 的摘要相等才进入自动核定资格。现有系统不持久化网络上传摘要。若取证要覆盖实际发送的临时文件，在隔离环境对同次发送所读文件另算摘要并关联批次。

真实回包涵盖拟启用的模型及结果形态。回包本身已经正确落位时可作为正常对照，另取至少一个具有真实跨列且可认证落位的正例。完整 `gs-008` 同源回放和独立 LOW/HIGH 作为两类版式的可重复对照。核对 PDF 源行、Word 中实际占列、释放的格、单位以及相邻值。沿同代 IR、独立报告和 Word 摘要核对生效的 blocker ID。源不匹配、包内原件缺失、源行或列证据歧义继续阻断对应项。正式输入完整性或归属错误走既有失败路径。

待人工核定的格保留报告原发现和定位。管理员沿用原包提交核定，以同一 UUID 重试，并对新代实物重新认证。审批和发布各走正式入口，核对未决场景拒绝、证据齐备且其他门禁满足的场景通过。[同源证据调查与取证字段](research/mineru-provenance.md)

## 真实 MySQL 同包接纳

用与目标版本、schema、索引和默认设置匹配的真实 InnoDB。记录实际应用写连接的事务隔离级别、自动提交状态和锁等待参数。用两个独立连接的屏障使竞争实际发生。核对 job 主键锁在前，源 PDF、原包、IR、质量报告和 Word 的主键锁按文件 ID 顺序取得。获取锁后的读取用于核对当前版本与过期时间。

| 竞争 | 通过标准 |
| --- | --- |
| 相同 UUID 同时接纳 | 仅一次加代和审计。另一方得到同一接纳回执。相同 UUID 改请求拒绝。API 联测仅首次产生投递。 |
| 不同 UUID 针对同一基线 | 仅一方提交。另一方以当前状态或来源冲突拒绝，原账本无败方记录。 |
| 文件删除声明、过期、持锁方回滚 | 变化先提交或等待中到期时整批拒绝。回滚后再核实有效快照可接纳。验证等待、提交顺序和失败后保留的原 job 指针。 |
| 真实锁等待异常或提交回执丢失 | 无半写。释放锁后按原 UUID 对账，核实安全重试和唯一已提交回执。 |
| 旧代 Worker 回流 | 原执行代的受保护更新被拒绝。新代仍只用冻结的来源和资源，结果槽、账本和审计一致。 |

读取锁等待信息的授权具备时，保留相关会话行锁证据。至少记录可复核的等待、结果顺序及解锁后新连接可见的已提交状态。既有 fake MySQL 用例继续作为 SQL 形状回归。[真实 MySQL 验收矩阵](research/mysql-concurrency.md)

## 审批证据最后重核

现有批准先重读报告、IR 和 Word，再在提交前重核文件描述。审批仓储锁住 job 并核对代次、主件和 receipt。报告或 IR 的状态仍可在最后一次重核之后、审批提交之前变化。发布会独立认证并在提交时锁住所观察的依赖。该发布保护仍可能晚于一条不应生效的批准。

建议为带参数值列认证证据的批准，从 `VerifiedTableEvidence` 提取本次调用的 job 和三份文件登记快照传给仓储。保留对象读取、字节摘要和实际 Word 认证在事务外。MySQL 按现有发布顺序先锁 job，再按 ID 锁快照中的 Word、IR 和报告，在同一事务按取锁后时间检查当前指针、代次、receipt、归属、描述、到期和删除声明，再写批准。SQLite 在同一写事务内重核。file 沿用发布生命周期锁、job 锁和文件 ID 顺序。保持历史记录、API 请求和审批记录摘要的合同。应用处理证据冲突时返回现有 `409 review_result_integrity_conflict`，代次或当前主件变化仍用原来源冲突协议。

用已经由真实 Word 认证、基础质量可批准的结果做竞争测试。线程 A 在最后重核之后暂停，线程 B 用正式仓储提交报告或 IR 的删除声明，或使 IR 等待中到期。让 A 完成审批提交并确认 409、批准记录和序号无写入。对照验证 B 回滚或证据未变时可批准。另验发布认证前失效与认证后、提交前失效均无发布记录或客户可见件。网络读存储故障和受控的描述冲突保留相应现有语义。

核对目标对象存储对生成件的覆盖权限和生命周期规则。确认登记有效期内对象受正式写入和删除流程约束，支撑锁外实物认证与锁内描述重核之间的不可变假设。[审批与发布窗口调查](research/approval-window.md)

## 灰度顺序

1. **隔离验收。** 在候选正式入口用独立队列、数据库和对象存储完成 Worker、真实回包、MySQL、审批与停用演练。通过后保存证据和目标环境需复核的差异。生产切换需单独授权。
2. **关闭状态核对。** 生产经授权部署兼容读者和执行者后，保持 `DOCUMENT_TABLE_VALUE_PDF_BINDING_ENABLED=false`。核对所有相关 API、Worker、内联执行及恢复入口的实际镜像、配置和路由，确认常规转换、历史件读取、待执行意图兼容。发现会读写同一队列或账本的旧实例则暂缓启用。
3. **定向首轮。** 现有设置是全局布尔值。拟在正式 Worker 自动绑定及管理员新同包核定接纳处共用服务端策略。总开关开启且 job 的 `(tenant_id, company_id)` 在显式名单内才接纳新的绑定。名单初始为空，首轮配置一个获准测试公司，待各入口配置收敛再提交试点任务。已有同包 UUID 重放继续先查回执，已接纳意图按冻结资料执行。管理员权限和同源条件仍须成立。同一队列的混配消费者按取件时序分配，无法固定试点范围。
4. **逐批扩围。** 核对名单内和名单外样本及管理员新接纳、实际 Word 落位、认证与未决 ID 的对账、审批发布结果、Worker 取证耗时和超时、锁等待及死锁。任一错误落位、未决放行、越范围接纳或证据不一致误过门，都立即停止扩围并执行停用。出现重复取证超时或数据库争用影响常规转换时，先停用并定位。成功证据经核对后才增加获准的公司。

## 停用与回退

1. 在兼容的版本上关闭总开关并清空名单，按实际部署方式使所有 API/Worker 配置生效。核对新作业的绑定入口及新管理员动作停止。已完成产物、报告和批准发布记录保持可追溯。
2. 列出停用前已进入转换的代次与已接纳 UUID。常规停用在来源仍有效时允许已接纳动作按冻结资料完成且可查同一回执。完整性事故暂停受影响的执行、隔离受影响代次的审批发布，按既有权限处理已批准或已发布结果。关闭开关本身不会撤回这些状态。
3. 用同镜像或已验证能读写含 `table_value_column_replay` 私有账本、保留代次保护的版本作为回退目标。旧版本需先用真实已接纳账本验证兼容性。对照验证普通转换、已接纳 UUID、旧件读取、未决项阻断，记录停用时间、实际生效范围和遗留事项。[配置与回退调查](research/worker-and-rollout.md)

## 指纹不一致时的逐页比对

在现行线上原排版白名单路径内先核对当前任务的上传 PDF、原包、批次、data ID 与原解析代。实际选中的 v2 必须有唯一同文档 layout 和对应的包内 PDF。包内 PDF 摘要相同时走既有验证。摘要不同时，只有可确认同一解析尝试且所有页以相同工具得到相同页框、词框与 96 和 144 DPI 渲染像素，才继续列核定。本地 CLI 和缺可信来源登记的历史转换沿现有证据条件处理。

页面观察受既有文档取证时限约束。比对成功仅允许继续从上传原件取证，逐格 Word 认证仍拥有解阻责任。自动流程和管理员同包核定复核同一来源。比较证据关联上传及包内 PDF、选中 v2、layout 和原包；新代沿冻结来源重放。已有原件身份冲突、错页、差值、证据不全或预算用完时保持拒绝或未决。当前增加的内容仅涉及来源资格与取证，云 MinerU 传输协议和正式结构解析沿用现有版本。[逐页比对和验收边界](research/mineru-source-verification-plan.md)

## 表框截断校正

原框的完整表头验证失败后，才在同页 layout 已确认表体左右边缘各 1 pt 范围内查找实测相接边线。用同一页观测同时确认末列表头与表体。候选区域只延伸单侧，禁止改变垂直范围和另一侧。扩入文字、未证图形、邻接块、竞争边线或共享边界均不采纳。

逐格绑定保留原框，新的可选内部边界证明记录 layout 点框、取证框和相接线段。原框重读仍须等于源 bbox 的页坐标投影，附加证明还须符合页框和源 layout 的几何约束。旧版无边界证明的指纹沿用。管理员输入继续只接纳人工核定。审批和发布沿用既有 IR 及 Word 重验。
