# MinerU 原件指纹调查与同源验收方案

调查沿用第五阶段任务。当前线上参数值列绑定仍有同源阻断。计划保留现用严格校验，评审后才选择供应商取证和接口实施方式。[第五阶段验收](../validation.md)

## 两份真实回包的只读复核

对分别登记的 ZIP、对应上传 PDF 和正式选中的 v2 同名 PDF 重算 SHA-256，与第五阶段记录一致。P7 的上传件取自历史包的原件，LOW/HIGH 用原合成夹具重新生成并先验证上传摘要。两份真实 ZIP 的 layout 均报 `3.4.4`、`hybrid`、`medium`，各一页。原始归档和完整指纹仍以验收记录为准。[候选 Worker 和回包证据](worker-acceptance.md)

| 观察 | P7 上传 → 回包 | LOW/HIGH 上传 → 回包 |
| --- | --- | --- |
| 长度和 SHA-256 前缀 | 112080 → 112172 字节，`24f724cf…` → `69e9aaba…` | 1503 → 1067 字节，`bf90bdcb…` → `c5ee429f…` |
| PDF 结构 | 39 个对象，`startxref` 111118 → 111210，trailer ID 变化 | 5 → 6 个对象，`startxref` 1319 → 770，回包新增 trailer ID |
| 文档元数据 | 均为 PDFium，`CreationDate` 从 6 月原记录变为本次解析时段 | 上传无这些元数据，回包新增 PDFium 的 Creator、Producer 及本次解析时段的 `CreationDate` |
| 页面观测 | 原页框、旋转、词框 XML、96 和 144 DPI 栅格均一致 | 同左 |

开源 `mineru-3.4.4-released` 的同、异步解析入口会先预处理 PDF。默认选择全部页，PDFium 仍新建文档、导入页面并保存，Hybrid 随后以这份处理后的字节解析和导出 `*_origin.pdf`。PDFium 新建文档时可写入当前创建时间及 Creator。用临时环境内 `pypdfium2 4.30.0`（PDFium `126.0.6462.0`）对 P7 本地执行全页导入并保存，复现了创建时间和 SHA-256 的改变，词框和 96 DPI 栅格保持一致。该实验验证机制，不能确定云端的 PDFium 构建或具体分支。两个真实回包的字节差异与此机制吻合。[锁定版本预处理](https://github.com/opendatalab/MinerU/blob/0dfc9460cd9ab693b9af60ae3fbffd7bc111b062/mineru/cli/common.py#L711-L714) · [PDFium 重建](https://github.com/opendatalab/MinerU/blob/0dfc9460cd9ab693b9af60ae3fbffd7bc111b062/mineru/utils/pdfium_guard.py#L108-L151) · [归档输出](https://github.com/opendatalab/MinerU/blob/0dfc9460cd9ab693b9af60ae3fbffd7bc111b062/mineru/cli/common.py#L547-L560) · [PDFium 新文档元数据](https://pdfium.googlesource.com/pdfium/+/refs/heads/main/fpdfsdk/fpdf_editpage.cpp)

历史缓存回放以该包中的 PDF 作上传输入，证明有严格同源证据时转换链可复现。历史回放无法证明平台曾把原始上传字节不变地归档。

## 官方接口能提供的证据

- 托管 v4 批量上传公开文档给出预签名 PUT、`batch_id`、调用方指定且回显的 `data_id`、解析状态和结果 ZIP 地址。已查的公开请求选项、轮询结果和回调结构未列出保留上传原件的开关、原件下载接口、服务端读入原件的摘要或签名清单。是否有账号专属接口须由 MinerU 确认。开源 FastAPI 的 `return_original_file` 控制将已有产物加入 ZIP，3.4.4 的 PDF 产物仍由预处理字节生成。[托管 v4 中文文档](https://mineru.net/doc/docs/) · [开放平台接口](https://mineru.net/apiManage/docs) · [开源选项定义](https://github.com/opendatalab/MinerU/blob/0dfc9460cd9ab693b9af60ae3fbffd7bc111b062/mineru/cli/api_request.py#L182-L203) · [同版取证明细](mineru-upstream-rewrite.md)
- `data_id` 关联业务任务，回调 checksum 的 SHA-256 输入为 UID、seed 和通知内容。二者没有服务端解析输入字节的独立证明。OSS 成功响应中的校验字段如 MD5 或 CRC-64 可辅助核对上传传输。即便该对象上传可证，也须有同一对象版本被本次解析消费并生成当前结果的绑定。验收仅记录允许的校验值和脱敏关联，不保存预签名 URL、回调凭据或令牌。[回调及轮询合同](https://mineru.net/doc/docs/) · [OSS 存储一致性校验](https://www.alibabacloud.com/help/en/oss/user-guide/data-verification/)
- 后续向供应方确认三件事。确认当前账户和模型的 `_origin.pdf` 是否是重写后的解析输入，与实际回包的版本关联。确认能否返回逐字节上传原件，且同批同项明确关联到实际解析结果。若仅能给指纹，确认它是否由解析端在任何重写前从实际读入对象计算，并由受认证接口或签名绑定本次输入、页映射和结果，索取字段语义、可用模式和可核对回包。当前未联系供应方。

## 缓存与回包复用

- 平台文档在单文件 URL 解析及批量 URL 解析中给出 `cache_tolerance`，默认 900 秒（15 分钟），适用于 `no_cache=false` 时可以复用的 URL 内容。设 `no_cache=true` 可重新从 URL 取内容。对于本项目的本地文件批量上传 `/api/v4/file-urls/batch`，公开文档给出的 24 小时是预签名上传链接的有效期。文档未给出重复上传同一 PDF 时复用 ZIP 的窗口，也未给出 `full_zip_url` 的固定有效期。[MinerU 开放平台文档](https://mineru.net/apiManage/docs)
- 第五阶段已保留两个不同真实 LOW/HIGH 批次的摘要。第一批由隔离宿主提交并在候选 Worker 重新获取，第二批由候选 Worker 实际重新上传。上传 PDF 的 SHA-256 都以 `bf90bdcb…` 开头，两批的 v2 和 layout 摘要分别相同。ZIP 摘要是 `ad8bafab…` 和 `a61757b0…`，包内 PDF 摘要是 `86feac65…` 和 `c5ee429f…`。该对照未控制缓存时间、账号行为或服务内部去重策略，不能量出缓存期限。逐次解析以本次任务身份、实际登记的 ZIP 和对应页面证据为准。

## 逐字节来源方案

1. **固定实际发送的原件。** 以本系统已登记的不可变上传文件为准。在进入 PUT 的字节流上核对长度和 SHA-256，与登记值比较，冻结对应文件 ID、租户、公司、任务及原解析代。记录 MinerU 账户范围、批次及唯一 data ID，重试匹配当前解析尝试。历史单结果缺 data ID 的普通转换兼容路径不为新的输入证明补造匹配身份。
2. **优先保留现有精确匹配路径。** 若供应方能在当前路线返回原始字节，使用正式规则选中的同文档原件，复算 SHA-256 和长度，核对与第 1 步相等，再绑定这份 raw ZIP、选中的 v2、唯一 layout 和页映射。命名及返回路径须由供应方契约确定。这个入口可继续用现有逐字节核验。
3. **原件不能返回时，评审供应方的输入证明。** 供应方从同一次实际读取、预处理前的完整 PDF 计算 SHA-256 和长度，通过可验证签名或经认证的不可变结果接口，把输入摘要与批次、data ID、解析输入对象版本或其他唯一身份、页面选择和不可变结果绑定。结果须能按 raw ZIP 摘要或经认证的不可变结果身份复核，并核对选中 v2 和 layout 的实际字节。签名属于供应方信任边界，调用方回显摘要、上传回执、PDF 名称和几何相似度均不足以授予资格。该方案属于后续需要批准的新证据入口。需保留可重验的证明及绑定，避免重跑时信任只在日志中出现过的指纹。
4. **供应方无能力时保持门禁。** 只有另行选定受控的 MinerU 入口时，才考虑由接收原件且控制实际解析的服务保留原字节，并把输入和不可变结果同次登记。现有云回包照原样保留。给已收到的 ZIP 补入本地 PDF 会伪造同包来源，不能作为其证明。
5. **来源核定后继续原有实物门禁。** 用实际上传原件做 Poppler 取证，独立核对页号、旋转、页框及表与值的位置。首轮使用全页且能验证页一一对应的处理。存在抽页、重排或未验证的坐标变化时保持未决，直到另有可信映射及实际版面验证。自动绑定和管理员同包重放共同使用同一输入证明。重放继承原解析代和原包，换输入或重新解析时重做绑定。只有实际 Word 逐格认证通过才解除对应质量阻断。来源缺证据沿用 `source_pair_unverified`，当前登记或归档字节冲突沿用完整性失败。独立表报告、审批事务内重核和发布门禁继续生效。

项目现状在 `mineru_execution.py` 登记原包及解析身份，`table_value_column_sources.py` 验证归属与实际字节，`pdf_value_column_review_flow.py` 的 `_paired_origin` 核对原件。管理员入口同样经 `verify_table_value_package_origin`。

## 仅用于参数值列核定的页面比对方案

两份历史实测各自比较实际上传 PDF 与自己的包内 PDF，页框、词框和 96 / 144 DPI 图像都相等。这可以作为两例的页面版面一致证据。提出在现有任务来源校验上，另评审一条只用于参数值列核定的路径，把页面版面一致作为处理过的 PDF 仍可用于对照的依据。当前逐字节校验及上线阻断继续生效，评审确认后再做隔离验证。

1. **保留任务来源和文件完整性。** 核对实际上传 PDF 的登记摘要，以及本次可信 MinerU 批次、唯一 `data_id`、原解析代、归属和当前 raw ZIP。固定实际选中的 v2、layout 和对应包内 PDF 摘要。摘要和页面比对证据随核定保存。同包重放复核这些绑定并保持原解析代和原包。
2. **逐页比对同一任务的两份 PDF。** 首轮只覆盖全页、有文本层且页序一一对应的文档。同一固定取证工具版本和渲染设置比较全部页的页框与旋转、词及词框、96 / 144 DPI 渲染像素。缺页、页序不清、无法取证或任一观察不同的任务继续未决。日期和无关 PDF 元数据可以变动，证据记录保留两份 PDF 的实际摘要和页面比对结果。
3. **核定仍取自实际上传 PDF。** 原件用于投影选中的 layout 和表位置，现有行列绑定及 DOCX 实物认证仍逐格执行。包内 PDF 用于版面对照。通过的页面比对证明观察到的版面一致，逐格认证决定对应的 blocker 能否解除。审批发布守卫维持原有合同。

隔离验收优先回放保留的两份真实结果，按实际上传原件核对页面并跑到 Word。P7 有 18 个原跨列项，可验证这一证据路径的实际解阻结果。LOW/HIGH 的真实回包零候选，另用原有划线跨列夹具验证独立版式。加入多页错序、同名异源、只改数值或表格线、串批次、损坏产物和证据不全的反例，核对未通过核定的格保留原 blocker。测试重复上传时使用新任务和各自归档证据对账，ZIP 相同与否只作记录。

## 下一轮隔离验收标准

使用与拟启用配置相同的实际 Worker 镜像、模型与正式上传和归档入口，测试账号、队列、元数据与对象区独立。只对拟启用且已取证的接口和结果模式开放。每例保留候选镜像、平台与工具版本、输入摘要和长度、解析尝试、可重验的供应方证据、ZIP/v2/layout 摘要、同代 IR/Word/报告摘要及门禁状态。

| 场景 | 通过标准 |
| --- | --- |
| 新鲜回包和不同版式 | 真实上传并获取实际回包，验证 MIN/TYP/MAX 与 LOW/HIGH 两种版式的输入到输出链。按获批证据路径验收，至少一份真正有错列候选的回包通过核验、实际 Word 落位及原 finding 对账。识别正确且零候选的回包仅证明相应来源或页面证据与常规交付。 |
| 重复解析和页映射 | 同一输入用不同解析尝试分别验证，记录本次 batch/data ID 和独立结果。ZIP 可随服务输出更新，各自须匹配其权威证据。加入多页及旋转或不同页框对照，明确同页、同行和挪动目标。未证实的抽页、换序或坐标应保持未决。 |
| 错配和降级 | 两份真实指纹不一致回包仍是当前逐字节守卫的反例。按所评审路径另覆盖同名异源、视觉相同但缺完整链路的异字节、缺原件或证明、摘要/结果被替换、同批 data ID 串包、跨任务及旧代重放。新证据另验伪造、缺失和超过授权范围的证明。在每种反例中核对不写入错误的认证或同包接纳。 |
| 实物与审批发布 | 合法共享值、贴边、文本或行归属不确定仍未决。盘点每个解除和未决的 finding ID，核对实际 Word 占列、释放格、相邻值及单位。未决或证据变更时审批和发布不得生效。全部证据完整的受控样本走正式批准、预览与发布。 |
| 启用边界 | 实际生产拟使用轮询或回调时，逐条验证其证据关联。新同包重放和灰度停用复用已经验证的合同。历史缓存、开源复现或供应方口头确认只能作为相应对照。完成真实正反验证后再评审启用。 |

本轮只执行保留回包的离线复核、开源 PDFium 局部复现和公开资料核对。第五阶段仍在进行，当前产品校验和线上配置未改动。
