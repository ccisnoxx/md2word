## 方案确认后的准备与实施

1. 读 Word 生成规则的 IR-002、TABLE-001，以及正式结果与证据认证章节。对照 CON-102 的状态和原子保证。使用第四阶段归档和本任务调查作基线，保留本次无关的既有用例结果。[Word 生成规则](../../../../spec/backend/word-generation-rules.md) · [仓储规则](../../../../spec/backend/database-guidelines.md) · [第四阶段本地验收](../11-15-table-value-pdf-binding-online/validation.md)
2. 先把审批最终重核的竞争在专项用例中复现。关闭窗口时沿用现有文件身份快照及发布锁顺序。重点核对 `table_evidence.py`、`use_cases/review_writer.py` 和三个正式仓储 adapter。通过另一连接或线程调度竞争。不在事务内重做网络或对象 I/O，不改变已绑定的历史批准记录。
3. 在批准的范围内增加默认空的服务端名单。共用 Worker 普通自动绑定和 API 管理员新同包接纳的策略。检查正常转换、各执行入口、同代恢复、名单外、空名单、权限和 UUID 先重读。覆盖与旧开关和冻结意图的停用兼容，记录配置生效方式。此方案不需要新增数据库表或公开 API 字段。
4. 为确实新增的可观察合同补定向测试和规范。候选制品就绪后，在授权的隔离环境准备真实 MySQL 测试、实际 Worker 容器和真实 MinerU 测试账号。审批事务的并发合同接受独立只读复核。记录候选摘要、配置项和验收结果。

- 逐项写明隔离验收结果和环境差异，准备约定的试点公司、实例清单、候选 digest、停止条件和兼容回退目标。验收记录仅使用获准的样本和脱敏身份，保留可授权复查的摘要、请求结果和锁序证据。
- 取得对应授权后先以默认关闭配置进入生产，只读取核对实际 Worker 镜像、工具、配置和已存在的正常交付对照。镜像或关键配置与验收记录有差异时补核影响项。定向启用及扩围按单独授权执行。
- 任何一项关键门禁缺证据，保持关闭。停用演练成功后再批准首轮。正式启用注记记录谁、何时、开关和名单、观察样本、停用时的剩余 UUID 和代次。

## 逐页比对实施与专项目标

1. 在现有 Poppler 读取边界实现有时间和字节上限的逐页比对。复用现有工具及错误语义，验证字符内容、词框、页数页框和平面图像。文档级只比对一次，禁止只以首个可见表页或有无同名原件认定全包一致。
2. 在正式 Worker 入口保留等 SHA 路径。以来源登记和原解析代作为异 SHA 路径的资格；在转换流程保存可复核的比较证据。管理员同包接纳及回放沿用原有冻结确认和 Word 门禁。
3. 在隔离环境用完整保留 P7 原包和其真实上传 PDF 回放，验证实际 Word 的列位置、解除及未决。使用另一版式的 LOW/HIGH 划线夹具验证可核定值及未决对照。加入错页、改值、串批次，并覆盖缺来源凭据和预算。记录真实归档样本与隔离复用原包的边界。

## 表框截断校正实施

1. 在上传 PDF 的页观测中核实外边线和窄条内相邻内容。单测覆盖左右、连接、竞争、共享边、超限、文字和未知图形。
2. 在原框表头失败分支接入，保留原 bbox 并附上可重读的取证框。复用原格行列单位判据和 Word 认证。
3. 在隔离正式 Worker 回放各夹具，核对原始和生效 finding ID、单元格和审批发布状态，记录实际候选与未决边界。
