## 正式 Worker 回放

以仓库 Dockerfile 构建 Linux/amd64 候选 `sha256:3db5107c6aa611ee9ca43f88fbb027b68c7a292c8a218b1d792d2ddd6d83b1c8`，在独立 Colima 内以应用用户 `md2word` 运行，使用隔离的 Uvicorn、Celery、内部 Redis 网络和临时元数据及对象目录。候选的 14 个变更应用文件与工作树逐一比对摘要一致。五项用到的 Poppler 工具均为 25.03.0。以下七个场景全部完成。外部 MinerU 边界用隔离原包登记，线上没有重新提交。真实样本来自第五阶段保留的归档字节，隔离脚本明确注入本次重放的任务、原解析代和上传来源登记，缺该登记另做负例。轮询、回调及实际 PUT 暂存字节的绑定由正式用例另验。

| 场景 | 观察结果 |
| --- | --- |
| 留存真实 P7 | 实际上传 PDF SHA-256 `24f724cf…` 与保留 raw ZIP `5de05d59…`。包内原件 `69e9aaba…`。逐页一致证据进入正式 IR，但 18 个原发现全部转为 `header_ambiguous`，零项自动认证。实际 Word 的 `±5 µV` 仍跨 MIN–TYP，`±100 µV` 位于原有单列 MAX，审批和发布均为 409。 |
| 异指纹嵌字体 LOW/HIGH | 修改包内 PDF 的 EOF 后注释构造等版面不同字节，原件不变。实际 Word 的 `7.2e-4 s` 只在 HIGH，`43 ms` 只在 LOW，2 项自动认证。第三项 `48 ms` 继续未决，双 409。 |
| 等指纹 LOW/HIGH | 保留原样 ZIP，旧登记无逐页身份标志。结果仍由原等指纹路径完成 2 项认证且保留 1 项。 |
| 错页、改值 | 分别用另一页替换包内 PDF、将包内 `43` 改成 `49`。逐页证明均未产生，0 自动认证，原 blocker 及双 409 保持。 |
| 串批次 | 按错误批次登记同一 ZIP。实际 Worker 在 IR 转换前后执行来源完整性核验，任务失败且无 Word 结果。 |
| 缺身份 | 以历史形态登记异指纹 P7。逐页证明未产生，18 项仍为 `source_pair_unverified`，双 409。 |

真实 P7 与第二种版式使用不同 PDF。P7 常规头行在 v2 的归一化表框右缘为 906，换算为 554.472 pt。上传原件的 UNIT 色块右缘为约 555.133 pt，外框右缘为约 555.309 pt。此前同源历史包相同表的 v2 右缘为 908，即 555.696 pt。现有列核定只接纳完整落在表框内的色块或边框，保留新真实包的全部未决符合该门禁。逐页比对只解决来源许可，未修改表框及列判据。
