# C4：降级页展示与翻译适配

父任务：`11-02-partial-success-page-degradation`。C1+C2（验证阶段降级）与 C3（渲染阶段降级）已完成并归档；本任务是第三批最后一个子任务。

## 目标

操作人员不用下载 DOCX 就能知道哪些页被降级、为什么：任务详情和异常中心直接列出降级页。翻译任务正确处理降级页：合成提示不送去翻译，并在翻译记录中说明跳过了哪些页。

## 现状（已核实）

- 降级事实只在 IR（`metadata.degraded_pages`）与结果件的 `source_integrity` 计数中，任务详情与异常中心看不到页码。
- 基础质量贡献 `BaseQualityContribution`（`quality_summary.checks_v1.document_base`）持久在任务记录，详情已公开其安全投影；结构为 `extra="forbid"` 的 v1 模型。
- 异常中心只收录失败、复核 blocked、可重试或卡住的任务；降级后成功的任务（质量 blocked、复核未开始）不出现在队列中。`failure_type` 是 API 枚举，前端有对应文案与筛选。
- 翻译：`extract_translation_items` 按块提取文本，降级页只剩合成提示段落，会被当作原文送去翻译。复核内容要求源 IR 与译文 IR 的可翻译单元按块 ID 完全一致。
- 渲染阶段降级（C3）排除了翻译任务：如果只在译文 IR 上降级，源/译文单元不再一致，复核会报冲突；要一致就得同时降级源 IR，而翻译批次的 `item_ids` 绑定在源 IR 上。

## 范围

1. 质量贡献携带降级页：`build_source_integrity` 输出有界的 `degraded_pages` 摘要（页码、触发阶段、原因码），`base_quality` 写入 `BaseQualityContribution.degraded_pages`，详情随 `quality_summary` 公开。
2. 异常中心：成功但有降级页的任务进入队列，`failure_type="page_degraded"`，不可重试，建议动作与证据摘要列出降级页；诊断抽屉展示同样信息。
3. 前端：任务详情显示降级页提示（页码 + 原因 + 触发阶段）；异常中心新增类型文案与筛选项。
4. 翻译：提取翻译单元时跳过 `metadata.synthetic` 块，提示保持中文；译文 IR 的 `translation` 元数据记录 `skipped_degraded_page_numbers`。
5. OpenAPI 快照与前端类型同步。

## 非目标

- 翻译任务的渲染阶段降级（见待确认 D4）；提示段落多语言模板；降级页人工替换或局部重跑。

## 验收条件

- AC1：验证阶段与渲染阶段降级的任务，详情 `quality_summary.checks_v1.document_base.degraded_pages` 列出页码、触发阶段和原因码；前端详情可见。
- AC2：这些任务出现在异常中心，类型为 `page_degraded`，可按类型筛选，不可重试；未降级的成功任务不进入队列。
- AC3：源 IR 含降级页的翻译任务成功，提示段落未送翻译，`translation.skipped_degraded_page_numbers` 正确，复核内容不冲突。
- AC4：旧任务（无 `degraded_pages` 字段的质量贡献）详情与质量状态不变。
- AC5：OpenAPI 快照、前端类型与前端单测更新并通过。

## 待确认决策

- **D1 降级页数据载体**：写进基础质量贡献（持久在任务记录，详情与异常中心读取都不需要额外 I/O，推荐）；备选为详情接口按需读取结果件 metadata（每次详情多一次文件读取，异常中心列表不可用）。
- **D2 异常中心收录**：降级成功任务进入队列，新类型 `page_degraded`（推荐）；备选为不进队列，只在详情显示。
- **D3 翻译中的提示段落**：跳过翻译，保持中文提示（降级件只能内部下载，推荐）；备选为按目标语言用固定模板生成提示（不走模型，但要维护多语言文案）。
- **D4 翻译任务的渲染阶段降级**：本批不做，保持整体失败，并在规格中记为已知限制（推荐）；备选为同时降级源 IR 与译文 IR，并调整翻译批次对源单元的绑定校验（改动面大，涉及翻译完整性合同）。
