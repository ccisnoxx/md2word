# 调研线上未决格定位与人工核定重生成

复核线上同一结果代可见的位置及产物、人工核定如何绑定当前原格、已有新代与重试的实际语义。范围为仓库内正式链路和本地回归入口。调研日期为 2026-11-15。

## 已确认的读取通道

- `GET /api/v1/document-jobs/{job_id}/quality/tables` 已对白名单表证据分页。接口及用例经任务可见性检查，游标绑定任务、代次、IR、结果文件与报告指纹，结束再次检查同次观测。公开条目含表 ID、源片段、源页与框、引用资源状态、源行到 Word 行的映射以及有效 flags。公开 flag 只有 producer、code、severity、fragment_id，缺逐格 finding ID、源行源格及 PDF 未决原因。内部 `get_table_evidence` 可取通过核验的完整报告。现有 `verify_report` 已重读同次报告、原 IR 与实际 DOCX，并用严格实物认证重建证据，校验当前代和依赖文件描述。可在这次认证过的 IR 上取未决身份，与原 finding 及仍有效的 blocker 对账。见 `app/domains/document_jobs/quality_review_router.py:58–68`、`use_cases/quality_review.py:169–191,303–354`、`quality_review_projection.py:156–188`、`views/quality_review.py:172–196,240–279`、`table_evidence.py:190–259`。
- `/review/blocks` 和相应块详情已有源 PDF 文件 ID、页与坐标空间核验、表格 ID、受控 flag。块详情按快照返回白名单表证据和表参考图，可取得截断且转义的来源 HTML 摘要及原 HTML 指纹。公开块 flags 只给 code、severity、table_id。当前前端提示面板消费块提示、源页和类别，不呈现逐格核定表单。见 `app/domains/document_jobs/quality_review_router.py:142–181`、`review_content.py:411–455,512–550,586–609`、`views/quality_review.py:397–453`、`frontend/src/api/documentJobs.ts:106–111`、`frontend/src/features/job-detail/JobReviewHintsPanel.vue:5–29`。
- 授权操作者可从现有任务文件与下载签发取原 PDF、当前 raw ZIP、IR，受文件类型、所属租户/公司/任务、当前代、上传状态、有效期和删除预留限制。参考图沿用 `/table-references` 和带 generation/IR 身份的受认证内容代理。参考图可缺失，仍可据合规可用的原 PDF 和表框定位。无需把存储路径、原始 metadata 或完整表 HTML 加入普通定位接口。见 `app/domains/document_jobs/use_cases/common.py:24–33`、`use_cases/access.py:140–170`、`use_cases/downloads.py:141–154,213–229`、`downloads_router.py:22–33`、`router.py:593–651`。

## 写入与重生成的真实边界

- `PATCH /review` 接收 status、issue_type、note 和固定的 `expected_source`。`review_writer` 与仓储内 `submit_review` 仍拒绝质量为 blocked 时批准。添加人工核定应保持独立输入语义，审批记录和备注不能充当来源校核。见 `app/domains/document_jobs/schemas/quality_review.py:24–30,108–112`、`use_cases/review_writer.py:56–98`、`review.py:216–238`。
- 普通 `/retry` 只接受可重试的 failed 任务。恢复顺序为已有结果进入 uploading，已有 IR 进入 rendering，有 raw 才从 parsed 重入。线上执行的 `_convert_and_save_document_ir` 遇冻结的 `job.document_ir_file_id` 同样直达 rendering。成功且质量 blocked 不能借 retry 录入核定，通常的重渲染也读不到新的 Grid 输入。recovery replay 对终态仅处理过期回调，不能修复此处。见 `app/domains/document_jobs/use_cases/read_model.py:313–324`、`use_cases/submission.py:175–225,443–452`、`execution.py:288–324`、`recovery.py:166–210,223–245`。
- Admin `POST /new-generation` 已有可复用权限、UUID 幂等、原快照核对、成功/未发布/未归档/未删除/重试预算、文件描述锁定、审计及投递后对账。现有请求只含 request_id、note、expected_source。用例仅允许内部 Admin 用户 JWT，拒绝 Admin/jobs token scope。它重新读取原 PDF 并核对实际长度及 SHA-256，核对原资源版本。仓储在 job 锁、稳定 ID 顺序的源 PDF 和当前结果描述文件锁中做 CAS。现有落地语义清空原 raw ZIP、IR、MinerU 批次与回调指针，回到 uploaded 重新解析。不能把它当成同一 raw ZIP 的重放。见 `app/domains/document_jobs/quality_review_router.py:212–238`、`schemas/quality_review.py:33–56`、`use_cases/publication.py:145–210,232–240,256–292`、`new_generation.py:88–92,144–203`、`app/infrastructure/persistence/mysql/document_jobs.py:268–299`、`app/infrastructure/persistence/file/document_jobs.py:262–283`。
- 第三阶段的 `PdfValueColumnUnresolved` 已有 fragment_id、finding_id、零基源行/源格与 reason。人工的 `TableValueColumnReview` 核对本次实际 PDF 指纹、已选 content list 指纹、JSON Pointer、页、原 HTML 指纹和 normalizer。每格核对原内容指纹、跨度、目标列和标题，原格需仍是当前跨列 blocker。批次验证成功后统一挂接。外部人工数据不得含 `pdf_binding`。已有自动与人工整批关联规则可复用。见 `app/services/document_ir/table_value_column_review.py:80–132,156–229,233–274`、`pdf_value_column_review_flow.py:195–230`、`.trellis/spec/backend/word-generation-rules.md:379–403`。

## 首版建议

1. 复用认证后的 `quality/tables` 白名单投影现有未决项，带表/片段/原 finding 身份、源页和框、零基行格、受控原因及当前代绑定。只投影可与当前原报告及仍有效的对应 blocker 对账的条目，重用既有来源和表格参考入口。已关闭或已核定的格出现在各自的证据关联位置，旧报告的未决证据为空时保持旧合同。列表沿已有分页限制，较大的表格明细用有界结构，不能将截断冒充完整。普通复核提示仅用于定位。由 Admin 结合实际原 PDF 核对目标列后，可用已授权的三件源产物按现行 JSON 模型准备记录。本期无需单元格编辑 UI。
2. 需要完成线上人工闭环时，建议为既有 Admin 新代接纳增加显式的表格核定同包命令类型。无该类型的原命令仍按当前语义重新解析。将当前 `expected_source`、IR/报告标识、原 source PDF、显式的当前 raw ZIP 文件 ID 和实际指纹、受审 finding IDs 以及完整核定批次的 canonical SHA 纳入请求冻结和幂等。以已认证的当前原 Grid 预验整批，原 PDF 和 ZIP 实物锁外核验。拿到已有 job/有序文件锁时重核当前状态、代次、各源描述和结果快照，原子记录仅供内部读取的来源、批次、代次、操作者及审计，沿原 UUID 查询对账。沿用仓储 JSON envelope 即可设计，无新业务表；现有 UUID 请求哈希需保留旧算法，新命令的签名覆盖类型与批次。来源不明或失配、记录含自动字段、过期或任一格已变化时整批拒绝。缺 `_origin.pdf` 或原件不等时保持来源问题阻断，若以后允许另一种可信同源证明，单独明确合同。
3. 同包核定接受后以新代从明确锁定的 ZIP 重新走 parsed → IR → Word。保留原 PDF/ZIP 的不可变化版本与真实来源代，重设新代质量/复核状态，清除新代旧 IR、结果、receipt 及旧回调可影响的准备态，由 worker 再验冻结输入。不能按同任务“最近 ZIP”、文件名或重新提交 MinerU 猜原格。当前 `_get_mineru_raw_result_file` 有未设指针时按最新历史包选的兼容分支，不能用于核定重放。来自原代的 raw 包重放凭代际绑定接纳，不能改写它原有 attempt 元数据。新 DOCX 仍需正式实物认证，表证据只解除精确核定的 blocker；其余未决和其他风险继续触发现有审批、发布门禁。不能以 Admin 接受或新代创建响应替代审阅事实。参见 `app/domains/document_jobs/execution.py:673–683`、`new_generation.py:180–203` 及前述 `TABLE-001` 规范。

若第四阶段只交付未决项定位和保留阻断，原本地 JSON 核定可用于调查或样件回放，当前线上结果仍不能凭本地 Word 放行。是否把 Admin 提交与同包重生成纳入本期是影响权限、持久化和验收的范围决策。建议把它纳入，保留仅 Admin 的最小写入面，并让普通用户从现有读 API 看待核定位置。普通用户编辑表格、直接上传替换已生成 Word、已发布产物原地改写属于独立产品改动。

## 同包新代的接纳、重读与累计人工核定

- 既有 `NewGenerationSubmission`、`NewGenerationLedgerEntry` 与私有 `_generation_requests_v1` 可以保存严格类型化的可选核定动作。原三字段命令无动作时保留原 fingerprint、旧账本解析和进入 `uploaded` 的语义。核定动作区分请求指纹与已接受执行摘要。请求指纹含动作类型、操作者、当前预期来源、归一的新批次及备注，用于按原 UUID 先查账。同 UUID 的重放比较原指纹。执行摘要冻结本次基础报告、文件绑定及服务端合并的累计批次，用于 Worker 复核。接受代、动作身份和审计同事务记录，对账继续用现有 UUID。公开响应只需要既有接受事实和必要动作类型。见 `app/domains/document_jobs/new_generation.py:16,40–92,95–141`、`use_cases/publication.py:145–177,212–254`。
- 锁外通过 `verify_report` 认证同次 Word、IR 和报告，冻结报告 ID/摘要、IR 与 Word 指纹、原发现/既有认证修正关联。另从显式当前指针读原 PDF 和 raw ZIP 的完整字节，核查长度、SHA-256、同源和已选内容。`job` 锁内比较原代、eligible 状态、原资源摘要、`expected_source` 中的结果 ID/SHA、复核来源 revision 和 receipt SHA，以及 PDF、raw、IR 仍为冻结指针。以固定 ID 顺序将锁集从既有 PDF/result 扩到 raw、IR 和报告描述，复核所有依赖的归属、类型、状态、摘要、长度、有效期及删除预留。重新核对结果登记的报告摘要与所读动作基线。对象 I/O 与取证保持锁外，已认证原快照发生变化时整批不接纳。见 `app/domains/document_jobs/table_evidence.py:190–259`、`new_generation.py:154–203`、`app/infrastructure/persistence/mysql/document_jobs.py:268–299`、`app/infrastructure/persistence/file/document_jobs.py:262–283`、`app/infrastructure/persistence/sqlite/document_jobs.py:265–295`。
- 有界累计人工批次与执行摘要随同一次接受落入私有动作账本。现有 HTTP getter 属于 UUID/actor 对账，Worker 可增仅内部的读取，按当前任务、执行代和最新显式接受动作找冻结批次，复核同源、同原包、原资源和摘要。同包新代首次以 `running/parsed` 开始。 由于跳过平常初始化开始/期限的 parsing 入口，接纳或该代首次重入需按既有任务预算记录开始和超时边界。旧回调继续按代次拒绝。失败 retry 本身会递增代次，失败点在 IR 之前时尤其需要认得原已接受 UUID。可沿“最新显式接受动作仍是核定重放且当前源/raw/执行资源完全匹配”的已锁定代际事实确认继续，也可在 retry CAS 中原子复制只含接受 UUID 的当前代身份。后续普通新代必须更新动作身份。不要凭任意旧账本或最新文件恢复批次。接受动作缺失、指纹不符或资源变化时保留原门禁，不能静默丢掉核定继续。Worker 重读冻结 PDF/ZIP，converter 再做批次和原格复核。普通任务响应会返回 `request_snapshot`，完整批次和内部登记留在私有账本。见 `new_generation.py:95–141`、`execution.py:142–185,223–235,262–272`、`execution_support.py:158–175`、`mineru_execution.py:283–290`、`result_state.py:167–175`、`use_cases/submission.py:391–452`、`app/infrastructure/persistence/mysql/document_jobs.py:73–103,170–178`、`http_responses.py:67–80`、`views/jobs.py:159–176`。
- 再次核定先继承当前已认证 Word/IR/报告中的同源人工子集。用 `review_sha256`、`source_cell_id`、`finding_id`、原跨度与目标列在 `value_column_corrections` 中逐格对应，只取 IR 的 `pdf_binding is None` 且认证中无 `pdf_binding_sha256` 的记录。新提交只针对仍有效的未决 blocker。合并后按片段归为一条 `TableValueColumnReview`，批内去重，统一复核当前 PDF、内容表版本、原格与 normalizer，按累积记录重生成和认证。自动项重新观测，同源未获实物认证的提议不继承。见 `app/services/renderer/table_content_evidence.py:183–223`、`app/services/tables/evidence.py:201–211,242–286`、`app/services/document_ir/table_value_column_review.py:233–274`。
