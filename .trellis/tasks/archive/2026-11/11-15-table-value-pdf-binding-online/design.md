# 线上正式转换接入设计

## 1. Worker 核对来源后启用取证

接点为 `app/domains/document_jobs/execution.py::_convert_and_save_document_ir`。该阶段已经取得登记的 MinerU ZIP 并可惰性加载源 PDF。只在新产 IR 的原排版模式按 Worker 配置开启，从同一个 `MinerUToDocumentIRService.convert_zip` 进入第三阶段。保留当前执行阶段和代次条件写入。

1. **核对任务和登记对象**。用当前 job 的源 PDF ID 与明确的 `mineru_raw_result_file_id`。复用实际 PDF 校验 loader 及 clone 同源父链归属核对。读取 ZIP 时核对租户、公司、任务、角色、当前指针、可用状态、有效期、删除预留、登记长度与实际 SHA-256，并对账原解析批次、data ID 与来源。慢读后重核任务/文件描述。原解析代和本次转换代各存其义，当前任务明确保留且血缘完整的旧解析包可重验，历史按时间寻找归档的兼容路径不授予自动资格。
2. **核对包内容**。正式 converter 继续按原策略有界展开、选唯一 v2。选中列表同目录、同文档名的包内原件 SHA 必须等于实际源 PDF。校验唯一同文档 layout、表区域和 Poppler 实测页框。批次绑定说明上传解析的链路，原件实物对账另有门槛。沿用现有 IR 原包/内容清单证据、三键 `mineru_validation_input` 和逐格绑定摘要。
3. **按原因关闭资格**。来源同一性不足、布局或 PDF 观察歧义时，复用同一个候选与未决构建流程，从原发现产出固定原因及源格。已知 PDF 来源不可用只在可选取证处处理，仍为裁图或占位所必需时由原合同处理。正式 ZIP、跨任务归属或实物完整性错误仍阻止登记当前 Word。启用后的历史不完整血缘可继续正常转换，原 blocker 和未决定位仍可读。

原包经过当前 Worker 的存储与任务绑定，包内原件的字节配对仍由现有 matcher 流程作最终资格判定。真实线上供应方的归档内容、原件是否逐字节保留，目前只有待实测项；启用前还需要实际提交 PDF 与真实回包配对验收。若上游不提供可验原件，受影响的原格保持未决。[来源与执行代次](research/source-and-attempt.md)

## 2. Word 实物认证和阻断

线上 renderer 继续使用认证过的 IR 实际写出 Word，在 `quality_checking` 对实际格位、释放的空槽和 OOXML 跨度进行现有认证。认证的表证据中保留原报告、认证修正集合与 PDF 出处指纹。登记时将报告、IR、实际 DOCX、源文件及当前代的选中凭据绑定，同代恢复从这一套产物重读。

- 表格证据的有效 flags 由原 finding 减去已获 Word 证实的对应 ID。未决项及其他 blocker 仍由现有 `base_quality` 写入当前代，结果可为内部草稿。审批和发布分别沿用 `review_quality_blocked`、`publication_quality_blocked`；自动或人工核定均不会产生批准。
- 带坐标的源表会附分栏候选提示。基础质量只把完整认证表报告中有修正证据的、实际渲染的同一源表片段的 `layout_wide_table` 和 `layout_two_column_candidate` 计为已对账的布局诊断。提示仍在产物证据中，其他布局和内容风险照常计算。此边界使只有布局提示的已认证表可以完成基础质量。
- 实际 DOCX 错位、未释放跨度或证据不一致时按现有完整性失败处理，发生在登记当前有效产物前。对本阶段有值列修正的新正式结果，提议在批准分支复用独立表报告的实物重验守卫。发布已重验独立报告。旧结果沿既有证据版本和读取路径。源数据、有效质量和证据校验仍按当前代/当前主件条件提交。
- 渲染整页降级时，随原表组闭包整理最终 IR 中的未决引用，前一份 IR 保留核查线索。保留页的未决项仍有效，降级页仍由整页降级 blocker 控制，解除集合以最终实际 Word 认证为准。

## 3. 人工核定到同包新代

1. 在现有 `quality/tables` 权限、分页及当前代快照内，为仍有效的表格 blocker 投影 `finding_id`、片段、源页、表区域、零基行格及固定原因。由已认证 IR 与表报告中的原 finding 对账。源 PDF、参考图和原格材料沿现有授权访问入口，定位内容用白名单。
2. 建议给现有内部 Admin 的 `/new-generation` 增加显式核定型请求选项。操作者查证源 PDF 后提交标准 `TableValueColumnReview` 批次，配既有 `request_id`、`expected_source` 及审计说明。该选项适用于当前结果仍有可核定跨列阻断、可确认同源、处于既有新代预算内的未发布任务。缺少来源证明、源归属错误或原件不等时保持阻断。
3. 在接纳前验证同一快照的当前报告、主 DOCX、IR、上传 PDF 与 raw ZIP。用当前原 Grid 校验 PDF/v2/HTML/原格指纹、原跨度和目标叶列，外部自动出处字段整体拒绝。服务端保留同源、此前已认证的人工子集，合并当前未决新记录。按同一来源格去重并冻结整批摘要。
4. 字节 I/O 与实物验证在锁外。复用既有 job 及有序文件锁，锁内比对代次、当前主件、IR/报告、源 PDF、raw 指针与冻结描述、资源快照，原子保存新的执行代、核定批次、已固定原解析包及审计。提交摘要覆盖动作类型、新批次和期望快照，用于同 UUID 幂等对账。执行摘要绑定服务端累计核定和验证过的实际来源。重复同一请求返回同一接纳记录，冲突批次或任一无效格整批拒绝。
5. 同包新代从 `parsed` 重入并初始化现有执行时限，重新构建 IR 和新 Word。Worker 通过私有账本读取该代冻结的 raw ZIP 与核定记录，再核验同源，人工已核定的格优先，剩余候选仍按 Poppler 取证。失败续跑仅可在来源与资源快照一致时继承该已接纳意图。普通换代替换旧意图。本次质量、复核与交付按新代重建。已批准或已发布历史的留存沿现有不可变记录合同，迟到旧代不推进当前结果。

普通新代仍从上传后发起新解析，普通失败重试仍可能复用已冻结的 IR。核定型请求使用既有私有 JSON 账本与同一接纳事务，避免第二套审批状态。对有可疑真共享或多义归属的格，人工记录仍须能核定目标列才可接纳。[人工核定的权限、重放与审计](research/manual-review.md)

## 4. 运行与兼容

- 建议用独立、默认关闭的功能配置控制线上接纳。暂不扩大为用户级选项。新可选定位字段及私有核定意图分版本读取，先兼容读者，再启用写者。后续关闭开关可停止新自动取证及核定接纳，已选产物和已保存意图按其冻结版本收尾。
- 复用仓库镜像中的 Poppler 工具链与逐页资源上限。每份文档的可选取证至多 60 秒且不超过任务剩余时限的一半，超预算的候选继续未决。上线前确认实际 Worker 的四工具版本、非 root 临时目录和归档取证覆盖率。日志仅记录受控诊断。
- 第三阶段依赖正确的 PDF 字符映射，几何证据不能校正源字体映射本身。首版继续使用已验证的划线或色块分段几何。平台启用及生产证据另行确认。[运行环境和跨版式基线](research/runtime-and-acceptance.md)
