# File retention automated cleanup execution contract

## Goal

把 Phase 4 的 read-only cleanup runner 推进到可执行但受控的 cleanup run 合同：Admin 必须先对精确 file_ids 做 cleanup preview，拿到 preview hash 后才能 execute；执行内部复用现有 physical-delete safety contract，不引入 scheduler loop，不做 S3 删除。

## Requirements

- Add Admin-only cleanup run preview and execute endpoints under Files retention API.
- Execution must reuse `FileUploadService.preview_retention_physical_delete()` and `execute_retention_physical_delete()`.
- Execution must require:
  - exact `file_ids`.
  - non-empty `reason`.
  - exact cleanup confirmation phrase.
  - preview hash generated by current cleanup preview.
  - bounded file count no greater than existing physical-delete cap.
- Preview must not mutate metadata, delete objects, or write audit.
- Execute must re-run preview, verify preview hash, then call the existing physical-delete execution primitive.
- Execute must write compact audit for the cleanup run.
- Response must include safety metadata:
  - no scheduler loop.
  - no provider calls.
  - no S3 deletion.
  - physical delete only through the existing selected-file safety primitive.
- Idempotency must rely on existing physical-delete outcomes: already missing / already deleted targets must not error.
- Update recovery action registry so `file_retention.automated_cleanup_execute` reflects the manual cleanup run execution contract, while always-on scheduling remains a known gap.
- Add targeted tests and OpenAPI/docs updates.

## Acceptance Criteria

- [x] `POST /api/v1/files/retention/cleanup-runs/preview` is Admin-only, read-only, and returns a stable `preview_hash`.
- [x] `POST /api/v1/files/retention/cleanup-runs/execute` is Admin-only and requires reason, confirmation, exact file IDs, and matching preview hash.
- [x] Execution reuses physical-delete semantics for local/local_object, missing objects, already deleted files, uploaded files, unsupported S3, and per-file outcomes.
- [x] Execution writes compact `file.retention_automated_cleanup_execute` audit and does not write audit for preview.
- [x] Preview hash mismatch is rejected.
- [x] Re-running against already deleted targets is safe and reports non-destructive skip/idempotent outcomes.
- [x] `file_retention.automated_cleanup_execute` recovery action registry entry is available for this manual cleanup run contract and keeps scheduler loop as a known gap.
- [x] Targeted backend tests, OpenAPI check, Trellis validate, and `git diff --check` pass.

## Notes

- Do not run a scheduler loop.
- Do not call real S3 delete.
- Do not run pdf-mineru parsing, provider cancellation, alert delivery, MinerU recovery, real translation providers, or Word generation.
