# 扩大页面降级覆盖面

## 目标

让“少量页面失败时其他页面仍能形成结果”覆盖更多真实失败路径，并消除写入 DOCX 的内部原因码。来自 2026-11-02 重新审查的修复优先级第 1 项，用户已明确授权开始。

## 需求

1. 渲染阶段支持多页降级：降级后再次渲染若因另一页失败，继续降级该页，不再固定只重试一次。
2. 计划阶段失败带定位：LayoutPlan、逻辑表格计划、RenderPlan 失败时写入 `failure_context`；能定位到块的表格计划失败可进入整页降级。
3. 降级提示使用中文原因，机器原因码只保留在 `metadata.degraded_pages` 与质量摘要中。

## 验收标准

- [x] 两个互不关联的页面渲染失败时任务成功，质量 `blocked`、交付 `internal_draft`，两页都被降级，IR 指针指向最后一代。
- [x] 重试次数、50% 阈值、已降级页再失败任一触发时，按当次错误整体失败，诊断指向当次失败页。
- [x] 表格计划阶段的 `TableRenderError` 可定位到页并降级，任务成功。
- [x] 无法定位到页的计划阶段失败显示文档级诊断和 `operation_kind`，错误类型与错误码不变。
- [x] 完整性类错误（`DocumentIntegrityError`）仍不降级。
- [x] 任务超时（`SoftTimeLimitExceeded`）不触发降级。
- [x] DOCX 提示不含内部原因码；所有可降级原因都有中文文案。

## 范围外

已有问题：渲染阶段外层 `except` 把超时归为 `document_job_unexpected_error`，涉及 `prepared_result` 恢复逻辑，单独处理。

页面统计、`degraded_page` 独立渲染操作、Poppler 就绪检查、单页文档策略、翻译任务渲染降级、脏裁图（后续项）。
