# 补齐表格占位失败原因与源页诊断

## 目标与价值

表格占位转换失败时，任务概览、诊断和异常处理页面显示可理解的具体原因；存在可信来源定位时，显示实际失败片段所在的源 PDF 页码，减少依靠日志人工排查。

## 规划时的基线事实

- 2026-11-06 线上只读检查了当前 6 个失败任务：3 个 MinerU 内容块验证失败已经有页码；另 3 个表格占位失败仅有 `table_placeholder_geometry_invalid` 消息，诊断为 null。具体记录见 `research/findings.md`。
- `app/services/document_ir/table_placeholder.py:25` 的异常仅携带稳定错误码；`:153` 的片段处理循环已持有可信 source_span，但失败时未附带定位。
- `app/services/document_ir/mineru_converter.py:361` 把验证报告附到表格占位异常；`app/domains/document_jobs/failure_diagnostic.py:34` 遇到可转换报告直接返回 null，遮蔽后续操作失败的潜在上下文。
- 既有前端已映射四个表格占位错误码；`frontend/src/utils/failureDiagnostic.ts:123` 的技术定位分支只识别渲染操作。可复用当前组件，必要适配限于诊断类型和格式化。

## 要求

- R1：几何区域无效、裁切失败、来源不可用、占位图或来源完整性校验失败，继续使用既有受控错误码；用户看到对应中文原因。不得把任意异常正文当作原因公开。
- R2：对可归属具体来源片段的失败保存实际 source_span 页索引，展示一基源 PDF 页码；跨页表格使用失败片段页，不使用合并后 owner 块首页。第一处失败即停止，不把未执行片段列为失败页。
- R3：文档范围错误（例如全局数量/累计资源预算、源文件整体身份校验）与无法定位的错误不伪造页码。旧事件缺少有效诊断时维持既有回退。
- R4：同一失败事件包含通过的 MinerU 报告时，仍能消费真实表格占位失败上下文。保留既有有效 MinerU 致命报告、渲染诊断和 retry_count 隔离语义。
- R5：任务详情与异常诊断 API 返回相同原因与位置；概览、诊断页签、异常抽屉复用共享展示。列表不增加逐条事件查询。
- R6：事件仅保存允许的原因码、操作类型、块 ID、页索引及可靠页数依据。不公开 PDF 正文、文件路径、URL、凭据、原始 HTML/bbox 或任意异常消息。
- R7：保持任务失败分类、原异常类型、重试、取消、降级、质量及发布策略。只补诊断，不借此修复坐标或改变转换结果。

## 验收条件

- AC1（R1、R2、R5）：通过真实 converter→eager Worker→持久化事件→详情/异常 API 链路构造“验证通过、表格占位几何失败”的合成输入，断言 failed / ir_converting / document_ir_failed、中文原因对应码、正确源页；三个页面的共享摘要能展示该合同。
- AC2（R2）：源索引 0 显示第 1 页；跨页表格后续片段失败时显示该片段源页，而非 owner 首页。
- AC3（R1、R3）：四类受控错误码保留；无页码/文档范围失败显示文档级提示，历史无证据记录继续显示未记录失败页码。
- AC4（R4）：可转换报告加真实操作上下文能出诊断；有效 MinerU 致命报告保持原结果；旧代上下文不泄漏到当前代；不更改现有事件选择合同。
- AC5（R5、R6）：事件 JSON 往返后证据一致；注入未知字段、危险 ID/页索引和私密字符串不会进入诊断；已有渲染诊断与安全消息回归通过。
- AC6（R7）：正常表格占位路径及直接受影响的降级用例保持原行为。API 类型/OpenAPI 快照、前端类型和相关文案测试同步。

## 范围外与证据边界

不回填历史失败事件、不自动重试线上任务、不修复转换几何算法、不新增诊断平台/依赖/数据库表，不提交、推送或部署。本轮使用脱敏合成夹具和本地定向验证；这不构成生产新任务验收。上线后新发生或经另行授权重试的任务才能产生新上下文，旧记录不能凭现有非致命告警推算失败页。
