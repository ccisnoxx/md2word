# B08 后续实施与最小验证计划

## 0. 本轮与后续授权边界

本轮只完成三件套及文档校验，不执行下面的产品实现、隔离数据库或生产步骤。任务保持 `planning`，表示迁移实现尚未开始；文档交付状态单独记录于 `validation.md`。用户已允许创建本任务，不需要重复申请文档写入授权。

后续只有 D-1/D-2 决定与代码实施范围获批后才进入实现。生产只读核查、停写、迁移写入、权限变更、部署、DROP 与恢复分别取得授权；批准设计不替代这些授权。禁止用 `APP_ENV=dev`、数据库名字或 fake 测试结果推定生产操作许可。

以下均为**未来实施时新增的夹具/测试要求，尚未创建或运行**。使用合成 payload，不复制生产数据。所有拒绝路径同时断言无越界 DDL/DML；不要只断言返回错误。

| F5 账本引导中断 | 正确空账本；另含同名异形账本 | 前者完整重检后可登记；后者拒绝，不能覆盖 |
| F6 版本异常 | checksum 不同、未知新版本、太旧、断链、错误 ledger_format | API/Worker 拒绝，不自动升级或降级后端 |
| F7 步骤前中断 | running 意图已提交但 DDL 未发 | 获锁识别 interrupted；显式 resume 重跑该步一次 |

| F13 删除拒绝 | 任一目标非空、未知消费者、未排空、缺备份/授权、发现外键/视图依赖 | 不发任何 DROP；恢复每个剩余步骤重新验证 |

## 3. 授权隔离 MySQL 的最小实跑

只在 S5 得到明确授权后运行。借鉴项目已有隔离模式（不读 `.env`、不复用业务库），采用显式测试连接参数、专用账号与一次性独立库；环境清理只针对本次创建且已识别的对象。若需要拉取镜像，先核实目标 daemon/builder 的实际镜像源和代理，正常拉取固定官方引用；不得未经诊断换源。

建议新增 `tests/test_mysql_schema_migrations.py` 与 `tests/test_mysql_schema_migrations_integration.py`（拟新增路径，当前不存在），按上表分别承载离线合同与真实引擎合同。后续最小命令形状如下，测试模块实现后才能执行；不把这些预定命令列作本轮通过：


真实引擎至少执行六组：

1. legacy_present adopt → B08_002 → 再跑一次，比较业务摘要且第二次没有 DDL；legacy_absent adopt 同样确认无操作收缩。
2. 空库 fresh → B08_002，重复启动 API/Worker 检查只读；半建 fresh 使用自己的 running 记录恢复，无账本半建库拒绝；fresh 正常新增表不违反恢复条件，但出现业务数据即拒绝续跑。
3. 两独立进程同时申请迁移，第二个拿不到锁且不写；第一连接中断后服务器释放锁，另一执行者才能接管。
4. 分别在意图提交后、第一张表已删除后、第二张表 DDL 已完成但账本未提交、最终 applied 提交前终止执行进程，验证状态可识别和恢复不重放已完成 DDL。终止的只能是专属测试进程/连接，不对业务进程做故障注入。
5. 真实 MySQL 上模拟 DDL 报错、元数据锁阻塞及连接断开，证明保持失败可见、无自动重连、不会继续下一步；超时后重新核对物理状态，不能推断 DDL 未执行。
6. 从备份恢复到另一隔离库，核对两保护表及其他正式对象/账本；执行 A1 的兼容检查。应用回退只测试 A1 支持集合，绝不拿 A0 的自动维护作为恢复手段。

记录实际服务端/驱动版本、源码与迁移 checksum、环境隔离证明、运行标识、故障注入点和前后摘要。skip、连接失败或 fake 成功一律不算真实引擎通过。成功结果只在相关源码/依赖/配置/夹具不变时复用，不因提交、worktree 或收尾重复执行。
