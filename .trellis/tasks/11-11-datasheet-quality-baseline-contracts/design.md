# Datasheet 质量基线、表格与状态合同设计

## 1. 样本和证据

复用 [P0 回归脚本](../../../scripts/ops/run_golden_sample_regression.py)、[本地质量矩阵](../../../scripts/dev/run_local_mineru_quality_matrix.py)及其人工验收模板。在 Golden Sample 体系中增加版本化扩展清单及独立样本目录，分别报告原有 OPA228 和扩展集。当前 P0 脚本的 `pass_rate` 以可运行样本为分母，历史报告继续按原字段解释。新报告以固定计划为分母，缺件和缺测显式呈现。扩展集先建立基线，升为正式发布门禁由独立决策完成。

每个样本记录稳定 ID、源数据手册与版本、选页、原件和派生件 SHA-256、可用范围与存放引用、风险标签、预期转换模式及独立标注版本。按标签选择有不同结构特征的两个非 OPA228 产品，至少保留一个完整跨页表所需的连续页面。只有明确允许入库的资料才提交原件或切页。受限资料保留在授权存放位置，仓库保存可验证的引用和必要的最小夹具。

预期标注从源 PDF 或已签字的版式规范独立建立。表格标注含逻辑表 ID、源页与片段、行列、合并矩形、表头层级和重复表头预期。技术 Token 标注含类型、预期字面或允许的等价呈现、所属段落或逻辑表单元格，以及每次出现的位置。页面标注含可比较区域、源页和配对规则。阻断样本固定预期的原因码、目标范围和交付结果。

运行记录固定计划、清单与标注版本、输入和 DOCX 指纹、代码提交、运行时、模板版本、渲染器、字体集和 DPI。实链路另记解析或翻译服务标识、适用计价版本和重试次数。每个结果按本地组件、隔离真链路、人工签字等实际证据分别记载。组件夹具、真 PDF 和人工结论分别追溯到各自输入与产物。证据使用现有安全存储策略，报告中的原文和内部引用限制在授权范围内。

## 2. 指标合同

同一次运行以 `sample_id × mode` 形成计划项，每项只有一个统计结果，所有重试归该计划项。先记录原始结果，再按同证据层级、转换模式与样本组聚合。比率用总分子除以总分母，附样本数和覆盖，分母为零标记 `not_applicable`。预期但无法观察标记 `not_measured` 并附原因。人工采集表单、算分脚本和输出报告共用同一口径版本。旧脚本的 `elapsed_seconds` 包含上传和产物检查，继续作为历史全程耗时。新增转换延迟单独记录提交和可下载时点，若只能通过轮询观察，随结果记录轮询间隔。

| 指标 | 测量单位及算法 | 失败和缺测 |
| --- | --- | --- |
| 转换成功率 | 正常计划项中，任务成功且主 DOCX 实际可下载、可打开的项数 ÷ 正常计划项数。 | 超时、缺输入、未执行、下载失败、主件无效各列原因，均无法进入分子。预期质量阻断的负例单独报告断言结果。 |
| 原生表格结构准确率 | 可编辑 Word 逻辑表中，行列数、合并坐标、表头层级与标注均匹配的表数 ÷ 计划项的预期原生表数。每张表一次匹配，另列意外多表、重复片段和不匹配原因。 | 已生成文档中漏表、图片替代、错误分表或合并均判未匹配。无可观测 DOCX 的预期表保留在分母，单列未评估数。 |
| 技术 Token 保留率 | 在标注指定段落或单元格中一对一匹配的 Token 出现次数 ÷ 计划项的标注次数。按数字、单位、公式、型号等类别拆分，另报多余、重复与错位。 | 重复值按出现次数匹配。允许的等价呈现由版本化标注明示。无可观测 DOCX 的预期出现次数保留在分母，单列未评估数。 |
| 页面视觉偏差 | 固定渲染环境，将同一标注区域的两组边界坐标按各页宽高归一化。每区域计算左、上、右、下四条边的绝对偏移均值。汇总均值与 P95，同时报告匹配页和匹配区域覆盖、溢出或裁切项。 | 以版本化的区域配对为准。无法可靠配对、合法重排跨页或缺少预览时附原因，不以页码猜配。翻译版用同模式批准版式基准，缺基准的页面标记缺测。 |
| 人工修改次数 | 首次产出至签字，按该文档及产物版本下已实际修正的独立缺陷计数。重复编辑同一缺陷只计一次。 | 原始记录保留缺陷 ID、类型、位置、轮次和处置。仅提出问题的条目不计为已修改。已完整记录的零修改与未记录分别表达。 |
| 人工验收耗时 | 同一份文档各审核轮次有效审核区间合计，以分钟记录，附参与者与轮次。暂停和等待另记。 | 缺起止时间或缺轮次时标记缺测。人工核对与实际编辑耗时分别采集，审核耗时只汇总审核活动。 |
| 单文档成本和延迟 | 成本首版取可归因的解析与翻译服务费用，含失败尝试和重试。记录币种、账单或估算依据。延迟从首次提交至合法主 DOCX 可下载，含排队与重试，另记失败用时。 | 缺账单或计价版本明确为缺测，部分可归因费用仅报分项。本地模拟耗时独立分组。对已测成本和成功延迟计算 P50/P95，采用最近秩法并附样本量，失败和超时单列。 |

父任务规定技术 Token 完整率 100%，既有 P0 成功率目标来自 P0 清单。其余数值先形成可复现基线和风险样本分布，再提出阈值。质量门禁仍由既有质量及发布合同裁决，度量报告作为验收证据。

## 3. Canonical Table Grid

- [网格合同](../../../app/services/tables/models.py)与[占位构建器](../../../app/services/tables/grid_builder.py)是 `canonical-table/v1` 的现有所有者。统一表意以零基行列、锚定单元格、横纵跨度、表头和来源片段为核心。共享占位、冲突及缺口诊断。
- 源校验从已验证的逻辑表分组构建网格。Word 规划从本次实际渲染的 HTML 取得投影，两者已有不同的身份域和文本来源。保留源账本、翻译内容和 OOXML 证据各自身份，用来源片段和稳定坐标对账。转换兼容的格式处理可保留，影响单元格归属或结构的偏差由结构证据判定。
- 跨页表沿用已验证的续表关系和重复表头提示。检查逻辑表头与 DOCX 的分页重复表头各自语义。合并范围越界、占位冲突、续表证据缺失或空表片段走现有诊断和降级路径。降级产物、原生表格和阻断质量分别记录。
- 每张表按同一逻辑表 ID 和来源片段对照三份结构证据。源 Grid 记录单元格锚点、占位跨度和逻辑表头。渲染投影记录保留及移除的续表行、输出位置和预期重复表头。Word 实物核对 `w:tblGrid`、`w:gridSpan`、`w:vMerge` 与 `w:tblHeader`。其中 `w:tblHeader` 描述分页重复行，续表去重需有独立来源证据。对不上时记录最早出现差异的环节，保留分母与诊断。
- 本阶段用独立标注和同源工件核对上述投影及技术内容归属。已证实差异集中登记，后续按共享规则选择复现夹具和跨样本回归。[问题清单](issues.md)

### 续表结构验收的四种输入

| 输入 | 源账本与 Grid | 渲染投影和 Word |
| --- | --- | --- |
| 两段完整且续表证据一致 | 一个逻辑表，按页保留两个 `present` 片段、各自占位和显式续表关系。 | 布局兼容时合成一张原生表。仅在现有重复表头证据成立时移除续段的重复行，按来源保留全部数据行。 |
| 上游已合并且有可核验证据 | 主片记录合并结果，后续源位置与已覆盖行有可核验绑定。同一批数据只计一次。 | 主表只写入一次，已覆盖的次页片段保留来源定位。用证据核对重复输出、占位和阻断。 |
| 确实缺片段或归属无法证明 | 缺失或空 HTML 保留来源身份、位置和质量诊断。 | 保留现有可追溯占位与表格质量阻断。源位置可在草稿中核对。 |
| 相邻但独立的表 | 分属不同逻辑表，分别保留网格和来源。 | 分别输出原生表，不合并行或移除其中任一表的表头。 |

首批修复复合表号归组。只接受两段各自有明确题注且完整数字复合编号一致、后段带明确续表标记且题注正文相容的证据，沿用页邻接、正文边界、几何、列数和表头签名检查。完整编号不同、题注冲突或证据不足时保守处理。Word 题注的字段与交叉引用规则继续由现有合同决定。已签发的历史分组在重读时按已记录关系校验，原始观测单独保留。

#### 上游预合并的来源绑定

- 输入为同一 MinerU 包的 v2 内容列表和唯一同文档版面。已有归一化收据关联相邻的主片与严格空片。前后处理表格和表体节点在同页索引、节点索引和几何位置对应，前处理保留两段完整 HTML，后处理保留主片且明确标记次片表体 `lines_deleted=true`。两段前处理题注须同号、正文相容且后段明确标为续表。次页表注也须在主片后处理版面和 v2 中保留。
- 主表前缀须与首段完整行一致，余下连续尾部须与次段去掉共享表头后的完整数据相符。总行数唯一确定共享前缀长度。存在共享前缀时，用显式连续 `<th>` 或经 PDF 和内容指纹校核的现有 `TableHeaderReview` 确认表头语义，并逐格核对两段前缀。次段至少保留一行数据。v1 仅接受可逐行核对的等宽网格及匹配的横向跨度。单独的 LaTeX 下标 Token 可忽略外层数学定界符，符号与下标逐字核对。纵向合并、归属歧义或证据缺失均走既有空片段占位与阻断。
- 来源 IR 在空片段记录 `upstream_coverage`，绑定包、内容列表、版面、前后处理定位、主片与空片的身份和行摘要。覆盖区间 `[row_start, row_end)` 是主片内零基行。Grid 保留两处来源位置，行数只来自主片。渲染投影通过 `upstream_covered_rows` 记录同一原生 Word 表内的实际区间，空片新增输出行仍为零。
- 已绑定空片免除本次空表诊断与非编辑占位。重读时用 IR 中的主片重算规范化行摘要，和片段身份、包身份及已记录区间对账。版面原始节点可用同指纹包回查。历史无绑定证据时继续按原记录处理。现有表头证据独立决定 `w:tblHeader`。

## 4. 质量、审核、发布和交付合同

遵循 [Document Jobs API](../../../docs/api/document-jobs.md)及当前 [质量聚合](../../../app/domains/document_jobs/quality_state.py)、[审核记录](../../../app/domains/document_jobs/review.py)、[发布提交](../../../app/domains/document_jobs/publication.py)和[状态更新](../../../app/domains/document_jobs/delivery_state.py)的写入边界。

| 对象 | 写入所有者与不变量 |
| --- | --- |
| 执行结果 | 执行链路按任务与代次确认主件。`succeeded` 表示执行成功，可以同时有 `blocked` 质量结论。内部下载继续按主件有效性、权限及下载分类判断。 |
| 质量 `pending/passed/warning/blocked` | 各质量生产者写入归属贡献，由服务端按 `blocked > pending > warning > passed` 聚合。发布前可随当前证据更新，晚到的旧代次证据不得更改现役结果。发布时固化实际采用的质量快照。 |
| 审核 `unreviewed/approved/needs_fix/blocked` | 审核端口在单任务串行化边界追加记录及更新当前引用。批准绑定任务代次、主件身份、校验回执及审核时质量快照。历史未绑定值只作历史证据，结果换件、重试或关键绑定失效时重算有效审核，已提交的审核记录保留。 |
| 发布操作 | 由现有 Admin 发布入口和原子提交端口负责。新发布需任务完成、发布写入开启、有效批准、`passed/warning`、已确认的预览和全部绑定证据可用。提交重新核验当前身份和期望来源。原子创建发布记录、提交成功审计及文件保护并更新指针。相同请求及载荷重放返回原记录，同一请求 ID 更换载荷则冲突。新提交发现证据已变时拒绝。 |
| 交付 `internal_draft/ready_to_publish/published` | `ready_to_publish` 是可变的资格投影，列表使用轻量条件，详情和发布提交负责完整核验。`published` 绑定正式发布记录及固定产物。发布后允许按合同更新归档元数据，交付内容、审核质量快照及文件身份保持固定。新版本使用现有 clone/rerun 路径。 |

发布记录包含任务与代次、源和主件文件身份及哈希、审核序号、质量、预览、配置、受保护文件、操作者和时间。交付下载核对该快照对应的文件，证据变化时返回合同约定的失败。并发提交的验收断言必须覆盖记录、当前指针和保护文件的一致性。

## 5. 兼容与恢复

保留公开状态枚举、历史审核读法、现有列表与详情动作差异、公开 API 和发布写入默认行为。现有 TAB-301～308、QA-601～607、REL-701～704 用于定位所有者和验收证据，清单状态按独立任务治理。无相应证据时，当前子任务只标记具体缺口。样本和报告按版本追加，旧结果可按原版本复算。若局部实现回退，保持已有发布记录和文件不变，使用原代码、清单和模板快照对照恢复。
