# 原生 Word TOC 的公式保真

## 来源与边界

基线提交 `8355179e` 的整份 SN74AC244 回放登记了 118 处公式，只写入 116 处。第 2 页目录列表的第 10、11 项含数学表达式，原生 TOC 策略替换了这两项的输出。正文 5.5、5.6 节各有一个同电压值的标题公式，源字符串和 OMML 投影指纹与目录公式不同，无法作为原目录公式的等价证据。

Word 的复杂字段区分字段指令、结果区和结束标记。更新整个目录会重新生成目录项。[OOXML 字段字符](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.fieldchar?view=openxml-3.0.1) · [Word 更新整个目录](https://support.microsoft.com/en-us/word/update-fields)

## 最小客户端实验

使用 LibreOffice 26.2.4.2 的独立 profile。每个合成 DOCX 恰含一个可更新的 TOC、一个真实 Heading 和一个带来源书签的 OMML 公式。调用索引对象的 `update()`，保存到新文件并核对实际 OOXML。[LibreOffice 索引更新接口](https://api.libreoffice.org/docs/idl/ref/interfacecom_1_1sun_1_1star_1_1text_1_1XDocumentIndex.html)

| 公式位置 | 完整刷新后的观察 |
| --- | --- |
| TOC 字段缓存内 | 目录条目重建，公式和书签消失。 |
| 同一段落，字段结束标记之后 | 该段落剩余部分被客户端纳入索引锚点，公式和书签消失。 |
| 独立正文段落 | 目录条目重建，原生公式和书签都保留。 |
| 真实 Heading 段落 | 标题里的公式和书签保留。刷新的目录条目只带标题文字，未出现该公式。 |

## 实现与验收

只处理已经识别为 TOC 且含数学 span 的源条目。保留一个原生 TOC 字段。含公式的原目录标题保留在独立正文段落，去掉旧页码和点引导符，公式继续通过现有 writer 写入并绑定原始来源字段、偏移和 SHA-256。普通目录项共享原生 TOC 目标。首条含公式时，字段与该条原目录标题各占一个物理段，普通目录项的代表必须指向字段段。

新行为在受影响的渲染计划中显式标记，并复用原有持久化内容认证及源公式库存。历史版本按原计划和原对象读取。整份真实样本需同时验证 Word 产物可打开、原生字段只有一个、两处目录原式在完整刷新后仍由书签定位，以及原件第 12 页的缺表质量阻断。

## 表头输入核对

三张已标注表的原 PDF 均为未标记 PDF，MinerU v2 的表格 HTML 均使用 `<td>`，相应的 layout 表节点也没有单元格表头字段。手工按原 PDF 核对的表头分别是第 1、1、1–2 行。正式 Grid 和 Word writer 继续消费显式的单元格语义。

在输入指纹核验后的临时副本中，只把这些已人工核对行的单元格标记从 `<td>` 改为 `<th>`。真实正式回放中，三张的 Grid、OOXML 行列、跨度和表头均与标注匹配，8 个标注 Token 保留。该对照验证现有结构链路可消费可靠表头标注，首轮原始输入的 0/3 度量仍有效。

在同一份 OPA228 对照中，仅用 `<thead>` 包住现有的 `<td>` 行，当前 `table-html/v1` 仍保留普通单元格语义。若扩展该输入合同，需要另行版本化或验证历史已签发的网格和渲染证据可重放。后续以来源能核实的 `<th>` 或等价的明确表头标注为准入条件。对当前三份源输入，表头需要上游补充或人工校核。

## 整份样本结果

2026-11-11，正式本地适配器从原样本的 38 个源页生成可打开的 DOCX。实际 OOXML 有 1 个原生 TOC 和 19 张原生表格。118 个源公式全部写入。目录原式绑定 `block_0027/list_items/9` 和 `block_0027/list_items/10`，分别由 `md2w_formula_000006`、`md2w_formula_000007` 定位。原件第 12 页的 `/11/0` 仍由源 PDF 裁图生成占位，保留 `table_noneditable_placeholder` 和表格质量 `blocked`。

已完成同一产物的 LibreOffice 完整刷新与仅保存对照。完整刷新有且只有一个索引，`更新目录` 占位文字由生成结果替换。两个公式书签、数学文字及下标结构均保留。仅保存和完整刷新的两条书签范围一致，两个输出都移除了外层 OMML `m:box`。原始生成件继续保留该包装及原渲染证据。客户端保存后的副本是用于验证的独立产物。

原始 DOCX 的 SHA-256 为 `8c8ae38289248d531b26f12658e524470c8655ecf4aae71d3696e0b32640d6dc`。本地文件及机器核对记录位于 `tests/tmp/datasheet-toc-verified-20261111/`。

7 项 TOC、页映射和公式定向用例通过。独立复核另通过 5 项历史预览及转换测试，并用 `8355179e` 的实物验证旧 v1/v2 计划哈希、原 DOCX 和持久化证据兼容。旧目录字段的通用块书签仍位于字段中。对新策略中跨块归并到独立字段的目录项，预览使用该真实字段路径估页，置信度为低。
