# 实施与验证

1. 在新建任务用例中计算显式 direct 文种的请求语言，在请求快照构建器复用现有写入点。
2. 扩展 `tests.test_document_job_modes`，覆盖两种快照上的 `zh/en/ru/auto` 和配置变更。复验四翻译方向、历史回退、继承克隆、术语重绑和 direct 零翻译。
3. 在隔离运行时通过正式创建入口提交中英文公开 PDF 各一份，观察持久化快照、HTTP 请求语言、批次、最终任务事件和翻译批次。通过正式结果读取取得 DOCX。
4. 在 WPS 对每份 DOCX 修改一处原文正文与一处原文表格单元格，保存副本，关闭并重新打开验证。
5. 更新任务模式规范、记录证据并检查差异。验证发生阻塞时保留样本及既有批次，避免重复提交已受理样本。
