# 分阶段整改设计

## 1. 决策基线与本轮边界

本设计依赖 `research/audit-matrix.md` 的 A01–A29。初始交付仅核实与计划；当前 B03 已按后续独立授权完成本地定向验收，详见 [进度记录](progress.md)，其余批次未由本轮启动。保持内部单租户、技术 PDF、模块化单体，保留 DocumentIR 与完整性/渲染/状态证据体系。未来批次按独立授权和任务验收推进，不把路线图批准解释为全部实施或生产变更授权。

现有 Spec 优先：Word 正式 owner、翻译完整性、批次生命周期、数据库与任务模式合同。CI、全量测试、发布聚合脚本不属于本计划默认执行方式；本文的未来最小检查均尚未执行。

## 2. 当前所有权与必须保持的合同

| 责任 | 当前 owner | 重构边界 |
|---|---|---|
| 外部包字节、路径与限额 | `app/services/document_ir/mineru_package.py` | 转换阶段复用，不复制或绕过。 |
| 源数据转 IR、v1/v2 与溯源 | `app/services/document_ir/` | 结构/顺序/资产/来源事实不由翻译修改；保留 v1 回退。 |
| 翻译检测/占位与结果验真 | `protected_tokens.py` / `integrity.py` / `document_ir_translator.py` | Codec、Validator、请求准备各自唯一；未通过不可回填，direct 不加载 Provider/Prompt。 |
| 同 job 状态、attempt/lease、receipt | `document_jobs` 领域规则与 file/sqlite/MySQL adapter | 原子检查在原 repository 序列化边界；不能退化成服务层读后写。 |
| 阶段编排与 Artifact 登记 | `DocumentJobExecutionService` / `DocumentFileService` | 先缩小纯决策职责，I/O 和状态提交暂留原 owner；不新建服务定位器。 |
| 排版、内容证据与共享规则 | `app/services/renderer/` + `app/conversion/docx_rules/` + HTML parser | 不把共享 conversion 规则误删为 legacy，不新增平行 writer。 |
| 质量、下载、复核与发布 | `base_quality.py` / `quality_state.py` / `document_jobs/service.py` 等既有 owner | 执行完成、质量 blocked、交付 internal_draft 是不同维度；不可把可下载当作可发布。 |
| 前端路由与授权投影 | router / appShell / auth store，后端仍裁决动作 | 组件拆分不得另算发布资格、权限或换代状态。 |

现有调用结构：正式 HTTP → document_jobs → MinerU/IR → 可选翻译 → Renderer → 质量/结果登记。旧 /jobs 已不在当前主 API router 中挂载；legacy conversion/stage_service 仍装配且有独立 Worker 入口。删除旧链路须先盘点残余消费者及共享依赖。

## 3. 优先级与执行顺序

- **P0**：已证实且需要立即处理的数据破坏、权限突破或核心交付阻断。本轮未取得足够新增 P0 证据；这不是系统无 P0 的认证。
- **P1**：已明确的边界不一致或可复现性风险，应在扩展功能/大拆分前处理。
- **P2**：可维护性、产品质量、已观察增长成本的局部改善。
- **P3 / 条件专项**：依赖产品决定、部署规模或外部发布意图；触发后按实际影响重新分级。

| 阶段 | 批次与优先级 | 前置与顺序 | 阶段退出条件 |
|---|---|---|---|
| S0 当前规划 | A01–A29 核实、任务去重 | 当前基线 | 三件套、证据、上下文与文档检查齐全；保持 planning。 |
| S1 边界与基线 | B03 P1；B02 P1；B01 P2 | B03/B02 不依赖大重构；B01 可独立 | 下载边界有定向证据；依赖可复现范围明确；状态文字和产物清单准确。 |
| S2 职责收敛 | B04 P2；B05 P2 | 基于 S1 稳定基线；B05 依赖自身调用盘点，不要求先完成 B04 | 一个职责提取试点验收；已选旧消费者迁移完成，未迁移项明确保留。 |
| S3 质量与前端 | B06 P2；B07 P2 | B06 衔接 TR-404/TAB-301 合同，不以整个 S2 为硬前置；B07 可独立 | 选定表格样本与页面的可观察合同满足。 |
| S4 条件专项 | B08 P2 条件；B09/B10 P2 条件；B11 P3 | 触发条件成立并单独确认 | 各专项证据闭环；不阻塞未受其影响的日常交付。 |

排期按风险而非“所有小事先做”：B03 先于执行器大拆分；B02 先于依赖升级；B01 不阻塞必要边界修复。阶段仅描述默认路线，不要求串行等待所有无关事项。

## 4. 批次范围与验收

### B01 文档事实与可删除产物清单（P2，A14/A21/A22）

- 范围：修正 Token 模块过时状态；核对 gap/架构/目录文档中的当前与历史含义；列出两个已跟踪 test-results 文件的用途、引用和保留需求。
- 非目标：批量翻译注释、清空 IDE/Skills/Trellis、删除共享 .run、全量归档历史文档、替用户选许可证。
- 验收：D1，当前文档不再把已接入 Codec 标为未实现；D2，旧 /jobs 状态与 router 一致；D3，每个待移出跟踪的产物有精确路径和用途说明，维护配置无误删；D4，旧基线可追溯、链接有效。
- 最小验证：文字检索、链接/行号检查、Git 精确路径差异；纯文案不运行应用测试。
- 回退：恢复本批次文档或跟踪变更，保持用户工作区文件；不改历史提交。

### B02 依赖解析与镜像来源基线（P1，A09/A16）

- 范围：确认受支持 Python/平台及可信安装来源，为直接/传递依赖建立精确版本与来源记录，覆盖 python-docx；Docker 基础镜像和 MySQL/Redis 引用固定到验证过的版本/摘要；说明 Poppler/apt 的剩余漂移。
- 先决条件：已有 requirements/package-lock 为输入，先确定可复用的工作环境证据。本机 venv 不是默认生产真源，不盲目 freeze 未识别环境。选工具前检查既有模式与官方兼容信息；本轮不指定 uv/Poetry/pip-tools、不要求新 pyproject。
- 验收：L1，相同目标环境的两次受控解析/安装得出相同完整版本集合并可核对来源/hash，第二次仅为验证可复现性；L2，不做隐含依赖升级，必要版本变动单列；L3，API/Worker 采用同一锁与镜像身份；L4，既有选定 DOCX 样本的正文、表格合并、公式、锚点/证据关系无非预期变化；L5，明确这里只保证了哪些层次，未锁 apt/构建时间戳时不宣称镜像逐字节复现。
- 最小验证：获批后在隔离环境安装与 pip check，复用相关输入未变的成功证据；只选择受依赖变化影响的既有 OOXML/renderer 测试。比较规范化 XML 结构和关系，不以原始 ZIP/hash 完全相同作为 DOCX 内容等价。
- 操作边界：实际拉镜像前查目标 daemon 的 active mirrors/proxy；保留原镜像版本、走正常 pull，不用 curl 超时替代拉取证据。本轮无 Docker 或生产操作。
- 回退：保留上一组 requirements/锁/镜像引用；不同时做功能重构。

### B03 MinerU 下载边界一致性（P1，A05）

- 当前状态：已完成获批本地实现与 AC01–AC10 定向验收，未提交/推送/部署；复用 10 + 1 + 4 个不同测试方法的既有结果。见 [逐项证据对账](../11-06-mineru-download-boundary/acceptance-reconciliation.md)。原 U1–U5 保留；U4 的换代/CAS 只确认相关代码未改，没有新增并发运行验证。
- 已选方案：允许名单内重定向，每次实际发送前校验并拒绝 URL userinfo；真实 CDN 跳转兼容不在此次离线验收结论内。

- 触发/影响：上游轮询响应提供非允许目的地址时，正式路径绕过回调已有策略；被允许初始 URL 的跳转也未在下载器中体现目的地址策略。现有内部类型并不保证第三方返回的 URL 合法。
- 范围：把结果 URL 策略落实到所有真实下载调用都经过的边界，覆盖回调、轮询和保留的 legacy 调用；重用已有 HTTPS/host 规则。调查真实供应商是否依赖跳转后，选择拒绝跳转或逐跳校验，不默认放行。
- 非目标：声称已复现 SSRF、泛化全站网络沙箱、重写 ZIP 解压、顺带迁移 AI Provider 配置。
- 验收：U1，非法 scheme/host 在发起外部请求前失败；U2，所有入口对同一 URL 得到一致结果；U3，不允许先请求非白名单跳转目的地再检查最终 URL；U4，合法结果下载、错误码/安全摘要、取消/换代后的不落主结果行为保留；U5，回调 checksum 不受削弱。
- 最小验证：伪传输/受控本地响应验证请求序列及拒绝前零请求，合法/非法 host、子域边界、跨域跳转、轮询与回调入口定向用例；不发内网探针、不连接真实供应商。未来候选涉及安全合同，需独立只读复核。
- 回退：若兼容问题不能安全解决，停止相关处理并保留失败诊断，不恢复绕过校验；真实跳转兼容证据单列。

### B04 执行器职责提取试点（P2，A11/A13）

- 范围：先记录阶段→输入快照→副作用→CAS/receipt→失败收口关系；建议首个试点为失败分类/安全证据构造，不移动数据库提交。候选集中于 execution.py 的 `_classify_worker_failure`、`_worker_failure_message`、`_worker_failure_evidence`；与 `_fail_stage_attempt` 中最终错误覆盖规则一起核对。
- 设计取舍：只在形成完整纯决策职责时移入邻近内部模块；若提取只剩转发包装则不做。暂不新增通用 StageContext、StageResult、插件框架、Artifact Registry 或全局事务。
- 验收：E1，同一异常类型/阶段/代次得到原有错误码、中文消息与脱敏 evidence；E2，不把异常正文/凭据泄漏至事件；E3，旧代/旧 attempt 仍无法覆盖新结果，超时与原有错误优先级不变；E4，事件时序与数量、direct 零翻译、receipt 主件身份保持；E5，职责 owner 唯一，没有新旧逻辑并存。行数减少不是单独验收目标。
- 最小验证：异常分类对照、定向执行阶段测试；仅触及状态路径才加入相应 generation/lease/receipt 用例。不顺带修历史超时/夹具问题。
- 回退：局部回退提取，不改 schema/记录格式。后续翻译/渲染阶段是否再拆，依据试点复杂度和真实修改压力另定。

### B05 legacy 剩余消费者收敛（P2，A03/A14）

- 范围：按 main 装配、独立 StageWorker、脚本/CLI、历史 spool、共享 docx_rules/parser 分组列调用表；逐个选定仍需保留的业务入口迁到正式 IR/Renderer，或在证明无人使用后删除独立实现。
- 非目标：重新移除已下线 /jobs、删除整个 app/conversion、删除 DocumentIR v1 支持、重写历史结果、凭源码无调用推断生产队列为空。
- 验收：G1，每个 legacy 入口有保留/迁移/删除决定与依据；G2，迁移入口的输入、输出、错误、资源/翻译语义与已确认合同匹配；G3，正式流程共享规则仍可用；G4，未确认的部署消费者/spool 标为保留，不伪装清零；G5，迁移部分仅一个正式 writer，路由不重新暴露 /jobs。
- 最小验证：静态 import/call map，选定入口的定向 adapter/characterization 用例和 OpenAPI 指定断言；真正涉及队列排空需另行授权环境核查。
- 回退：以消费者为单位回退；回退时不得让两种写者混写同代结果。

### B06 表格翻译上下文（P2，A06/A07）

- 归属：继续已有 TR-404 待办，依赖 TAB-301 的当前实际表格合同；不创建同目的新实现。
- 范围：先从已知技术表格选短文本、合并表头、多级表头、正文+公式混合格样本；为请求附只读行/列/表头上下文。优先保留现有 item ID 与 DOM 回填定位，不直接改成 r/c ID；如确需改 ID，必须单独设计在途批次/证据兼容。
- 验收：T1，模型只能返回既有 id/text，context 不进入输出；T2，技术信息在上下文中也不能形成泄露未保护值或绕过 Token 规则的旁路；T3，合并单元格、eq 子树、正文索引、完整性计数和批次来源保持；T4，新增上下文计入明确的请求预算，超限行为确定；T5，同一预先选定样本集的人工语义评审给出具体改善/不变/退化项，未证明质量改善不全量启用。
- 最小验证：请求形状/预算与原回填合同测试；fake 只能证明结构/拒绝行为。真实译文对照涉及 Provider 调用和费用，需另行授权；未授权时仅完成准备，语义效果保留未验证。
- 回退：关闭新增请求上下文或回退该任务；不覆盖历史成功译文，兼容变更须排空/隔离在途任务。

### B07 路由加载与单页职责拆分（P2，A15/A27）

- 范围：路由按现有入口做动态导入候选；优先一个 JobDetail 页面内稳定职责，不同时拆五个巨页。沿现有 API client/store/composable 模式，不改后端合同。
- 验收：F1，登录后跳转、深链接刷新、角色路由与异常加载反馈保持；F2，选定页面轮询/刷新/取消请求与换代行为不重复、不丢失；F3，动作资格使用后端返回，权限过滤保持；F4，如报告首包改善，记录同一依赖/构建条件下的入口 chunk 和加载数据；F5，涉及布局/弹层时才验证 375/768/1024/1440px、深色及焦点行为。
- 最小验证：现有 auth/appShell/选定页面相关 Vitest 子集；必要的 vue-tsc/Vite 构建用于实际导入与 chunk 检查；只做所改流程的浏览器验收，不运行完整 Playwright smoke。
- 回退：路由或单页分别回退，不与认证存储迁移混做。

### B08 schema 版本治理（P2 条件，A12）

- 触发：下一次已授权的持久化合同变化、明确 bootstrap 部署事故或跨版本升级需求；单凭 LONGTEXT 不触发全库改造。
- 范围：设计现有 schema 的初始版本归属、单一迁移执行者、API/Worker 兼容窗口和停止条件；比较现有 SQL 方式与候选工具。工具选型须先查官方版本/问题记录，不预设 ORM/Alembic。
- 验收：M1，支持范围内的旧 schema→目标 schema 可重复推进，重跑不重复 DDL/回填；M2，部署过程不由多个 API/Worker 竞争迁移；M3，中断可识别并恢复/前滚，状态和数据完整；M4，逐项标注可逆/不可逆操作，恢复方案有备份与兼容证据；M5，不把 fake SQL 检查当成真实 MySQL DDL 验收。
- 最小验证：定向 schema/历史记录 fixture；真实 MySQL 仅在授权隔离环境验证目标升级路径。没有环境时保持未验，不触碰生产。
- 回退：按迁移逐项定义，不能统一承诺 down migration 或事务回滚；无关表/JSON 不整体重写。

### B09 认证、密钥与 Provider 出站专项（P2 条件，A18/A19/A20/A27）

- 触发：对公网暴露方式变化、凭据泄漏/权限事故、明确会话或密钥轮换要求。现有内部部署也保留风险，不因“内部”自动豁免。
- 范围：先核实代理/TLS/跨域、客户端、管理员边界、受支持 Provider、存储权限与备份策略。分别决定 Cookie/CSRF、密钥存储或出站策略，不捆绑全面迁移。
- 验收：S1，所选认证方式保留合法客户端和登出/过期行为，未授权请求拒绝；S2，若用 Cookie，则 CSRF/跨域/属性策略有定向证据；S3，密钥不进入普通响应/日志/不受控备份，轮换与 Worker 生效路径可验证；S4，出站策略拒绝不允许目标且不破坏已确认兼容端点；S5，复用已有 admin 与配置审计。
- 最小验证：所改认证/权限/配置的定向正反例及独立安全复核；运行环境事实需授权读取，禁止读取/打印真实秘密。本轮不判断必须购置 Secret Manager。
- 回退：保留安全拒绝与审计，不为兼容恢复泄漏或放开权限。

### B10 保护查询、容量与质量指标（P2 条件，A24/A25）

- 触发：明确数据量增长计划、实际慢查询/清理时延或运营指标需要。
- 范围：先记录 publication/file 数量、查询次数/扫描行数、定向延迟；复用现有 metrics/质量字段。需要时再设计 file→publication 索引，避免先增表；定义降级率等指标分母、缺失历史值与多代去重。
- 验收：Q1，相同固定数据集下保护集合完全一致；Q2，并发发布/清理不会删除被保护文件，锁序/快照合同保持；Q3，若宣称优化须有前后查询或延迟证据；Q4，历史未知值不当作 0 或 passed，指标可由 Artifact/质量事实对账；Q5，不缓存出过期保护结果。
- 最小验证：定向基准、保护集合对照及受影响事务案例；不进行全站压测或全量回归。真实并发证据另列环境条件。
- 回退：保留旧查询到新索引完整性确认，避免双写长期并存；具体回填/回退在专项设计中给出。

### B11 分发与许可证决定（P3，A23）

- 触发：用户明确开源或对外分发目标。
- 范围：确认代码/样本/字体/模板权利范围与拟采用许可；不自动添加许可证或删除私有工具配置。
- 验收：C1，所有者明确许可决定；C2，适用范围与第三方归属可核对；C3，分发包不包含未经授权的样本/秘密/本机产物。
- 最小验证：文件、来源和分发清单核查；如需法律判断单独取得相应意见。本轮不作法律结论。

## 5. 继续实施前的共同条件

只选择一个独立批次或已有任务，重新核对当前代码与本基线差异；准备该批次可审阅的 PRD/design/implement。验收和最小检查精确映射所改合同，已有成功输入未变即复用。遇到无关旧测试失败，单列为历史维护，禁止扩成全仓修复。

涉及安全、并发、持久化或发布的候选，针对具体未解决风险安排独立只读复核；规划中的风险清单不是提前启动实施代理的依据。外部文档/依赖工具选择在相关专项中按受支持版本研究，本轮未进行工具选型或引入依赖。
