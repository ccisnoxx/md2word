# P0 仓库本地环境信息清理与提交卫生检查

## 目标与用户价值

清除正式仓库中的个人网络脚本和开发机路径，建立可本地运行、能在提交前阻止再次混入的仓库卫生检查，并依据脱敏扫描证据判断是否需要另行清理历史。

## 当前授权

用户于 2026-11-10 审阅最终规划摘要后明确批准实施。授权覆盖本方案的当前树清理、开发工具依赖与本仓库 Git 钩子激活；历史改写、凭证轮换、提交、推送及生产操作仍未授权。

## 实施前的核查基线

- 基线为 `main@d45e46e1`，工作区初始干净，Git 跟踪 1,668 个文件。
- `.auto-wifi-dns.zsh.tmp` 仍被跟踪，共 74 行，包含网络和 DNS 修改命令；本地历史中存在两个新增记录。
- 用户目录模式筛查命中 150 个文件，涉及任务材料、文档和两个开发脚本；精确位置清单保存在本地。
- 内网地址模式命中 4 个文件，部分为既有部署配置，不能直接批量删除或替换。
- 跟踪的 IDE、共享运行配置和 AI 工具目录需要按用途核查，目录名本身不是删除依据。
- 核查基线时未配置 `core.hooksPath`，实际 Git hooks 目录没有非示例钩子。Gitleaks 8.30.1 已通过官方制品校验后临时运行，没有持久安装。
- 当前 1,668 文件快照的 25 条 secrets 命中已核对为文件校验和；历史发现同一段硬编码 Bearer token 的两条记录，其中一条在 HEAD 祖先中。有效性和吊销状态未验证，历史其余命中未全部人工排除。扫描边界见[验收记录](verification.md)，详细报告保存在本地。
- 既有整改总计划的 A22/B01 覆盖同类卫生问题，本任务只承接本次明确范围，不自动启动其余整改。

## 需求

| ID | 可观察需求 |
|---|---|
| R1 | 删除已跟踪的个人网络脚本，并防止临时文件再次进入提交。 |
| R2 | 将任务和可共享文档中的个人项目路径替换为 `${PROJECT_ROOT}` 或清晰的语义占位符，保留证据和机器可读字段的含义。 |
| R3 | 清除维护中开发脚本对个人目录的默认依赖，显式配置缺失时给出中文错误，不把文档占位符当作可执行路径。 |
| R4 | 提供仓库卫生检查和 Git `pre-commit` 入口，拒绝 `.tmp` 文件、个人用户目录路径、未经声明的 RFC1918 IPv4 地址和新 secrets；检查真实暂存内容，输出只包含定位和规则，不回显敏感值。 |
| R5 | 对 IDE、AI 和过程性材料形成逐类处置清单，保留团队协作、工作流和可追溯证据。 |
| R6 | 对当前跟踪快照和本地可达历史执行 secrets 与内部信息筛查，记录版本、范围、命中处置及历史清理建议；无法执行的范围明确报告。 |

## 授权边界与非目标

- 本轮只修改 `design.md` / `implement.md` 约定的卫生治理路径；不改其他任务状态和无关业务行为。
- 不改写 Git 历史，不强推、提交、推送、部署、访问生产、轮换凭证或修改全局配置。
- 不一概删除 `.idea`、`.agents`、`.codex`、`.trellis`、`.run` 或历史验收材料。
- 不新增 GitHub Actions/CI，不运行应用全仓测试、服务或发布聚合检查。
- 扫描不上传仓库内容，不验证真实凭证有效性，不扫描工作区中未跟踪/被忽略的私有运行配置。
