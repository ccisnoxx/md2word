## 规划时确认的背景（实施更新见文末）

- 当前基线 main 为 25860865，工作开始时干净。74cea825 的列表发布证据轻量化已包含于线上公开版本 28cacd8a；git 祖先检查成立，28cacd8a 与当前 HEAD 的 app/frontend 没有差异。当前 HTTP 健康版本声明不等于逐文件镜像核验。
- 本轮公开 ready GET 返回 200、version=28cacd8a、MySQL 后端，单次耗时 0.905806 秒。没有认证列表接口或页面加载计时，不能用该值代替列表耗时。
- 任务列表每次先执行两次全表 shape 校验，再查询统计/分页：app/infrastructure/persistence/document_job_list_query.py:118。
- 异常列表经 service.list_visible_jobs 读取全部任务并过滤权限，再逐条有效复核和异常分类，最后分页：app/domains/document_jobs/service.py:1438、app/domains/document_jobs/incidents.py:86。已验证绑定的任务可能在两个阶段分别读取主件，实际耗时贡献未测。
- 两页均 finally 清理 loading；请求超时为 50 秒：frontend/src/pages/JobsPage.vue:571、frontend/src/pages/IncidentTriagePage.vue:728、frontend/src/api/client.ts:15。未发现已证实的加载状态泄漏。
- 独立 worktree list-ready-once 和 list-key-columns 已有候选实现及验证记录，尚未接入本 main。前者合并请求内校验，后者需要五个文本列和数据回填；两者都缺真实 MySQL 引擎验收。本任务不重做其功能，也不改动其工作区。

## 范围和需求

- R1：分别定位两个列表从请求到显示的主要耗时，区分 SQL、解码、元数据读取、动作构建、网络和渲染；保留可复核、脱敏证据。
- R2：优先评估现有无迁移候选 list-ready-once 的收益与兼容性；仅在证据说明其不足时评估已有大 key 拆列候选。新方案不扩大为索引、缓存、连接池、重写前端或完整异常 SQL 下推。
- R3：异常列表只针对测量证实的瓶颈规划局部优化；保留租户/公司/owner 可见性、有效复核、分类、搜索、排序、分页、total、summary、动作与错误合同。不能因两次读取看似重复而直接删除观察。
- R4：复用已通过且输入不变的结果；接入多个候选导致输入变化时，只补交叉影响验证。保留全部并发工作。

## 验收标准

- AC-1 / R1：记录真实运行版本、角色、筛选、页大小、可见数据量及请求次数；默认首页、无匹配搜索和翻页各按受控串行样本记录。分开标记首次和预热耗时；不得把三次采样称为 p95。
- AC-2 / R2、R3：建议性能目标为当前数据规模下两个默认首页接口连续三次成功、耗时中位数不超过 2 秒，浏览器从进入列表到出现数据或明确空状态不超过 3 秒。该目标已随方案获批，不是已达成事实；不达标保留任务未完成，报告主要剩余耗时。
- AC-3 / R3：改前冻结实现与候选在相同输入/时钟下的条目、顺序、total、summary 和动作一致；覆盖 admin/operator、空结果、分页、有效复核失效和主件到期。新增成本计数直接对应已证实瓶颈。
- AC-4 / R2、R4：清楚记录复用版本、重叠文件、整合结果与真实 MySQL 验证状态；缺失引擎/认证证据不得记录为通过。大 key 拆列未获部署迁移授权时仅交付本地评估与执行准备。
- AC-5 / R1、R3：正常请求结束和错误返回后页面结束 loading；保留原错误提示，不能用缩短超时或提前隐藏 spinner 代替接口提速。
