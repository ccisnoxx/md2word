## Findings (fixed)

- **P1：恢复全列验收缺口。** 文件：`release_ops/snapshot.py:63`、`release_ops/test_release_ops.py`。原实现无论用途都忽略两列查询 JSON 和五个 key 值；若备份恢复损坏这些派生值，默认比较仍可能通过，无法满足恢复前后“全部列一致”。复核指出后，由仍持有代码所有权的实施 agent 新增显式 `snapshot --include-derived`：全列值/结构纳入摘要，报告标记 `all_columns`，拒绝与默认 `original_columns` 混比。新增回归确认派生 JSON 变化失败及 scope 混用失败。默认迁移模式继续允许获准的派生值变化，避免将恢复与迁移比较混为一项。
- **P2：运维文档状态和实际输出不一致。** 文件：`production-execution-plan.md`。原文仍称载体不存在、未实现；完整差分描述还包含当前脚本不提供的字段级差异定位。复核直接同步为已实现本地候选，链接真实 CLI，区分数据库摘要与尚待执行的对象/Redis恢复，注明全列模式、受支持 schema 边界、摘要比较的实际输出和真实演练前置。保留研究 agent 新增的分阶段排空顺序，不覆盖其工作。
