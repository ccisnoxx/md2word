# 生产动态模板目录设计

## 数据归属与接线

| 内容 | MySQL 模式权威 |
| --- | --- |
| 模板存在性、名称、描述、启用/删除状态、后续上传的默认版式和 render policy | 每模板一条目录记录。逻辑删除保留 ID 和历史，启动不得复活。 |
| 版本生命周期、路径、文件 SHA-256、版式和 render policy | 既有 `resource_versions`。新版本复用 `resource_version_sequences`。目录元数据不改已绑定版本的 payload。 |
| 全局默认模板 ID、模板各自的默认版本 | MySQL 的全局指针与现有 `resource_default_versions`。全局默认必须是启用模板，且其默认版本已发布。 |
| 内置资源与动态实物 | 镜像内只读 seed。上传留在 API/Worker 共用的受管目录，由版本路径和哈希定位。 |

使用窄的模板目录持久化端口，沿用现有 MySQL adapter/composition。关联目录、版本和指针的写入在同一 MySQL 连接事务完成，维持其他资源类型的行为。MySQL 公开列表、详情和任务选择读取目录。只有草稿时可显示已登记资产，普通任务仍需 published。管理操作的成功响应可读取刚停用的记录，公开详情继续隐藏该记录。版本列表以持久化记录为准，保留整数别名去重及文件缺失诊断。file/SQLite 保留原本地路径。

## 写入与渲染

- 复用模板包联合预检。预检后把候选文件放进本次上传独占的受管位置，完整文件就绪后提交数据库。目录和首版 draft 同一事务插入，后续版本用既有序列和只插入规则。已确定回滚时只清理本次请求的文件。提交结果未知时，从独立连接核对登记路径和哈希，无法确认时保留文件供对账。未提交残留不能阻止合法重试。
- 发布继续使用同一草稿快照的成功验证任务和原 CAS。发布并设默认、默认切换、禁用版本、停用及删除通过一致的锁顺序检查及写入。元数据补丁只更新提供的字段。实施时核对目录和已有资源键的排序规则、模板 ID 大小写语义以及并发连接行为。
- 模板级停用或删除只修改目录，版本记录及实物继续保留。提交后，新建与克隆（包括 `keep_source_snapshot`，它会创建新任务 ID）在 API 准入时检查目录及版本授权。继承来源快照的克隆校验通过后继续沿用原版本及哈希，不重新选择默认或为草稿扩大权限。同一任务重试保留模板绑定，包括只重绑术语的重试。
- 快照 Worker 去掉 `resolve_template_render_state()` 前置调用，复用 `materialize_render_resources()` 校验数据库版本、快照、DOCX、版式和格式规则。模板级停用或删除后，已经绑定的任务可继续。显式版本禁用由渲染使用的同一数据库记录判定，应先于快照哈希判断，覆盖草稿验证后发布导致哈希变化、随后版本被禁用的情况。保持现有默认版本保护、任务格式、已授权 draft 和发布后可重验行为。无快照任务沿用模板版本解析入口及已知兼容规则。更新 `tests/test_job_render_resources.py:273` 的旧清单停用断言。

## 初始化、迁移与回退

1. 在既有 schema 入口增量建立目录与全局默认结构。实施前核对选定基线的 B08 状态，若 schema 所有权已迁移则沿用新入口。以真实 MySQL 覆盖空库和旧结构升级。
2. 使用 bundled manifest 幂等登记 seed，遵守既有版本身份和文件哈希约束。并发插入冲突后读回核对等价性，已有目录元数据、已关闭状态和合法默认指针保留。先登记 seed，再解析默认模板。
3. 参照 `scripts/ops/migrate_document_job_state.py` 提供只读预检、显式应用、复核。旧 manifest、默认状态、现有 MySQL 版本与共享卷一起对账。重建旧容器前保全其私有层可能存在的自定义清单。MySQL 配置指向旧自定义 `TEMPLATES_MANIFEST_PATH` 时明确提示迁移，运行时使用 bundled seed。
4. 用旧清单证明模板可见性、名称、启用等目录状态，用数据库证明已登记版本身份并校验文件哈希。旧清单明确标注的禁用状态只可应用于相容版本，不能自动移动有效默认或复活关闭版本。无版本登记的旧项、孤立草稿和文件、异常默认、冲突及缺失资产显式列出，未经确认不自动发布或恢复。
5. 应用前确认预检基线，在单写入口下迁移，重复运行保持一致。保留旧输入、数据库和卷的恢复材料，新旧应用避免混合写入。新目录开始接收变更后，回退旧应用前需对账这段变更，核对历史任务可用性。生产数据可迁移程度待获授权的预检确认。
