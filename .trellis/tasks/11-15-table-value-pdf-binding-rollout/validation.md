# 第五阶段隔离验收

实施基线为现有分支的 `e31f87de`。验收环境使用独立 Colima 实例 `md2word-rollout5`、独立网络、测试数据库和队列，按生产 Dockerfile、固定基础镜像和 57 个带摘要的 wheel 构建候选。宿主使用 Apple Silicon，候选容器运行 `linux/amd64` 并通过 QEMU 执行。正式目标机器和目标对象存储策略待另行核对。

## 审批及名单

- 对文件和 SQLite 两种仓储，旧逻辑在最后重核后成功声明删除报告或 IR 时仍能写入批准并返回 200。同样交错在新逻辑返回 `409 review_result_integrity_conflict`，复核记录和序号均不写入。SQLite 在锁后观察时恰好到期的 IR 也被拒绝。
- 定向聚合 41 项通过，覆盖名单内外、配置校验、同一个 UUID 在停用后重放、同包在途继续、审批事务冲突、旧入口和 OpenAPI。另两项旧交付状态用例在阶段四干净基线同样失败，涉及早期 `quality_summary` 及 SQLite 列假设。
- 实物重建、字节校验和对象读取仍在仓储锁外。锁内使用同一次认证的文件登记和任务快照。对生成件的物理不可变保证依赖正式存储的覆盖权限和生命周期合同。

## 运行环境

- 固定 MySQL 镜像版本为 `8.4.9`，隔离服务实例为 Linux/arm64。隔离写连接实读 `REPEATABLE-READ`、`autocommit=0`、`innodb_lock_wait_timeout=50`，服务端 `utf8mb4/utf8mb4_unicode_ci`。使用随机测试 schema 对账。
- 候选镜像 ID 为 `sha256:6127850d19531ef99844ffb99090dfbb09dab1f0e997d1673de1381987618f1f`，Python 为 `3.11.18`。实际消费容器以 `md2word`（UID 1000）运行，四项工具均位于 `/usr/bin`，报告 `25.03.0`，Debian 包为 `25.03.0-5+deb13u4`。

## 划线 LOW/HIGH 的真实回包

同一候选入口从上传到实际回包处理合成公开样本。上传 PDF 为 1503 字节，SHA-256 为 `bf90bdcb7a4a23beaa5496f371190a85461966d1c35b4b452ec983b62c974b6d`。真实归档 ZIP 为 21630 字节，SHA-256 为 `a61757b0fb85ba190f5e706f3c5289fc25ae734f5e1328b1a39698dcc07dacb8`。其对应 `_origin.pdf` 为 `c5ee429ffb598c06136bd481f4e916fa75a0434cadf93e05457299f260ca07a3`，与实际上传不同。回包已将三个值分别放在独立列，Word 实物的 `7.2e-4 s`、`43 ms`、`48 ms` 归 HIGH、LOW、HIGH，表格没有跨列候选，自动认证为零。该用例未提供同源正例。[实测回包与 Worker 指纹](research/worker-acceptance.md)

## MySQL 写事务和审批发布

最终候选容器使用 PyMySQL 1.2.3 对隔离 MySQL 8.4.9 的 8 项定向用例全部取得通过记录。从独立连接的 `performance_schema` 实际观察到 2 次 job 主键与 6 次文件主键的行锁等待。覆盖同 UUID 一次接纳、不同 UUID 争用、锁后读取删除预留和有效期、回滚释放锁、超时和已提交回执丢失后对账、旧代防护。

正式审批遇报告或 IR 删除声明先提交时返回 `409 review_result_integrity_conflict`，批准记录、序号和指针均不写入。反向交错证明文件声明等批准提交释放行锁。报告在发布实物认证前已失效时保留现有安全 500，认证后到提交前失效为 409，均未写入发布。来源完整的受控实物正例为审批 200、发布 201，跨列未决负例为双 409。MySQL 用例使用实际 Word、IR 和报告，预览和上游传输使用测试夹具。[并发矩阵及证据](validation-mysql.md)

## 单公司灰度与回滚

在同一隔离 MySQL schema、对象目录和 Redis 队列中，以候选 Uvicorn API 与正式 Celery Worker 依次运行关闭、限定公司开启、关闭和清空名单三档配置。用嵌入字体且已登记资源版本的同源划线 LOW/HIGH 夹具，保留实际 Word 和报告的核对摘要。

| 阶段 | 实际结果 |
| --- | --- |
| 关闭 | 三处原跨列均保持阻断，自动认证 0 项。 |
| 单公司开启 | 名单内认证 2 项，Word 的 `7.2e-4 s` 只在 HIGH、`43 ms` 只在 LOW，`48 ms` 的独立行证据不足，继续阻断审批和发布。管理员对最后一格核定返回 202，冻结第 1 代。名单外仍 0 项，新人工请求返回 409。 |
| 关闭并清空名单 | 新同包请求返回 409，原 UUID 重放返回 200，回执保持第 1 代。尚未执行的第 1 代继续使用同一 raw ZIP，实际 Word 三格均单列且 `48 ms` 只在 HIGH，3 项认证、0 未决，批准返回 200。上一代 Word SHA-256 保持，新普通转换 0 项认证。 |

最初未嵌字体的 Helvetica 划线夹具在该 Linux 候选的字体环境中留下 3 个 `header_ambiguous`，保守阻断。改用嵌字体对照后跑通上述流程。灰度演练未配置真实预览，发布正反对照归入前述 MySQL 专项。[候选实测](research/worker-acceptance.md)
