# 前端页面细节优化技术设计

## 最小可行设计

本任务不创建新设计系统，也不引入新的组件库。实现只扩展现有三个权威边界：

1. `frontend/src/styles/main.scss` 继续拥有全局视觉令牌和共享滚动条工具类；
2. `frontend/src/layouts/AppLayout.vue` 继续拥有顶栏响应式信息层级、用户菜单和焦点返回；
3. `frontend/src/components/TranslationQaReviewPanel.vue` 继续拥有 QA 复核内容、表单和移动端操作布局。

页面级文件只负责为真实滚动根节点选择已定义的滚动条类型，以及修复全站审计确认的局部 P2 问题。不得建立第二套 token 文件、通用配置驱动 UI 框架或仅转发样式的包装组件。

## 任务边界与阶段

该任务保留为一个实现任务，不拆成多个子任务，原因是两个阶段都会修改 `main.scss`、壳层、共享组件和同一组视觉回归用例；拆分会形成重复文件所有权和第二份验收清单。

实现仍设置两个硬门禁：

```text
全站审计完成
  -> P0/P1 可用性与共享规则修复
  -> P0/P1 自动化与截图门禁通过
  -> P2 状态、阴影、间距与反馈收敛
  -> 全范围回归
```

P2 不得在 P0/P1 门禁通过前提前扩张。

## 全站审计模型

审计记录继续写入 `research/ui-detail-audit.md`，每项问题至少包含：

- 页面族与复现路由；
- 视口和主题；
- 截图、运行时断言或源码锚点；
- 严重度与用户影响；
- 共享所有者或局部所有者；
- 计划验证方式。

路由按登录/访问控制、处理队列/任务详情、质量治理、配置发布、系统运维五类覆盖。已有 smoke 能回答的行为不重复手工猜测；现有 `fullPage` 截图对固定遮罩产生的视觉失真不能直接定性为缺陷。

## 滚动条合同

### 令牌与工具类

在 `main.scss` 的现有 `--app-*` 命名空间新增滚动条尺寸、轨道、滑块、hover 和 active 颜色令牌，并为深色主题提供对应值。

提供两种显式工具类：

- `app-scrollbar-transient`：侧栏、保存视图条、短横向筛选/操作条；轨道默认透明，滑块在 `hover/focus-within` 时出现。
- `app-scrollbar-persistent`：抽屉正文、长表格、配置列表、命令面板；始终保留低对比度细滑块，hover 时增强。

工具类同时实现 Firefox 的 `scrollbar-width/scrollbar-color` 和 Chromium/Safari 的 `::-webkit-scrollbar*`。不使用全局 `*::-webkit-scrollbar`，避免改变第三方弹层、浏览器原生控件和未审计容器。

### 分类规则

- 容器主要用于发现“还有更多内容”时使用 persistent。
- 容器内容短、滚动方向显而易见或属于常驻导航时使用 transient。
- Element Plus 内部表格滚动根必须标记实际承载滚动的元素，不能只给外层卡片加样式。
- 所有分类只改变视觉，不改变 `overflow`、滚动方向、滚动位置和键盘行为。

## 移动端顶栏合同

### 桌面

`>640px` 继续显示搜索、主题、用户身份、修改密码和退出入口，保持现有行为和 smoke 定位方式。

### 移动端

`<=640px` 顶栏只平铺：

- 导航按钮；
- 当前页面标题；
- 搜索按钮；
- 主题按钮；
- 用户菜单触发器。

用户菜单使用现有 Element Plus dropdown，不新增状态管理。菜单内提供“修改密码”和“退出”；触发器显示可辨识的用户身份，但宽度必须受限，页面标题获得剩余弹性空间。更窄断点隐藏模块名和面包屑，不隐藏页面标题。

### 行为与焦点

- 修改密码仍调用现有密码 dialog 和提交逻辑。
- 从用户菜单打开 dialog 时，关闭后焦点返回用户菜单触发器；桌面仍返回原修改密码按钮。
- 退出仍调用唯一的 `handleLogout`，不得复制认证清理逻辑。
- dropdown 触发器、菜单项和 dialog 必须具备明确的 accessible name。

## QA 复核抽屉合同

### 桌面

保留 `header / 可滚动正文 / 固定 footer` 三段布局。表单、快捷键提示和操作按钮维持现有密度，避免改变高频桌面复核路径。

### 移动端

抽屉根节点成为唯一纵向滚动根，header、证据正文、复核表单和元信息按文档流排列：

```text
标题与状态
  -> 证据与建议
  -> 片段与关键证据
  -> 复核表单
  -> 紧凑吸底操作栏
```

移动端正文不再拥有第二个纵向滚动区。快捷键提示隐藏；操作栏只显示“关闭、仅保存、保存并下一条”，使用不透明背景、上边框和安全区 padding，不能遮挡表单最后一项。操作栏的 sticky 行为限制在 QA 抽屉内部。

实现优先通过现有 DOM 和断点样式重排，不提取仅为移动/桌面各渲染一次的重复表单组件，也不复制表单状态。

## P2 视觉规则

### 状态反馈

- 运行中：允许克制的脉冲或进度动画，并遵守 `prefers-reduced-motion`。
- 成功/警告/阻断：文字语义为主，搭配图标/形状和色彩；颜色不是唯一信息源。
- 禁用：保留内容对比度，通过控件状态、边框和原因文案表达，不对整卡统一降低透明度。
- 静态指标卡：不使用 hover 位移、放大或强化阴影；只有真实可点击卡片才有 hover/focus。

### 阴影与间距

- 基础内容面板以边框和背景分层；`--app-shadow-subtle` 只用于需要轻微抬升的交互或常驻浮层。
- `--app-shadow-panel` 及更强阴影保留给 dialog、drawer、command palette 等真实覆盖层。
- 复用现有空间令牌；固定像素只保留在图标尺寸、1px 边界、视口合同等有明确约束的位置。
- 移动端收紧装饰性间距但不压缩点击目标；桌面不通过普遍增大留白降低数据密度。

## 兼容性与数据流

- 不改变 API、Pinia、路由查询或权限数据流。
- 主题仍由 `AppThemeToggle.vue` 和 `data-theme` 管理；新增滚动条令牌随现有主题切换。
- 用户菜单只改变操作入口位置，不增加新的用户状态来源。
- QA 表单继续由现有 props/computed/emit 单向合同管理，不新增草稿副本或兼容分支。

## 测试设计

新增或收紧以下目标断言：

- `375px` 下顶栏当前标题具有可辨识宽度，修改密码和退出可通过用户菜单访问。
- 用户菜单打开密码 dialog 后，关闭时焦点正确返回。
- `375x812px` 下 QA 抽屉只有一个纵向滚动根，表单与三个操作可滚动到达，吸底栏不遮挡最后一个表单项。
- transient/persistent 滚动容器使用明确工具类，关键容器的 computed style 与主题令牌匹配。
- `375/768/1024/1440px` 保持无页面级横向溢出；浅色和深色至少各覆盖一个壳层、一个表格和一个抽屉样本。

## 风险与回滚

- 风险：移动端 dropdown 改变已有 smoke 的按钮定位。应按语义更新移动端断言，桌面断言保持不变。
- 风险：sticky 操作栏可能与软键盘、安全区或 Element Plus drawer 高度计算冲突。使用 `100dvh`、安全区 padding 和短视口断言验证。
- 风险：滚动条 CSS 在 macOS overlay scrollbar 下不明显。以 Windows/Firefox 语义属性和 Chromium computed style 双重约束，不以单一截图判定。
- 风险：P2 全局选择器可能误伤复杂业务页面。优先调整令牌和明确共享类，局部规则必须有审计证据。

回滚按阶段进行：P2 可独立回滚到已通过门禁的 P0/P1 状态；滚动条、顶栏和 QA 抽屉分别保持独立 diff 边界，不通过兼容开关保留旧行为。
