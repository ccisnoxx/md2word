# 前端页面细节优化

## Goal

在不改变现有业务能力、信息架构和设计方向的前提下，系统审查并优化前端页面的视觉与交互细节，使界面更精致、一致、易用，并消除影响移动端可用性和跨浏览器观感的成品缺陷。

## Background

- 2026-06 已完成壳层、设计令牌、核心工作台、诊断详情、治理配置、长尾管理页和响应式门禁的一轮系统化改造；本任务是成品细节审计与收敛，不重做设计系统。
- 用户指出左侧导航内容溢出时会显示较粗的浏览器原生滚动条；滚动能力需要保留，但视觉表现应与工作台一致。
- 本任务采用“先完成全站细节审计，再修复 P0/P1，最后收敛 P2 视觉细节”的交付方式。

## Confirmed Facts

- 前端为 Vue 3 + Element Plus；基础视觉令牌集中在 `frontend/src/styles/main.scss`，壳层由 `AppLayout.vue` 和 `AppSidebar.vue` 管理，复杂页面和组件仍包含较多局部样式。
- `AppSidebar.vue:253` 的导航区域只有 `overflow-y: auto`；`frontend/src/` 至少 21 个文件包含滚动容器，但没有共享的 `scrollbar-width`、`scrollbar-color` 或 `::-webkit-scrollbar` 规则。
- 现有关键页面截图用例在 `375/768/1280/1440px` 下通过，证明基础路由、横向溢出和部分焦点行为仍有效；这些用例不验证纵向可达性、视觉遮挡、滚动条观感和状态对比度。
- `375px` 截图已确认移动端顶栏操作区会把页面上下文挤压到只剩一两个汉字。
- `375x812px` 截图已确认翻译 QA 复核抽屉的高 footer 占据大部分视口，正文、表单和操作缺少可靠的纵向可达路径。
- `AcceptanceCenterPage.vue:1042` 等局部样式会对整个禁用卡片降低透明度；项目内同时存在较多直接阴影、渐变和固定像素间距，适合在 P0/P1 稳定后做统一收敛。
- 详细证据与测试缺口记录在 `research/ui-detail-audit.md`。

## Requirements

### 审计与交付

- R1. 全站审计必须覆盖登录/访问控制、处理队列/任务详情、质量治理、配置发布和系统运维页面族，并以源码、真实截图或运行时断言为证据。
- R2. 问题清单必须区分功能可用性、响应式/可访问性、共享组件一致性和纯视觉润色，并按 P0/P1/P2 排序。
- R3. 第一阶段修复审计确认的 P0/P1 问题；第二阶段只在第一阶段验证通过后处理阴影、间距、状态反馈等 P2 项。

### P0/P1 可用性与共享规则

- R4. 滚动条采用分级策略：侧栏和短横向操作条默认隐藏轨道，仅在 `hover/focus-within` 时显示细窄滑块；抽屉正文、长表格和配置列表始终保留低对比度细滚动条。
- R5. 滚动条视觉弱化不得禁用滚轮、触控板、触摸或键盘滚动，也不得用裁切掩盖真实的溢出问题。
- R6. 移动端顶栏保留导航、当前页面标题、搜索、主题和用户菜单；“修改密码、退出”收拢到用户菜单，桌面端继续平铺显示。
- R7. 移动端顶栏优先保证当前页面标题可辨识；模块名和面包屑可以按断点降级隐藏。
- R8. 移动端翻译 QA 复核抽屉采用单一纵向滚动内容，标题、证据和复核表单按顺序滚动，底部保留紧凑吸底操作栏。
- R9. 移动端吸底操作栏保留“关闭、仅保存、保存并下一条”并隐藏键盘快捷键提示；桌面端继续使用独立正文滚动和固定表单 footer。

### P2 视觉收敛

- R10. 继续使用现有蓝/青/翠色和“克制、专业、数据密集”的企业工作台方向，不引入第二套主题或营销式视觉语言。
- R11. 只有运行中状态允许轻量动态提示；成功、警告和阻断必须同时使用文字、图标或形状与颜色表达，不得只依赖颜色。
- R12. 禁用状态保持标题、说明和原因可读，不再通过整卡低透明度表达不可用；只有真实可交互卡片提供 hover/focus 反馈。
- R13. 阴影、圆角、间距和动效优先复用现有 `--app-*` 令牌；移除无业务含义的局部强化效果，不通过扩大留白牺牲数据密度。

### 兼容与质量

- R14. 优化必须保持浅色、深色和跟随系统主题能力，并覆盖 `375/768/1024/1440px` 关键视口。
- R15. 现有导航、权限、路由查询、焦点可见性、弹层关闭/焦点返回和业务操作行为不得回归。
- R16. 共享问题应落在全局令牌、共享样式或公共组件中；不得在多个页面重复添加等价补丁，也不得新增前端依赖来解决纯样式问题。

## Acceptance Criteria

- [x] AC1. 审计清单覆盖全部页面族，每项 P0/P1 都有可复现证据、归属文件和验证方式。
- [x] AC2. 左侧导航及短横向操作条仍可通过滚轮、触控板、触摸和键盘滚动，常态不显示突兀轨道，交互时出现细窄滑块。
- [x] AC3. 抽屉正文、长表格和配置列表始终提供低对比度细滚动条，并在浅色/深色主题下可辨识。
- [x] AC4. `375px` 宽度下，顶栏显示可辨识的当前页面标题，移动端用户菜单可访问“修改密码、退出”，桌面端入口保持不变。
- [x] AC5. `375x812px` 等短视口下，翻译 QA 复核抽屉的正文、表单和三个主要操作均可到达、无互相遮挡；桌面布局保持原有密度与操作路径。
- [x] AC6. 状态反馈不依赖颜色单独表达，禁用卡片正文保持可读，静态卡片不出现误导性的 hover affordance。
- [x] AC7. 纳入范围的页面在 `375/768/1024/1440px`、浅色/深色主题下无新增页面级横向溢出，主要操作和焦点路径可达。
- [x] AC8. 相关单元测试、前端构建和目标 Playwright smoke 通过；新增断言覆盖顶栏标题、用户菜单、QA 抽屉纵向可达性和滚动容器合同。

## Out Of Scope

- 后端业务逻辑、API、权限模型和数据合同变更。
- 导航信息架构、路由结构或业务流程重做。
- 脱离现有设计方向的整站重做、第二套主题或新组件库。
- 与已验证问题无关的页面功能新增和大规模组件重构。
